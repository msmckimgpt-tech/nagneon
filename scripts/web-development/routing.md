## 웹 보조 개발 경로

- 설계 대안·어려운 원인 분석·독립 리뷰 또는 분리 가능한 구현에서 웹 보조 경로가 유용하면 `web-development` 스킬을 사용한다. 단순 수정과 빠른 수정/테스트 반복은 로컬에서 처리한다.
- 사용자가 전역 기본 보조 흐름으로 요청한 `Web 다방면 병렬 검토/작업 → Web 종합·Best way 검토 → 로컬 원본 대조·최종 검증`을 따른다. 웹쫀쿠는 선택적인 웹 모델 경로, Remote Desktop Commander는 웹에서 내 머신의 작업 파일·터미널을 연결하는 수단이다.
- 웹 작업별 기준 커밋·명시한 파일·수용 기준을 전달한다. 구현자는 별도 worktree/브랜치를 사용하고 공유 대상 병합은 로컬 최종 검증 뒤 기존 통합 규칙으로 수행한다. 원본 응답·종합 결과·실제 테스트 증거를 보존한다.
- 웹 위임은 독립 리뷰·구현·최종 웹 종합 모두 시간이 오래 걸려도 추론 수준 `xhigh`를 사용한다. 웹쫀쿠는 `chatgpt-web/extra-high`와 `model_reasoning_effort="xhigh"`, 브라우저는 실제 Extra High 선택을 확인한다. 미지원·한도·지연 때문에 high/medium/Instant로 자동 하향하지 않으며 불가한 단계는 알린다. 이후 사용자의 명시적 예외는 따른다. 로컬 모델·추론·기본 제공처는 유지한다.
- 로그인·연결·사용량 제한으로 웹 단계가 실행되지 않았으면 구체적으로 알리며 로컬 실행을 웹 실행으로 표시하지 않는다. 파일 설치, 실제 웹 병렬 완료, 웹 종합 완료, 로컬 검증 완료를 구분한다.
