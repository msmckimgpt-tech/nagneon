# 방송 흐름 진단

매니저 화면의 응답 진단에서 **방송 흐름 진단 다운로드**를 선택하면 현재 프로필의 로컬 진단을 JSON으로 저장한다. 최근 120회 응답의 메모리 내 집계와 별도로, 앱을 다시 실행해도 보존되는 단계별 기록이다. 다운로드는 기존 로컬 인증을 거치며 모델 호출, 입력 장치 연결, 파일 정리를 실행하지 않는다.

## 기록 범위

- 발언 수신: 전송 ID와 대화 ID의 연결, 입력 종류, 제공된 캡처·전사 시각. 구독 전사의 근사 구간과 직접 측정한 시각을 구분한다. 없는 시각을 0으로 채우지 않는다.
- 일반 방송 반응: 요청 입력, 선택된 관객과 대화 기억 출처, 모델 결과 도착, 수용·보류·대기·서버 전달·렌더러 표시 확인. 제공처가 보고한 토큰 사용량과 호출 영수증을 연결한다.
- 관객: 켜진 관객 전체의 입장 대기·참여·말없이 보기·자리 비움 상태와 입장 시각. 인원이 많으면 여러 조각으로 나누고 `part.index`와 `part.count`로 묶는다.
- 대화 기억: 성공적으로 저장된 대화의 목격자, 해당 요청에 선택된 대화 출처와 실제 목격 여부. 기억이 선택됐다는 사실이 발언에 영향을 줬다는 증거는 아니다.
- 앱: 서버 시작과 종료 구성 요소별 시작·완료·실패 및 소요 시간, Electron의 종료 요청과 실제 `quit` 이벤트. 종료 중 기록이 끝나면 마지막 시작 단계가 남을 수 있다. 마지막 기록만으로 장애 원인을 확정하지 않는다.

일반 반응 이외의 모델 호출·리허설 생성·모든 커뮤니티 활동·장치의 원시 프레임 전송을 전부 추적하는 기록은 아니다. 발언 수신 전의 누락과 기록 시작 이전 사건을 복원하지 않는다. 직접 전달한 구형 발언 경로에는 전송 수신 ID가 없을 수 있다. 제공처의 실패 호출에 결과 영수증이 없으면 요청의 종료 상태만 남는다.

렌더러 확인은 실제 채팅 요소의 관찰 시각이며 사람이 읽었다는 증거가 아니다. 이전 채팅을 뒤늦게 불러오는 경우도 첫 화면 표시와 구분해 해석해야 한다. 종료 이벤트는 네이티브 프로세스의 종료 시각을 대신하지 않는다. 패키지 검사에서는 별도의 `process-exit.json`, `process-close.json`과 전체 로그로 프로세스 종료와 표준 출력 연결 해제를 구분한다. 기존 15초 검사 기준은 유지한다.

## 개인정보와 보존

저장 위치는 프로필의 `data/broadcast-trace/`다. 원문·닉네임·모델 입력·화면·음성·오류 원문·인증 정보는 허용 목록에 없다. 방송·발언·대화·관객·호출 ID는 프로필별 키로 만든 HMAC 가명 값이다. 같은 프로필의 단계와 재시작을 연결할 수 있지만 다운로드에 원래 ID나 키는 포함하지 않는다. 시간과 연결 관계가 남으므로 익명화된 공개 자료로 취급하지 않는다.

앱이 소유한 JSONL 구간 파일만 최대 256KiB씩 저장하며 합계 16MiB, 최근 7일 범위를 유지한다. 다음 쓰기의 회전 또는 1분 간격 점검 때 오래된 파일을 정리한다. 앱이 꺼져 있으면 디스크 정리는 다음 실행까지 미뤄지며, 다운로드는 만료된 기록을 제외한다. 작은 연결 키 파일은 용량 계산에서 제외된다. 종료 직전 강제 중단·전원 손실에는 마지막 기록이 없거나 불완전할 수 있다.

파일 이름과 헤더·키가 일치하는 구간만 읽고 정리한다. 다른 파일과 잘못된 헤더는 보존하며, 링크 경로나 외부에서 변경된 쓰기 구간은 거부한다. 키가 없어졌거나 손상돼 복구할 수 없으면 기존 기록을 보존하고 새 기록을 중단한다. 원문이 들어간 알 수 없는 필드와 손상된 줄은 내보내지 않는다. `invalidRecords`, `readError`, `omittedFiles`, `unmanagedFiles`, `failedRecords`, `error`를 함께 확인한다. 빈 기록을 정상 수집의 증거로 삼지 않는다.

진단 저장 실패는 별도 오류 상태로 표시하고 방송의 입력·반응·종료는 계속한다. 한 프로세스 안에서는 `run`과 `sequence`로 순서를 확인한다. 시스템 시각이 바뀌거나 여러 실행 구간이 겹치면 시각만으로 전체 사건 순서를 확정할 수 없다. 용량·기간 상한, 실행 중 최대 4,000개 요청 연결과 4,500개 표시 연결 때문에 이력이 일부만 남을 수 있다.

## 검증과 복귀

`test/broadcast-trace.test.js`는 합성 입력의 실제 Studio 경로, 대화 목격·검색 연결, 120회 초과와 재시작, 전체 관객 페이징, 늦은 이전 방송 결과, 렌더러 시각 검증, 보존 상한·손상·링크·저장 실패, 인증된 읽기 전용 다운로드를 확인한다. `test/graceful-shutdown.test.js`는 종료 실패와 남은 정리 작업, 종료 요청·완료의 구분을 확인한다. `scripts/verify-broadcast-trace-ui.cjs`는 격리된 Electron에서 다운로드와 저장 실패 안내를 검증한다.

이 검사는 실제 마이크·게임 소리, 장시간 자연스러움 또는 사람의 평가를 대신하지 않는다. 이전 앱은 추가된 진단 파일을 사용하지 않으므로 기존 사용자 기록을 덮어쓰지 않고 실행본을 되돌릴 수 있다. 설치와 복귀는 [고정 설치 절차](STABLE-INSTALLATION.md)를 따른다.
