# 이전 대화 기록의 질문과 주변 발언 회상

발화 종류(`kind`)가 없는 이전 대화 기록도 원문 그대로 읽습니다. 스트리머의 질문과 가까운 관객 발언을 함께 찾아, 짧은 답변에 질문의 검색어가 없어도 목격한 대화를 회상할 수 있습니다.

`ConversationJournal`의 선택적인 세 번째 인수는 `{legacyAudienceIds: () => []}`입니다. 호출자는 현재 알려진 관객 ID 배열을 반환하며, 역할이 매니저인 인물과 선택된 매니저를 제외해야 합니다. 회상할 때마다 새로 평가하므로 제거되거나 매니저로 바뀐 인물은 종류 없는 관객 발언을 연결하는 데 사용하지 않습니다. 콜백을 제공하지 않으면 종류 없는 관객 답변을 연결하지 않습니다.

명시된 `kind`는 현재 역할보다 우선합니다. 종류가 없을 때만 `personaId === 'streamer'`를 스트리머 질문으로, 콜백이 반환한 ID를 주변 관객 발언으로 취급합니다. 익명 인물과 후원 기록은 이 보조 판정에서 제외합니다. 콜백에 없는 인물이나 명시적인 공지·후원 발언도 관객 답변으로 추정하지 않습니다.

현재 역할은 과거 역할을 입증하지 않습니다. 이 연결은 **인접한 목격 발언을 찾는 보조 수단**이며, 답변 여부나 과거의 발화 종류를 확정하지 않습니다. 반환한 인용에도 추정한 `kind`나 답변 확정 표시를 추가하지 않습니다. 원문·종류·저장 형식·revision을 바꾸거나 회상만으로 저장하지 않습니다.

목격하지 않은 발언, 이미 최근 문맥에 포함된 발언, 다른 세션·허구 여부·역순 시간은 기존 연결 경계를 유지합니다. 스트리머가 다시 말하면 이전 질문의 연결을 멈추며, 질문 뒤 90초 이내의 관객 발언을 최대 세 개 연결합니다. 정정은 같은 화자의 보존된 발화 순서와 120초 경계를 따릅니다. 정정 묶음을 나누어 낡은 발언만 남기지 않으며, 회상은 최대 8개 인용·총 1,800자·인용당 600자로 제한됩니다.

합성 회귀 검사는 다음과 같이 실행합니다.

```powershell
node --test test/legacy-conversation-recall.test.js test/spoken-question-memory.test.js test/recall-continuation.test.js test/conversation-journal.test.js test/correction-recall.test.js test/recall-experience.test.js
```

검사는 이전 기록 재로딩, 원문·revision·저장 부작용 없음, 현재 역할 재평가, 명시적 종류 우선, 익명·후원·공지·알 수 없는 인물 제외, 목격·시간·세션·보존 순서·삭제·인용 한도를 확인합니다. 합성 검사는 실제 계정의 모델 응답이나 설치된 앱에서 관객이 자연스럽게 회상하는지에 대한 검증을 대신하지 않습니다.
