# 함께 들은 말과 관객의 기억

2026-09-13. 공개 대화의 원문을 보관하고, 당시 함께 있던 관객이 다음 방송에서도 관련 발언을 다시 찾는 기능이다. 일반 라이브와 가상 기획·시즌의 대화에 연결했다. 모델은 GPT-6 Astra / low 그대로다.

## 사용자 흐름

`방송 밖 이야기 → 함께 들은 말, 오래 남기기`에서 원문·방송 제목·시각·함께 들은 관객을 확인한다. 검색, 관객 필터, 고정한 말 필터와 30개 단위 페이지를 제공한다. 최대 4,000개 중 오래된 미고정 발언부터 정리하며, 중요한 말은 100개까지 고정한다. 고정·검색은 모델 호출이나 포인트를 쓰지 않는다.

삭제는 원문을 보고 두 번 누르는 방식이다. 모델 응답 중에는 삭제를 기다리도록 안내하고 서버에서도 거부한다. 성공하면 현재 채팅의 같은 원본 ID와 기억 검색에서 제거하며 대기 응답도 비운다. 실패하면 원문과 고정을 유지하고 오류를 표시한다. 핫클립·시즌 기록·기존 관객 프로필에 별도로 복사된 내용과 복구 백업까지 지우는 전역 삭제는 아니다. 이 범위는 화면에 명시했다.

## 출처와 검색

원문마다 UUID, 세션, 공개 시각, 작성자, 실제 목격 관객 ID, 방송 제목, 가상 기획 여부를 저장한다. 라이브에서 실제 공개한 말만 기록한다. 리허설 예시·비공개 인터뷰·창작 속마음은 기록하지 않는다. 새 입장자는 입장 전에 다른 관객이 들었던 원문을 자신의 기억으로 받지 않는다. 이후 다른 관객이 설명한 말을 함께 들으면 그 설명의 새 출처를 갖는다.

정규 라이브와 시즌 진행의 `viewerContext.recollections`에는 해당 관객이 목격한 원문만 담는다. 최근 35개 대화와 중복하지 않으며 최대 8개/합계 1,800문자, 각 600문자 이하의 발췌를 제공한다. 발췌 여부와 시간·화자는 유지한다. 긴 인용이 뒤의 취소 발언을 밀어내지 않도록 분량을 배분한다. 출처가 없는 기존 개인 문자열은 이 두 모델 경로의 기억 입력에서 제외한다.

검색은 한국어 조사·상투적인 회상 질문을 일부 제거한 어휘/부분 일치와 문서 빈도 가중치다. 본인의 관련 원문, 최근 명시적 취소·정정, 관련 대화, 고정 발언 순으로 제한된 문맥을 선택한다. 모델에는 최신 의사 변경을 우선하고, 가상 설정을 실제 게임 사실로 만들거나 원문에 없는 기억을 꾸미지 않도록 지시한다.

이는 의미 검색이나 모델 재학습이 아니다. 동의어나 암시만 있는 질문, 관련 없는 최근 정정, 긴 발언의 뒷부분은 놓칠 수 있다. 여러 관객 패킷은 한 모델 요청에 함께 들어가므로 실행 수준의 비밀 격리는 아니다. 개별 특수기능·인터뷰·클립 회고의 모든 문맥이 새 검색기를 사용하는 것도 아니다. 장기 자연스러움, 반복률, 관계 변화의 수용 기준은 계속 열려 있다.

## 저장과 복구

`server/journal-store.js`는 다음을 사용한다.

- `conversation-journal-index.json`: 현재 리비전, 순서, 조각 해시. 기존 JsonStore의 임시 쓰기·fsync·rename과 3세대 백업을 적용한다.
- `conversation-journal-chunks/<sha256>.json`: UUID 앞 두 자리별 불변 조각. 바뀐 조각만 새로 쓰고 마지막에 인덱스를 커밋한다. 기존 조각을 덮어쓰지 않는다.
- 기존 `conversation-journal.json`이 있으면 검증해서 읽고 첫 변경에 이전한다. 원본은 남긴다. 인덱스나 백업이 생긴 뒤에는 오래된 이전용 파일로 돌아가 삭제된 말을 부활시키지 않는다.

시작 시 모든 참조 해시·원문 스키마·순서·중복·링크를 검사한다. 손상이 있으면 완전한 이전 인덱스로 복구하고 경고를 남긴다. 유효한 복구본이 없으면 초기화하지 않고 시작을 거부한다. 저장 실패는 메모리에 확정하지 않는다. 공개 채팅은 표시됐지만 기억 저장만 실패한 경우 이를 별도 오류로 알린다.

64회 변경마다 현재·백업·보존한 손상 인덱스가 참조하는 조각을 남기고, 이 저장소가 소유한 미참조 해시 파일만 정리한다. 해석 불가능한 인덱스가 있으면 정리를 미룬다. 손상 증거가 계속 쌓이거나 이전용 원본을 남긴 경우 디스크 크기가 4,000개 보관량보다 커질 수 있다. 전체 사용자 데이터의 여러 파일을 하나의 트랜잭션으로 커밋하는 구조는 아니다.

## 검증 결과

전체 203개 Node 검사와 TS/Vite 빌드가 통과했다(`artifacts/memory-package-final.log`). 기억 전용 19개는 원문·목격자·가상 구분·고정 한도·삭제·실패 후 재시도·백업 복구·기존 파일 이전·실제 서버 재시작·내보내기 인증을 검증한다. 이전 시즌 검사의 관객 선택이 확률적이면서 모모만 단정하던 문제는 실제 공개한 관객의 원문을 검사하도록 바로잡았다. 실패 로그 `memory-package.log`와 재시도 로그를 보존했다.

Electron 8개 흐름은 신규 빈 화면, 30개 페이지, 검색/고정, 늦은 입장자 필터, 서버/화면 재시작, 900px 너비, 삭제 실패 보존, 확정 삭제다. `memory-journal-desktop-test.json`, `memory-journal-ui-final-output.log`, `memory-journal-desktop.png`. 합성 관객/별도 프로필이며 물리적 화면·마이크를 사용한 검사는 아니다.

실제 Astra 연속 8회에서는 라디오 요일 정정, 첫 방문자의 이전 사건 미목격, 두 차례 재시작과 180개 합성 중간 발언 뒤의 약속 취소를 확인했다. 마지막 개인 코너 회상은 실패했다. 이 보고서의 `passed:true`는 당시 자동 단언 범위만 의미하며 전체 기억 합격으로 사용하지 않는다(`conversation-memory-live.json`/`.log`). 검색 순위와 문맥 선택 순서를 수정하고 원문을 보존한 상태에서 두 질문을 다시 호출했다.

최종 재실행은 각 질문 시각 이전 원문만 사용했다. 모모는 ‘이번 주 작은 행복’, 각보는고양이는 ‘한 판 돌아보기’를 각각 회상했으며, 마지막 취소를 존중했다. 지연은 10.455초/11.618초다(`conversation-memory-retrieval-fix.json`/`.log`). 앞선 재실행 중 취소 질문에 더 늦은 기록까지 포함했던 결과는 `conversation-memory-retrieval-fix-later-cutoff.*`로 따로 남겼다. 키보드로 넣은 한국어와 가상 시계 기반의 소수 사례이며 실제 20분 음성 방송 또는 장기 몰입 인증은 아니다.

긴 합성 원문 4,000개의 용량 시험에서 단일 JSON 전체 재저장 평균 약 416ms/회, 검색 약 306ms였다. 조각 저장과 불변 문자열 복사를 적용한 뒤 같은 조건의 12회 저장 평균 39.62ms, 검색 53.06ms였다. `journal-capacity-test.json`, `journal-capacity-final-test.json`, `scripts/benchmark-journal-capacity.mjs`. 운영체제·디스크 캐시 영향을 포함한 이 기기의 합성 시험이며 상시 응답 지연 보장은 아니다. 최대 보관량에서 수십 ms의 서버 작업 비용과 의미 검색 한계는 후속 개선 대상이다.
