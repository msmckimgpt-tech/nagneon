# AI 관객 미션

방송실의 포인트 안내 아래, **관객이 보고 있는 순간** 위에 **AI 관객 미션** 패널이 있습니다. 게임 방송 중 관심 있는 AI 관객이 보고 싶은 짧은 게임 내 과제를 제안하고, 다른 AI 관객이 자기 가상 예산으로 동참하거나 반대할 수 있습니다. 침묵은 찬성으로 세지 않습니다. 제안자와 실제 동참자 수·금액은 서버 기록으로 표시하며 플랫폼의 실제 시청자·후원 수치가 아닙니다.

미션점은 기존 앱의 가상P 잔액·관객 후원·포인트 부탁과 분리된 가상 예산입니다. 미션점과 기존 앱 가상P 모두 현금 가치·구매·환전이 없으며, 미션 완료가 스트리머의 P 잔액을 바꾸지 않습니다. 미션을 위한 별도 모델 호출은 추가하지 않으며 기존 방송 반응 요청에서 선택적으로 제안합니다. 그 요청은 기존 AI 연결의 이용량을 사용합니다.

## 제안과 예산

현재 초기값은 다음과 같습니다. 참여 효과를 실측해 정한 빈도가 아니며, 제안을 반드시 발생시키는 일정도 아닙니다.

| 항목                     | 기본값과 동작                                                   |
| ------------------------ | --------------------------------------------------------------- |
| 관객별 가상 예산         | 최초 참여 시 100미션점. 사용 가능 잔액과 예치 합계의 상한도 100 |
| 소비한 예산의 보충       | 10분마다 1미션점. 상한을 넘겨 쌓이지 않음                       |
| 한 관객의 한 미션 예치   | 1~40미션점, 한 번만 참여. 남은 목표·잔액이 적으면 그만큼만 예치 |
| 목표                     | 20~200미션점                                                    |
| 새 제안 간격             | 전체 최소 2분, 같은 제안자 최소 5분                             |
| 동시 진행                | 최대 2개, 같은 조건의 진행 미션은 1개                           |
| 모금·수락 기한           | 제안부터 5분. 목표를 모아도 수락 전까지 기한은 연장되지 않음    |
| 수행 기한                | 수락부터 10분                                                   |
| AI 완료 후보의 확인 기한 | 후보부터 최대 3분, 원래 수행 기한을 넘지 않음                   |

현재 방송 요청을 직접 접하고 아직 같은 방문에 있는 일반 관객만 참여합니다. 매니저·시스템 관객, 비활성 관객, 요청 이후 입장하거나 나갔다 돌아온 관객은 그 요청의 예치자가 될 수 없습니다. 수다·휴식·방송 밖 활동, AI 차단, 오래된 화면, 삭제된 입력에 기대는 응답에서는 참여를 받지 않습니다. 모델의 장면 확신이 75% 미만이거나 집중도 높은 큰 사건으로 분류한 경우에는 제안·동참·반대·완료 후보를 보류합니다. 관객별 취향과 상황에 따라 아무 제안도 없을 수 있습니다.

## 조건과 결정

자유 입력 조건은 받지 않습니다. 현재 허용하는 조건은 세 가지입니다.

| 조건                   | 유형   | 완료 기준                                                                    |
| ---------------------- | ------ | ---------------------------------------------------------------------------- |
| 소모 아이템 없이 한 판 | 수행형 | 수락 후 게임 내 소모 아이템 없이 한 판을 끝냄. 승패 무관                     |
| 재시작 없이 한 번 도전 | 수행형 | 수락 후 한 번 도전해 결과까지 재시작하지 않음. 실패해도 약속을 지켰으면 완료 |
| 현재 보스 한 번 처치   | 성공형 | 수락 후 현재 게임의 보스 한 명을 실제로 처치. 도전만 하거나 실패하면 미완료  |

제안 이유는 관객이 보고 싶은 이유이며 추가 수행 조건이 아닙니다. 현실의 위험한 행동, 개인정보 공개, 결제·유료 행동은 미션 조건으로 사용할 수 없습니다. 고정 조건과 금칙어 검사는 임의 표현 전체를 이해하는 안전 판정기는 아닙니다.

1. **함께 모으는 중**에는 예산을 보관합니다. 동참자는 따로 표시되고 반대는 예산을 소비하지 않습니다.
2. 목표가 차면 **수락 기다림**으로 바뀝니다. 모금은 부탁이며 수행 의무가 아닙니다. **이 조건 수락**을 눌러야 시작합니다.
3. 수락 전 **조건을 바꿔 다시 제안**에서 조건·목표를 수정할 수 있습니다. 이전 예치를 전액 반환하고 새 미션 ID와 조건 버전을 만듭니다. 이전 동참·반대는 승계하지 않습니다. 수락한 조건은 중간에 바꿀 수 없습니다.
4. 진행 중 AI가 완료 후보를 낼 수 있지만 자동으로 정산하지 않습니다. 스트리머가 표시된 게임 조건을 직접 확인하고 **조건을 지켰어요 · 예치 소비** 또는 **조건 미충족 · 반환**을 선택합니다. 후보가 없어도 직접 확인할 수 있습니다. 불확실하면 확인을 미루거나 취소할 수 있고, 기한이 끝나면 반환합니다.
5. 완료 확인은 예치만 소비합니다. 거절·취소·미이행·기한 종료·방송 종료·게임 변경은 전액 반환합니다. 일부만 모였어도 각자 예치한 만큼 반환합니다.

**거절 · 예치 반환**은 같은 방송에서 같은 조건을 다른 관객·더 큰 목표로 다시 제안하는 것도 막습니다. 스트리머가 **내 요청으로 같은 조건 재제안 허용**을 눌러야 그 조건을 다시 허용합니다. **미션 전체 중지**는 진행 중 예치를 반환하고 모든 새 제안·예치를 막습니다. 명확히 “미션은 그만”, “미션 안 할래”라고 말하는 것도 전체 중지로 처리합니다. 음성·채팅은 수락이나 완료 정산의 버튼을 대신하지 않습니다. **미션 제안 켜기**로 다시 켜도 이전 거절 조건은 별도 재허용 전까지 막히며, 기존 제안 간격도 유지합니다. 기존 훈수 허락·거절 및 기존 앱 가상P 부탁의 동의 경로는 그대로 사용합니다.

## 기억·저장·재시작

제안·수락·반환·스트리머 완료 확인 안내는 당시 직접 접한 관객에게만 기억 자료로 전달됩니다. 화면 장면은 같은 요청을 실제로 목격한 관객에게만 따로 남습니다. 기여하지 않은 관객도 직접 본 장면을 회상할 수 있지만, 예치했다는 이유로 자리를 비운 동안의 장면을 본 것으로 처리하지 않습니다. 스트리머 완료 확인을 접한 기억과 게임 수행을 직접 본 기억도 구분합니다. 장면 설명 자체는 모델의 관찰 후보이며 게임 성공을 증명하지 않습니다. 공동체에서 회상할 때도 기존 관객별 목격 기억의 범위를 따릅니다.

독립 파일 `missions.json`의 버전은 1입니다. 기존 `world.json`·Economy 형식, P 잔액, 프로필 reader 표시는 미션 때문에 변경하지 않습니다. 다른 기능에서 요구한 더 높은 reader 표시는 내려서는 안 됩니다. 미션 원장에는 예산 지급·보충·예치·소비·반환, 요청 ID와 실제 안내 목격자를 함께 저장합니다. 같은 요청을 재전송하면 원래 결과를 돌려주며, 내용을 바꾼 동일 요청 ID는 거절합니다. 한 서버 안의 결정을 순서대로 저장하고 기존 프로필의 단일 작성자 잠금을 사용합니다.

앱을 다시 열면 미정산 미션을 취소하고 예치를 **한 번만** 반환합니다. 재시작으로 이미 소비한 완료 미션을 환급하지 않으며, 방송을 이어서 수행한 것으로 가정하지 않습니다. 정상 종료에서도 미정산 예치를 반환합니다. 화면의 탭 이동이나 조건 상세 접기는 결정·정산을 실행하지 않습니다. 상태가 바뀐 뒤 도착한 수락·정산 요청은 거절하고 현재 서버 상태를 표시합니다. 자동으로 다른 결정을 재시도하지 않습니다.

원장 저장 실패 시 메모리와 기존 파일의 예치·정산을 보존하고 미션 AI 참여를 차단합니다. 오류를 표시하며 반환 유지 작업은 잠시 뒤 재시도합니다. 방송 중지 자체를 저장 오류가 막지는 않습니다. 기존 원장이 손상되거나, 더 높은 버전이거나, 백업만 남은 경우 과거 백업을 자동 복원하거나 예산을 새로 발급하지 않고 시작을 중단합니다. 과거 백업 복원은 완료 정산을 되돌릴 수 있으므로 임의 삭제·덮어쓰기로 복구하지 마세요.

## 합성 대화 예시

다음은 동작을 설명하기 위해 작성한 **합성 예시**이며 실제 방송 기록이나 모델 출력 보장이 아닙니다.

> 모모: 재시작 없이 한 번 도전하는 장면이 궁금해. 20미션점 보태볼래.
> 지지: 결과보다 긴장감이 재미있어서 15미션점 동참.
> 팝: 한 번의 선택이 궁금해서 남은 25미션점 동참.
> 다른 관객: 평소 방식이 더 좋아. 이번엔 반대할게.
> 안내: AI 관객 3명이 60/60미션점 예치. 수락은 자유입니다.
> 스트리머: [이 조건 수락] → 도전 실패, 재시작 없이 결과 확인 → [조건을 지켰어요 · 예치 소비]
> 안내: 수행형 조건의 스트리머 완료 확인. 예치 소비, P 지급 없음.

> AI 관객: 현재 보스를 한 번 처치하는 미션을 제안해볼까?
> 스트리머: 미션은 그만. 지금은 평소대로 할게.
> 안내: 미션 전체 중지, 기존 예치 반환.
> AI 관객: [새 제안·예치·집단 재촉 없이 평소 장면에 반응하거나 관망]

## 실행과 검증

개발용 체크아웃에서 기존 연결·프로필을 준비한 뒤 `npm run desktop`으로 실행합니다. 방송실에서 게임 카테고리로 방송을 시작하면 패널을 사용할 수 있습니다. 실제 모델의 선택이 필요하므로 특정 문구로 제안을 강제하거나 정기 발생을 보장하지 않습니다. 변경된 소스의 로컬 검증은 설치본 교체나 실제 계정·장치 검증을 뜻하지 않습니다.

```powershell
npm ci --no-audit --no-fund
npm run check
npm audit --audit-level=high
node --test test/mission-board.test.js test/mission-runtime.test.js
node -e "const {spawnSync}=require('node:child_process');const env={...process.env};delete env.ELECTRON_RUN_AS_NODE;delete env.OPENAI_API_KEY;const r=spawnSync('node_modules/electron/dist/electron.exe',['scripts/verify-missions-ui.cjs'],{env,stdio:'inherit',windowsHide:true});process.exit(r.status??1)"
```

마지막 검사는 자신의 `artifacts/mission-ui-<시각>/`에 합성 프로필과 화면을 만들고 숨김 Electron 창·인증된 임시 로컬 서버를 사용합니다. 제안, 부분 펀딩, 마지막 잔액만 예치, 중복 클릭, 사용자 확인 소비, 조건 변경, 거절, 정확한 기한, 전체 중지, 지연 수락 거절, 탭 이탈·복귀, 재시작 환급과 완료 정산 보존, P 불변을 검사합니다. 390px·860px 화면을 확인합니다. 비정상 종료 입력은 자기 합성 미정산 스냅샷으로 재현하고 실제 서비스를 두 번 재시작하며, 사용자 프로필이나 실제 계정·화면·음성을 사용하지 않습니다.

실제 모델과 여러 게임에서의 제안 품질·체감 빈도, 물리 장치, 설치본 업데이트, 다른 변경과 통합한 뒤의 네이티브 뒤로/앞으로 탐색은 별도 수용 검증이 필요합니다. UI는 최근 미션을 보여주지만 원장·요청 이력의 장기 보관 정리는 아직 구현하지 않았습니다.

미디어 회귀는 합성 캔버스·오디오와 주입한 소리 분석기로 검사합니다. 기존 화면 플레이어 동작을 유지하면서 탭 이동과 모의 창 가시성 이벤트 동안 미션 원장·앱P가 바뀌지 않고 화면 샘플링·독립 클립 녹화·소리 분석이 계속되는지, 방송 종료 시 트랙과 녹화가 끝나는지 확인합니다. 숨김·최소화에 따른 미리보기 해제 기능은 이 검사의 대상이 아닙니다. Reader5 프로필의 미션 정산·재시작 회귀도 기존 reader 표시와 앱P 보존을 확인합니다.
