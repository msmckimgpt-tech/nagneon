# 공개 방송 채팅 조사와 관객 소통·후원

2026-09-13. 작업: `codex/chat-attention-donations`, 기준 `dac2f30`. 개발 경로는 `G:/dev/ai/00_game_backseat-worktrees/chat-attention-donations`이며 main과 데이터·의존성·검증 산출물을 분리했다.

## 이번에 직접 확인한 범위

주 방향은 **스트리머와 관객 사이의 사실적인 소통**이다. 공개 한국 방송 다시보기와 연결된 실제 채팅을 조사했다. 영상·음성을 재생해 장면과 대사를 함께 관찰한 조사는 아니다. 채팅 타임스탬프만으로 반응의 원인을 특정하거나, 영상 메타데이터를 실제 영상 시청으로 보고하지 않는다.

치지직 공개 API의 비로그인 응답으로 다음 세 영상의 채널·제목·게시 시각과 채팅을 확인했다. 게시 시각은 API의 `publishDate` 원문 날짜이며 방송 시작 시각과 구분한다.

원본 출처는 각 영상의 `https://api.chzzk.naver.com/service/v3/videos/<videoId>`와 `https://api.chzzk.naver.com/service/v1/videos/<videoId>/chats?playerMessageTime=<ms>&previousVideoChatSize=50`이다. 비공개 방, 로그인, 쿠키, 연령 제한 우회는 사용하지 않았다. 성공한 표본 파일에는 채팅 본문·재생 시각·메시지 종류만 남기고 시청자 닉네임·프로필·사용자 해시는 보관하지 않았다. 실제 관객을 복제하거나 외부 채팅 원문을 제품 대사·모델 테스트 입력으로 사용하지 않았다.

각 영상의 10분과 30분에서 API 응답 하나씩, 최대 200행을 조회했다. 총 1,200행을 가져왔으나 느린 채팅의 응답은 서로 겹치고 수십 분에 걸쳐 있었다. 비교에는 **각 기준 시각 이후 5분 이내의 일반 메시지(type 1)만** 남겼다. 최종 표본은 겹치지 않는 817행이다. 빠른 채팅은 200행 제한 때문에 5분 전체가 아닌 27~52초의 일부만 포함한다. 채널 규모·한국 전체 비율이나 분당 메시지 수를 추정하는 표본이 아니다.

문자 수는 Unicode 코드 포인트 기준이며 치지직 이모티콘 자리표시자는 한 기호로 계산했다. 웃음 기호는 연속된 `ㅋ`/`ㅎ` 검출일 뿐 실제 감정 판정이 아니다. 일반 채팅에 섞인 질문·단편 반응·다른 사람 말에 대한 응답을 읽을 수 있었지만, 모든 줄의 대상을 확정할 수는 없다. 영상의 게임 카테고리가 해당 10분/30분 구간의 게임 플레이를 증명하지도 않는다.

추가로 침착맨의 공식 [채팅 읽어주는 라디오](https://www.youtube.com/watch?v=mmFnJm5zrHc)는 제목·게시일·길이와 한국어 자동 자막 트랙의 존재까지 확인했다. 자막 요청은 빈 응답, transcript 요청은 `400 FAILED_PRECONDITION`으로 끝나 실제 자막·영상 관찰 자료로 사용하지 않았다. [침하하의 TTS 관련 글](https://chimhaha.net/request_find/449108?page=1)은 영상 발견 경로와 한 이용자의 회고이며 방송인의 의도나 일반 문화의 증거로 격상하지 않았다.

## 관찰에서 적용으로

**관찰:** 같은 방송에서도 반응의 길이와 웃음 표기 빈도가 달랐다. 빠른 채팅은 단편 표현·공동 웃음이 연속할 수 있고, 여유 있는 표본에는 맥락을 덧붙인 문장이 보였다. **제품 해석:** 고정 웃음 비율·문장 길이·발언 할당량을 강제하지 않는다. 스트리머가 받아준 흐름을 중심으로 보고, 선택되지 않은 채팅은 지나갈 수 있다. 화면을 분석한 설명은 내부 scene에 두고 말하는 관객의 감상·질문·짧은 응답을 구분한다.

**관찰:** 치지직 공식 안내는 익명 후원의 공개 닉네임을 숨기면서 해당 스트리머의 후원자 확인을 허용한다. [공식 영상 후원 안내](https://help.naver.com/service/30044/contents/22983?lang=ko&osType=COMMONOS). **제품 해석:** 실제 금전 결제와 별개인 가상 포인트에 공개 익명 표시와 무료 개인 조회를 적용한다. 이 자료가 후원을 본 관객의 반응 확률이나 TTS의 적정 빈도를 입증하지는 않는다.

**설계 가설:** 후원은 일반 채팅보다 주의를 끌지만 진행 중인 이야기보다 항상 우선하지 않는다. 후원 농담에 일부 관객이 짧게 응답하고, 진지한 이야기나 이어지는 발언에는 기다리게 했다. 후원자에게 전원이 감사하거나 정체를 맞히는 행동을 기본 반응으로 만들지 않았다. 특정 창작자의 캐릭터·유행어를 복제하지 않았다.

## 구현

- `chatAttention`은 관객 입장 이후 60초 내 공개 발언을 대상으로 스트리머 발언, 후원 최대 2개, 호명, 일반 채팅의 맥락을 최대 7개 전달한다. 기존 최근 채팅·질문 응답 기억도 유지한다. 미래·입장 전·삭제·만료·가상 기획 발언은 현재 주목 대상으로 쓰지 않는다. 각 관객이 모든 줄에 답할 의무는 없다.
- 새 후원 또는 직접 호명된 관객 간 채팅은 정지 화면/Just Chatting에서도 한 번 더 반응할 수 있다. 채팅만 보고 생성한 답변은 연속 호출의 계기가 되지 않는다. 후원에 대한 호응만으로 새 포인트 보상이 생기지 않는다. 실제 새 화면·발언·소리가 있으면 일반 반응 흐름이 다시 열린다.
- 모델은 매우 긍정적인 공동 경험에서 자발적 후원 의도, 짧은 메시지, 익명 여부를 선택한다. 서버가 실제 참여·시청 시간·지갑·재충전·보상 상한·중복 사건·유료 행동 차단을 확인하고 금액을 결정한다. 현재 모델이 후원 의도를 비우면 지급하지 않는다. 예전 형식의 응답은 기존 후보 방식과 호환한다.
- 후원은 실제 저장에 성공한 거래 ID로 채팅과 알림에 나타난다. 메시지 없는 응원도 가능하다. 금지어 또는 익명 후원의 현재 닉네임/ID/기록된 이전 닉네임 서명은 공개 메시지에서 보류한다. 내부 사건 분석문을 대신 읽어주지 않는다.
- 공개 ledger, 채팅, 오버레이 표시, AI 입력, 대화 기억에는 익명 후원자 매핑을 넣지 않는다. 실제 후원자 ID와 당시 이름은 경제 기록에 저장하고 인증된 `GET /api/donations`에서 무료로 조회한다. 별도 **받은 후원** 창에 당시 이름·현재 이름·안정된 관객 ID가 보이며 성향 해금이나 포인트 차감은 없다. 현재 경제 기록의 최근 거래 300건에 포함된 후원만 보이며 UI에 이 범위를 안내한다.
- 내부 후원 후보와 의도는 공개 observation/다음 관객의 이전 장면에서 제거했다. 공개 지갑 정보에서도 마지막 후원 시각을 제거했다. 공개 이름인 후원은 기존 닉네임을 표시한다. 삭제한 채팅은 알림과 기억에서 사라지지만 이미 받은 포인트와 개인 거래 내역은 유지된다.

익명성은 서비스가 제공하는 구조화된 매핑과 표시의 구분이다. 로컬 파일 소유자나 앱 연결 권한을 가진 스트리머로부터 거래 기록을 암호화해 숨기는 보안 경계는 아니다. 모델이 자유 문장에 신원을 암시하는 모든 표현을 절대 생성하지 않는다는 보장도 아니다. 정체 추리 금지 지침·정확한 자기 서명 차단·실제 모델 사례로 현재 경로를 검증했다. 개인별 컨텍스트는 한 모델 요청에 함께 들어가는 기존 설계를 유지한다.

## 검증과 남은 범위

`test/chat-attention-donations.test.js`: 11개 검사. 실제 HTTP 401/200·무료 조회·공개 state/export, 재시작과 닉네임 변경, 포인트 보존·원자성·중복 방지, 익명 서명·금지어, 입장/삭제/만료, 공개 기억, 관객 반응 연쇄 차단을 검증했다. `test/donation-render.test.js`: 2개 React 서버 렌더 검사로 공개 익명·금액·HTML escaping·만료/삭제/미래 알림 배제를 확인했다. 이는 실제 창 조작 검사가 아니다.

`scripts/verify-chat-attention.mjs`: 공식 CLI, `gpt-6-astra`, `low`, 합성 6사례를 실제 호출했다. 최종 프롬프트 기준 모두 통과했으며 8.567~18.277초였다. 관객 간 질문은 호명된 관객 한 명이 답했고, 후원 농담은 한 명이 받아쳤으며, 진지한 이야기에서는 농담을 멈췄다. 익명 정체를 모른다고 답했고, 이어지는 말끝에는 기다렸다. 극적인 성공에서는 3명의 축하와 일반/익명 후원 의도가 각각 생성되어 서버 지급 경로도 통과했다. 실제 사용자 발언·웹 채팅 원문·장치 캡처는 모델에 전송하지 않았다.

이 6사례는 장기 현실감이나 실제 방송의 음성 전달 지연 개선을 입증하지 않는다. 최종 전체 검사·통합 결과는 아래 기록으로 남긴다. 사용자 앱 재시작, 게임 실행, Computer Use, 마이크/화면/출력 장치 캡처는 수행하지 않는다. 배포 패키지를 자동 교체하지 않는다.

다음 검증에서는 사용자 방송의 실제 대화에서 질문 회수·안 읽힌 채팅에 대한 태도·후원 뒤 자연스러운 주제 복귀·관객 개별 말투의 지속성을 살펴야 한다. 게임 플레이 중 영상/음성/채팅을 같은 타임스탬프로 확인하는 조사, 더 다양한 창작자·규모·플랫폼의 표본, UI 사용성 검사는 남아 있다. 저장 복구 작업은 별도 `codex/clip-storage-recovery`에 제품 변경 없이 보류했으며 이번 소통 방향보다 앞서 진행하지 않았다.
