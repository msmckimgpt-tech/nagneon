# 0.1.15 실행 도구 유지보수

기존 시작 메뉴와 바탕 화면 바로가기는 같은 고정 `Start-Nagneon.cmd`를 사용한다. 새 실행기는 이미 설치된 표준 PowerShell 7 또는 Store 설치를 우선 선택하며, 둘 다 없으면 Windows PowerShell을 사용한다. 실행 정책을 덮어쓰지 않고 선택한 엔진의 실패를 그대로 반환한다. 앱 버전, 관객 생성, 모델 선택과 저장 형식은 0.1.15 그대로다.

설치 도구에는 `Launcher-Command.ps1`을 함께 둔다. [기존 설치 절차](STABLE-INSTALLATION.md)에 따라 검증된 0.1.15 앱 패키지를 다시 적용하면 데이터와 이전 바로가기뿐 아니라 이전 CMD도 백업한 뒤 실행기를 갱신한다. 새 앱 패키지를 중복 배포하거나 게시된 0.1.15 파일을 교체하지 않는다.

회귀 검사는 실제 CMD에서 두 진입점의 표준·Store·Windows PowerShell 선택과 실패 시 재시도 금지, 종료 코드 37 보존, 한글·공백·느낌표·앰퍼샌드 경로를 확인한다. 실행 파일은 인자를 기록하는 격리 fixture이며 사용자 앱·프로필을 열지 않는다. Codex 같은 패키지 호스트가 WindowsApps를 다른 보기로 제공할 때는 `NAGNEON_TEST_POWERSHELL`에 검증용 PowerShell의 절대 경로를 지정한다. 이 변수는 테스트에만 적용되며 제품 실행기에는 적용되지 않는다.

앱·프로필 복귀 기준은 기존 설치 문서를 따른다. 현재 기록에 구버전 앱을 연결하거나 실행 정책을 바꾸어 복구하지 않는다. 이전 CMD 바이트는 업데이트 백업에 남으며, 새 실행기에서 문제가 생기면 검증된 설치 도구와 앱 패키지로 다시 적용한다. 네이티브 설치·실행 결과와 배포 파일 해시는 해당 유지보수 릴리즈 기록에 별도로 남긴다.

개발 검증: `npm ci`, `npm run check`의 1,204개 검사와 빌드, `npm audit --audit-level=high`가 통과했다. 격리 설치 fixture에서 같은 0.1.15 패키지를 다시 적용해 프로필·백업·기존 CMD 해시와 실행기 바이트 복귀/재적용을 확인했다. 실제 사용자 환경의 실행 확인은 이 fixture와 구분한다.
