# 관객 메모의 저장 응답과 초안 보존

`나의 관객`에서 메모 저장을 누르고 응답을 기다리는 동안 다시 입력하면, 이전 요청의 완료 처리가 새 초안을 지우던 문제를 수정했다. 또한 저장 HTTP 응답이 화면 상태 갱신(SSE)보다 먼저 도착하면, 방금 저장한 내용이 아직 갱신되지 않은 이전 서버 값으로 되돌아가던 문제도 수정했다.

메모를 편집할 때마다 로컬 편집 번호를 올리고, 요청을 시작한 번호가 현재 번호와 같을 때만 저장 완료로 표시한다. 새로운 초안이 생겼으면 편집 상태와 저장 버튼을 유지한다. 서버 값은 실제로 바뀌었을 때만 편집하지 않는 카드에 적용한다. 메모 원문·서버 API·저장 형식·관객 ID는 바꾸지 않는다. 저장 오류가 나면 초안을 유지하고 다시 저장할 수 있다.

## 실제 화면 검증

`scripts/verify-viewer-note-draft.cjs`는 계정·마이크·게임을 사용하지 않는 합성 관객 두 명을 만든다. 실제 Electron/React 화면과 인증된 HTTP 서버, 별도 파일 프로필에서 다음을 검사한다.

- 서버가 첫 메모를 저장한 뒤 HTTP 응답을 지연하고 그 사이 새 문장을 입력한다. 이전 완료 응답이 새 문장을 덮어쓰지 않고, 아직 저장하지 않은 상태로 유지되는지 확인한다.
- SSE 발행을 잠시 지연한 상태에서 저장을 완료한다. 이전 화면 상태가 방금 저장한 문장을 지우지 않는지 확인한다.
- 합성 HTTP 오류 뒤 초안과 기존 서버 값을 각각 확인하고, 다시 저장해 성공을 확인한다.
- 닉네임 변경 후에도 같은 관객의 메모가 유지되는지 확인한다. 서버를 정상 종료한 뒤 같은 격리 데이터로 다시 시작하고 화면을 열어 저장된 메모를 확인한다. 다른 관객의 메모가 바뀌지 않았는지도 확인한다.
- 실제 모델 호출은 0회다. 스크린샷과 구조화 결과를 `artifacts/viewer-note-*/`에 남긴다. Windows CI에서도 같은 검증을 실행한다.

수정 전 `viewer-note-yMGLFI/result.json`은 새 초안이 `첫 저장`으로 덮어써지는 실패를 보여준다. 편집 번호만 적용한 중간본 `viewer-note-0gzY0F/result.json`은 첫 오류가 해결돼도 늦은 SSE로 내용이 되돌아갈 수 있음을 보여준다. 최종본 `viewer-note-wg75QQ/result.json`은 네 검사 통과와 모델 호출 0회를 기록한다. 화면은 같은 폴더의 `notes.png`다. 작업 공간은 `viewer-note-draft-20260923`이며 최초 실행기의 함수 반환 복제 오류도 `native-before.log`에 보존한다. 실행기를 고친 뒤 제품 결함을 재현했으므로 실행기 오류를 제품 실패로 세지 않는다.

사용자가 탭을 닫거나 앱을 종료하기 전 저장하지 않은 초안을 영구 복구하는 기능은 아니다. UI 경합 수정이며 사용자 설치본 교체·릴리즈 검증은 별도다.
후속 검토에서는 재시도 성공 후 이전 오류 안내가 남지 않는지와, 편집하지 않는 카드가 다른 연결에서 실제 변경한 서버 메모는 정상 수신하는지도 확인했다. 최종 `viewer-note-A9tXpc/result.json`의 다섯 검사가 모두 통과했고 모델 호출은 0회였다. `check-final.log`는 형식 검사·866개 테스트·TypeScript/Vite 빌드 통과를, `audit.log`는 취약점 0건을 기록한다.
