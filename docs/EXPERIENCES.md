# 방송 놀이터 · 기획과 구현

2026-09-13. 목표는 현실적인 방송 연습과, 현실에서는 하기 어려운 방송의 즐거움을 함께 제공하는 것이다. 관객은 실제 사람이 아니라 지속되는 설정과 기록을 가진 AI 캐릭터다. 친밀감, 취향 차이, 자기만의 역할을 중심으로 설계한다.

## 지금 작동하는 흐름

`방송 놀이터 → 기획 방송 → 방송 시작 → 설정 작성 → 무대 열기`로 시작한다. 각 기획 방송은 세 장면으로 구성되며 장면 사이에 자유 채팅·마이크 대화를 이어갈 수 있다. 관객은 기존 성격과 취향을 유지한다. 장면을 진행하면 Astra low를 한 번 사용한다. 기획된 환호가 자동 포인트 보상으로 순환하지 않도록 분리했다.

| 기획 방송 | 경험 |
|---|---|
| 우리 방의 기념일 | 생일·100일·개인적인 기념을 함께 축하 |
| 기다렸던 복귀 방송 | 반가움, 어색함, 두 번째 첫날 |
| 방구석 시상식 | 가상의 상과 수상 소감, 각기 다른 심사위원 |
| 채팅 크루 팬 페스티벌 | 관객별 취향 부스, 서로의 제안에 대한 반응 |
| 이 순간의 전설 | 명장면 선정, 클립 제목 회의, 예능식 과장 |
| 우리만 아는 밈 공방 | 농담의 씨앗, 변주, 스트리머의 선택 |
| 새벽 라디오 | 가상의 가벼운 사연과 DJ의 답변 |
| 취향 재판소 | 가벼운 취향 논쟁, 반론, 방장의 판결 |
| 크루 챌린지 | 도전 선언, 응원·코치 역할, 결과 정리 |
| 만약에 극장 | 자유로운 허구 세계관, 선택, 역할극 엔딩 |

기획 방송은 최대 50개까지 앨범에 남는다. 대화가 있는 방송을 핫클립으로 옮기면 다른 관객들도 댓글과 대댓글을 남길 수 있다. 실제 화면에서 관찰한 사건과 기획 방송의 설정은 분리한다. 후속 기억에도 가상 기획 방송 표시를 붙인다.

상황 연습은 오프닝·침묵·반복 실패·훈수·논쟁·급격한 유입·스포일러·사적 질문·후원 압박·비판·기술 문제·엔딩·도배·리듬의 14종이다. 준비된 채팅을 9초 이상 간격으로 내보낸다. 응답·중재·점검 기록과 자기 성찰 질문을 제공하며, 발언 내용의 공감 능력이나 방송 실력을 자동 점수화하지 않는다. 실제 방송 기록·포인트·관객 기억을 변경하지 않는다.

## 검증

- `artifacts/expansion-check-final.log`: 74개 서버 테스트 및 TypeScript/Vite 빌드 통과(저장 복구 통합 전 기준).
- `artifacts/expansion-desktop-test.json`: 실제 Electron 렌더러에서 연습·기획 방송·포인트 수첩·핫클립·댓글·녹화된 WebM 재생·화면/마이크 해제·900px 화면 검증. 모델과 화면/음성은 합성 입력이다.
- `artifacts/expansion-live-result.json`: 실제 GPT-6 Astra low 7회, 기획 방송 3장면·창작 독백·취향 인터뷰·협상 행동·핫클립 대댓글. 임시 관객/크레딧을 사용하고 사용자 데이터는 쓰지 않았다. 10.5~14.5초의 단일 요청 지연이 측정됐다. 이는 소규모 연결 검증이며 장기간의 자연스러움을 증명하지 않는다.
- `artifacts/experiences-native.png`: 현재 설치된 개발 앱의 실제 방송 놀이터 화면. 방송·마이크·화면 연결은 중지 상태다.

## 확장 방향과 남은 품질 과제

이 10종은 출발점이다. 다음 확장은 장기적인 방송 시즌, 관객 간 갈등과 화해의 지속적인 변화, 취향별 소모임, 관객이 자발적으로 기획하는 행사, 가상 합방 역할, 도전의 여러 결말, 사연·투표·미션이 다음 방송으로 이어지는 구조다. 해당 항목은 아직 구현 완료로 표시하지 않는다.

현재 기획 방송은 순서가 있는 세 장면과 자유 대화이며 완전한 분기형 서사 엔진은 아니다. AI가 항상 재미있고 일관된 반응을 한다는 보장은 없다. 방송 중 촬영 장면과 감정을 평가하는 장기 실사용, 반복률·기억 오류·훈수 오류·평균 및 상위 지연 측정이 필요하다. Steam 판매 준비에는 별도의 배포·복구·인증·설치·라이선스 검토가 남아 있다.
