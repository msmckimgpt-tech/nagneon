# 종료된 방송 놀이터 · 과거 구현 기록

기획 방송·시즌·상황 연습을 별도 모드로 시작하는 기능은 종료되었습니다. 현재 앱은 평소 방송에서 관객과 이야기하며 기념일·복귀·도전·취향 논쟁·관계 변화를 이어갑니다. 새로운 기획 방송이나 연습을 시작하거나 진행할 수 없으며, 예전 기록은 내보내기에 보존됩니다. 현재 사용 방법은 [Nagneon 사용 안내](USER-GUIDE.md)를 참고하세요.

아래 내용은 **2026-09-13 당시 구현과 검증**입니다. 표의 기능과 테스트 결과는 과거 빌드에 해당하며 현재 이용 가능한 모드나 최신 버전의 검증 결과가 아닙니다.

## 당시 기획 방송의 구성

과거에는 `방송 놀이터 → 기획 방송 → 방송 시작 → 설정 작성 → 무대 열기`로 시작했다. 각 기획 방송은 세 장면으로 구성되었고, 장면 사이에 자유 채팅·마이크 대화를 이어갈 수 있었다. 관객은 기존 성격과 취향을 유지했고, 장면 진행에는 Astra low 요청 한 번을 사용했다. 기획된 환호를 자동 포인트 보상으로 순환시키지 않았다.

| 당시 기획 방송 | 경험 |
|---|---|
| 우리 방의 기념일 | 생일·100일·개인적인 기념을 함께 축하 |
| 기다렸던 복귀 방송 | 반가움, 어색함, 두 번째 첫날 |
| 방구석 시상식 | 가상의 상과 수상 소감, 각기 다른 심사위원 |
| 채팅 크루 팬 페스티벌 | 관객별 취향 부스, 서로의 제안에 대한 반응 |
| 이 순간의 전설 | 명장면 선정, 클립 제목 회의, 예능식 과장 |
| 우리만 아는 밈 공방 | 농담의 씨앗, 변주, 스트리머의 선택 |
| 새벽 라디오 | 가상의 가벼운 사연과 DJ의 답변 |
| 취향 재판소 | 가벼운 취향 논쟁, 반론, 방장의 판결 |
| 크루 챌린지 | 도전 선언, 응원·코치 역할, 결과 정리 |
| 만약에 극장 | 자유로운 허구 세계관, 선택, 역할극 엔딩 |

당시 기획 방송은 최대 50개까지 앨범에 남았고, 대화가 있는 기록을 장면 기록으로 보관해 댓글과 대댓글을 이어갈 수 있었다. 실제 화면에서 관찰한 사건과 기획 방송의 설정을 분리했으며 후속 기억에 가상 기획 방송 표시를 붙였다.

상황 연습은 오프닝·침묵·반복 실패·훈수·논쟁·급격한 유입·스포일러·사적 질문·후원 압박·비판·기술 문제·엔딩·도배·리듬의 14종이었다. 준비된 채팅을 9초 이상 간격으로 내보내고 응답·중재·점검 기록과 자기 성찰 질문을 제공했다. 실제 방송 기록·포인트·관객 기억은 변경하지 않았다. 현재의 첫 사용 안내에서 제공하는 리허설은 이 별도 상황 연습 모드와 구분한다.

## 당시 검증

다음 원본은 해당 개발 작업의 로컬 `artifacts/` 기록이다. 합성 입력·실제 모델 연결·네이티브 화면 확인을 구분하며 현재 버전의 수용 결과로 재사용하지 않는다.

- `artifacts/expansion-check-final.log`: 당시 서버 테스트 74개와 TypeScript/Vite 빌드 통과. 저장 복구 통합 전 기준.
- `artifacts/expansion-desktop-test.json`: Electron 렌더러의 연습·기획 방송·포인트 수첩·핫클립·댓글·녹화된 WebM 재생·화면/마이크 해제·900px 화면 검증. 모델과 화면·음성은 합성 입력.
- `artifacts/expansion-live-result.json`: 실제 GPT-6 Astra low 7회로 기획 방송 3장면·창작 독백·취향 인터뷰·협상 행동·핫클립 대댓글을 확인. 임시 관객·크레딧을 사용하고 사용자 데이터는 사용하지 않았다. 단일 요청은 10.5~14.5초였으며 장기간의 자연스러움을 증명하지 않는다.
- `artifacts/experiences-native.png`: 당시 설치된 개발 앱의 방송 놀이터 화면. 방송·마이크·화면 연결은 중지 상태.

## 현재 이어지는 경험과 남은 검증

현재는 관객의 자발적인 유입·성향 변화·클립 선택과 일반 방송의 대화를 중심으로 경험을 이어간다. 사용자가 별도 시즌이나 정해진 장면 순서를 시작하는 흐름은 다시 제공하지 않는다. [관객 유입과 변화](AUDIENCE-AUTONOMY.md), [자발적인 커뮤니티 활동](AUTONOMOUS-COMMUNITY.md)

반복되는 말투·기억 오류·훈수 오류·응답 지연과 장기적인 관계의 자연스러움은 실제 사용에서 계속 확인해야 한다. Steam 판매 준비에는 설치·업데이트·복구·인증·배포 조건의 검증도 필요하다. [판매 준비 기준](RELEASE-GATES.md)
