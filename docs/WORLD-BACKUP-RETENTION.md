# 변경 세대를 보존하는 world 저장

`world.json`에는 관객의 관계·기억, 방송 설정, 포인트와 구매 기록이 함께 저장된다.
이 파일의 백업은 최근 세 번의 실제 저장 변경을 복구할 수 있도록 보존한다.
내용이 같은 방송 중지나 앱 종료는 이전 복구 시점을 소비하지 않는다.

`JsonStore`의 `skipUnchanged`는 기본적으로 꺼져 있으며 서버의 world 저장에만
켜진다. 입력 사본의 스키마 검증과 reader 호환성 표식 승격을 먼저 수행하고,
검증된 값의 정규 JSON UTF-8 bytes가 실제 기본 파일의 bytes와 정확히 같을 때
쓰기·임시 파일 생성·백업 회전을 생략한다. 캐시나 객체 참조는 비교 기준이 아니다.
관객 데이터를 메모리에서 수정한 뒤 중지할 때도 변경 내용은 계속 저장된다.

기본 파일이 없거나 손상됐거나 외부에서 달라졌으면 기존 원자 저장 절차를 따른다.
동일성 비교에서 발생한 읽기 권한 오류는 임시 파일 생성 전에 보고한다.
손상 원본 보존이 대기 중이거나 이전 쓰기의 임시 파일이 남아 있으면 기존 저장
절차를 유지하며 쓰기를 생략하지 않는다. 공백·키 순서·스키마 기본값을
정규화해야 하는 경우도 실제 저장으로 취급한다. 잘못된 UTF-8를 같은 문자열로
해석하는 경우까지 구분하기 위해 디코딩한 문자열 대신 원본 bytes를 비교한다.

백업은 이전 변경 세대의 상한이며 현재 기본 파일의 복제본이나 최소 백업 수를
보장하지 않는다. 새 프로필이 바뀌지 않은 채 닫히면 최초 복제 백업을 만들지
않는다. 기존 백업의 삭제·손상도 내용이 같은 저장으로 자동 치료하지 않는다.
이 동작은 여러 저장소를 묶는 트랜잭션이나 동시 외부 작성자 보호를 추가하지 않는다.
프로필 작성자 잠금과 reader/provenance 검증은 기존 경로에서 계속 적용된다.

검사는 `test/world-backup-retention.test.js`에서 실제 임시 파일과 격리 서버를
사용한다. 구별 가능한 이전 세대를 둔 반복 중지·종료·재시작, 실제 변경의 한 번
회전, 메모리 수정, 외부 파일 수정·삭제·손상, 읽기/쓰기 실패와 UTF-8 경계를
검증한다. 패키지 재시작 검사는 변경 없는 종료에 기존 파일과 모든 백업이 그대로
남는지를 확인한다. 사용자 설치본·장치·계정 수용 검증과는 별도다.
