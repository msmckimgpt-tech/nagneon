# 재입장한 관객의 최근 소리 근거

관객이 방송을 나갔다 돌아온 뒤에는 재입장 시각부터 들은 소리만 현재 방송의 청취 근거로 전달한다. 예전 방문의 대사나 효과음을 같은 관객 ID의 최근 소리로 다시 넘기던 문제를 수정했다. 소리 분석 결과가 재입장 뒤 늦게 도착한 경우에도 원래 캡처 시각을 따른다.

`SoundScene.context()`는 관객의 현재 `joinedAt`, 원래 구간 시작 시각, 캡처 당시 청취자 목록을 함께 확인한다. 입장 시각을 확인할 수 없거나 관객이 삭제됐다면 최근 소리를 제공하지 않는다. 원래 사건과 청취자 기록을 고쳐 쓰지 않으며, 계속 시청하던 다른 관객은 같은 근거를 받는다. 새 방문이 구간 중간에 시작됐다면 전체 구간을 들었다고 가정하지 않는다.

이 규칙은 로컬 음향 분석과 ChatGPT 구독 시스템 대사에 공통 적용한다. 구독 전사의 정정도 원래 구간을 기준으로 처리한다. 최대 4구간·최근 30초 제한, 무음 제외, 입력 종료·교체 시 삭제, 시스템 대사와 스트리머 발언의 구분을 유지한다. 설정·저장 형식·모델 선택·호출 수는 변경하지 않는다.

## 재현과 검증

```powershell
npm ci
node --test test/sound-visit-boundary.test.js
npm run check
npm audit --audit-level=high
```

회귀 검사는 합성 소리 사건으로 재입장 전후, 지연된 분석 완료, 구독 정정, 잘못된 입장 시각, 기존 제한과 복사 격리를 확인한다. 실제 Studio의 모델 입력과 인증된 루프백 HTTP 업로드도 검사한다. HTTP 검사에서는 합성 분석기를 사용하며 사용자 마이크·화면·계정·음성을 수집하지 않는다.

2026-09-30 Windows에서 수정 전 6건 중 5건이 실패했고 수정 후 관련 회귀 68건이 통과했다. 원본 로그는 격리 작업 공간의 `artifacts/before.log`와 `artifacts/regression.log`에 보존한다. 이 결과는 모델로 전달되는 현재 방문의 청취 범위를 입증하며 효과음 분류 정확도, 실제 모델의 자연스러운 반응이나 물리 장치 성능을 입증하지 않는다.

정상 실행 정책을 유지한 시험 호스트를 지정한 전체 `npm run check`는 형식 검사, 1,213개 테스트, TypeScript/Vite 빌드를 통과했다. 최초 호스트 실패는 `artifacts/check.log`, 성공한 전체 검사는 `artifacts/check-configured-host.log`와 `artifacts/test-host.json`에 남긴다. Vite의 500 kB 이상 JS 청크 안내는 출시 성능 검증과 구분한다.

전체 검사에서 Codex 호스트의 WindowsApps 보기와 기본 시험 엔진 정책 차이가 확인되면 [실행 도구 검증 안내](RELEASE-0.1.15-LAUNCHER.md)에 따라 `NAGNEON_TEST_POWERSHELL`에 검증용 호스트의 절대 경로를 미리 지정한다. 제품 실행기나 Windows 실행 정책을 변경하지 않는다. 실패 기록과 재검증 결과를 함께 보존한다.

최초 기준 코드의 `brace-expansion` 빌드 의존성에서 npm audit 고위험 경고가 확인돼 통합을 보류했다. 해당 패치가 반영된 0.1.17 코드로 갱신한 후 전체 검사 1,215개·형식 검사·TypeScript/Vite 빌드와 보안 경고 0건을 확인했다. 원본은 `artifacts/check-0.1.17.log`, `artifacts/audit-0.1.17.json`이며 이전 실패도 보존한다. 경고 면제나 감사 우회는 사용하지 않았다. [공식 취약점 공지](https://github.com/advisories/GHSA-qhr7-859c-m2p7).
