# 채팅 침묵과 전달 지연의 진단

2026-09-14. 기준 `c72b8f159438b566a5de306e7cd20d96b9dc6d59`, 작업 `codex/reaction-diagnostics`, 경로 `G:/dev/ai/00_game_backseat-worktrees/reaction-diagnostics`.

[실제 게임 대화 검증](LIVE-CONVERSATION-ACCEPTANCE.md)에서는 전투 후 일반 채팅이 거의 없었지만, 당시 원본은 모델이 말하지 않았는지와 생성된 말이 보류됐는지를 구분하지 못했다. 기존 모델 호출 수와 최종 대화 기록만으로 원인을 특정할 수 없다. 이번 변경은 앞으로 진행하는 방송에서 그 차이를 확인하기 위한 운영 기능이다. 이전 게임의 침묵 원인을 소급해 확정하거나 대화 품질·응답 속도를 개선했다고 주장하지 않는다.

## 동작

- 매니저 화면의 **채팅이 뜸하거나 늦을 때 · 응답 진단**을 펼치면 현재 집계를 읽는다. 새로 확인과 진단 다운로드는 로컬 읽기만 수행하며 모델을 호출하지 않는다.
- 일반 라이브 모델 요청의 시작·완료 시간, 발언/영상 유무와 영상 수, 참여/응답 후보 수, 생성 채팅 수, 대기·표시 건수, 첫 표시까지 걸린 시간을 기록한다. 관객 생성·특수 기능·기획·커뮤니티·음성 전사 호출은 포함하지 않는다.
- `generated=0`인 정상 완료는 모델의 침묵으로 구분한다. 중복·금칙어·스포일러·훈수 제한·참여 범위 변경·시간 초과·채팅 수 제한은 별도 보류 사유다. 생성 중 취소/오류와 음성 교정 보류도 요청 결과로 구분한다.
- 화면 반응 기한을 넘긴 모델 결과와 큐에서 표시를 기다리다 만료된 채팅은 서로 다른 요청 상태로 남는다. 기존 20초 영상 반응 기한과 채팅 정책을 완화하지 않았다.
- 새 발언, 운영자 정리, 방송 종료 등 다른 경로에서 빠진 대기 채팅은 `cleared`로 집계한다. 이 항목만으로 어떤 원문이나 사람이 원인이었는지는 알 수 없다. 실제 표시 뒤 삭제한 채팅은 표시됐던 건수에 남는다.
- 모델 시간의 중앙값/95백분위는 반환된 응답만 대상으로 한 최근 보관 표본의 nearest-rank 값이다. 실패/취소돼 결과가 없는 요청은 응답 시간 분포에 넣지 않는다. 음성 전사, 문맥 준비, 캡처 연결, 모델 이후 채팅 대기는 모델 시간에 포함하지 않는다. `firstDeliveryMs`는 모델 요청 시작부터 첫 채팅 표시까지이며 발화 끝 기준 지연이 아니다.

집계는 앱 메모리의 최근 120개 일반 요청으로 제한한다. 총 호출 수는 이번 방송 전체, 나머지 합계는 보관 중인 요청 기준이다. 방송을 종료하면 결과를 내려받을 수 있고 다음 방송 시작/앱 종료에서 지워진다. 앱 재시작 후 복구하는 장기 진단 저장소는 아니다. 진단 요청 ID는 내부 숫자이며 관객/대화/계정 ID가 아니다.

## 내용과 접근 경계

`GET /api/diagnostics/reactions`는 기존 루프백·실행별 인증·Origin 제한을 따른다. `download=true`이면 JSON 첨부 파일로 제공하고 항상 `Cache-Control: no-store`를 보낸다. 서버가 정한 필드와 사유만 포함하며 모델 오류 원문, 발언/채팅 원문, 이미지·음성, 닉네임·관객 신원, 페르소나·메모·계정 토큰·파일 경로는 기록하지 않는다. 기존 전체 운영 기록 내보내기와 별개의 다운로드다. 외부 업로드와 디스크 자동 저장은 없다.

개별 관객의 마음·의도·성향을 해금하는 기능이 아니다. 모델의 빈 응답은 관객의 심리나 거부 의사를 확정하지 않으며 앱이 응답 후보로 전달한 인원수와 함께 해석해야 한다. 진단 정보는 모델 프롬프트·대화 기억·관객 학습으로 되돌려 보내지 않는다.
