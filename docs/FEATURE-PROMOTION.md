# 신규 기능의 능동적 정식 편입

배포·정식 릴리즈는 [앱 안정성·유지보수 정책](SERVICE-RELEASE-POLICY.md)을 우선 적용한다. 기능 승격 후에도 실제 패키지·데이터 보존·복귀를 검증한다. 콘텐츠 품질 목표의 미달만으로 유지보수 릴리즈를 막지 않는다.

2026-09-15 사용자 지시로 기능별 실사용과 검증 조건을 충족하면 별도 통합 요청을 기다리지 않고 수정, squash 통합, 원격 push, 새 정식 릴리즈까지 수행한다. 과거 PREVIEW-2.md의 별도 사용자 결과 보고/승인 대기 문구보다 이 정책을 우선한다. 시간 경과나 피드백 부재는 통과 근거가 아니다.

Codex heartbeat `nagneon`이 매일 오전 10시(Asia/Seoul)에 이 작업에서 점검한다. 실행은 Codex 자동화 환경 가용성에 의존한다. 앱 자체가 코드를 변경하거나 자동 업데이트하는 기능은 아니다.

## 기능별 승격 조건

로컬 릴리즈 적용은 [고정 설치 절차](STABLE-INSTALLATION.md)를 따른다. 버전별 worktree EXE로 바로가기를 교체하거나 기존 사용자 프로필을 새로 만들지 않는다. `Install-NagneonRelease.ps1 -Register`로 데이터 백업과 패키지 해시 검증을 마친 뒤 고정 진입점을 갱신한다.

1. 버전/코드와 실제 사용한 기능, 기대/실제 결과를 식별할 수 있다.
2. 해당 기능의 알려진 재현 가능한 이슈를 해결하고 재검증했다.
3. 최신 main과 격리 통합한 실제 코드의 `npm run check` 및 관련 런타임/패키지 검증이 통과했다. fixture는 실제 계정·장치·플랫폼 연결을 대신하지 않는다.
4. 승격 기능만 이중 프리뷰 게이트에서 분리한다. 나머지는 두 옵션을 모두 요구하며 프롬프트 자유 편집 같은 디버그 도구는 정식 편입 후에도 디버그 모드가 필요하다. 설정 마이그레이션과 비활성 경로를 검사한다.
5. 코드와 배포 파일 일치, 새 버전, 릴리즈 노트, 이전 버전 복귀 방법을 확인하고 새 정식 릴리즈를 게시한다. 기존 태그/파일을 덮어쓰거나 실행 중 앱을 강제 교체하지 않는다.

사용자가 제공한 결과와 이미 허용되어 수집한 해당 앱 진단만 이용한다. 수집 기간/개인 데이터 범위를 자동 확대하지 않는다. 로그인이나 개발자 설정이 필요한 기능만 보류하고 다른 기능은 계속 진행한다. 비밀·개인 대화 원문은 원격에 게시하지 않는다.

## 최초 진행 원장

초기 프리뷰 대상은 `codex/preview-0.1.0-2`의 `b984eb9`다. 아래 초기 상태보다 후속 점검 기록과 최신 정식 릴리즈를 우선하며, 오래된 프리뷰를 현재 main에 일괄 병합하지 않는다. 사용자의 “확인했습니다”만으로 실사용 합격을 만들지 않는다.

| OBS | 검증 중 | 기존 실제 검증과 현재 버전 일치 및 회귀 |

각 점검에서 대상 SHA, 증거 경로, 이슈/수정/검증 결과, 다음 조치를 추가한다. 상태는 미사용, 검증 중, 이슈 수정 중, 승격 가능, 정식 편입으로 구분한다. 변화가 없으면 알림을 반복하지 않는다. 의미 있는 수정·승격·릴리즈, 실패, 꼭 필요한 사용자 조치만 알린다.

릴리즈 후 [Git 병렬 개발 규칙](PARALLEL-DEVELOPMENT.md)에 따라 사용 종료 worktree와 통합된 로컬/원격 작업 브랜치를 정리한다. 실행본/증거가 들어 있는 worktree는 보존한다.
