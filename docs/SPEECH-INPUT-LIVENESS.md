# 긴 발언 전달과 방송별 취소 처리

구독 음성 연결의 단일 전사 조각은 최대 4,000자다. 이를 수신한 뒤 일반 발언 묶음의 3,000자 제한으로 첫 항목을 꺼내지 못하면, 해당 발언과 뒤에 들어온 모든 발언이 대기 상태에 남는다. 대화 기억의 원문 저장 제한도 3,000자여서 허용된 긴 전사가 기억에 저장되지 않는 문제가 있었다.

## 전달과 보관

- `SpeechInbox.receive()`는 4,000자를 넘는 원문을 메시지 발행·영수증 저장 전에 거부한다.
- 첫 항목이 3,001~4,000자이면 그 발언 하나를 온전히 전달한다. 뒤의 발언은 다음 요청에서 처리한다. 일반 묶음은 합계 3,000자와 최대 4개 제한을 유지한다.
- 원문을 자르거나 조각의 시각을 새로 만들지 않는다. 원문 영수증, 발언 ID, 당시 화면·원음 구간·관객 범위, 정정·복구 경계를 유지한다.
- 대기 항목 40개와 방송별 영수증 20,000개 제한, 동일 발언 재전송의 중복 방지, 같은 ID의 다른 내용 거부를 유지한다.
- 대화 기억의 원문은 최대 4,000자까지 그대로 저장한다. 문맥 교정문은 최대 3,000자이며, 기억 검색의 발췌 예산과 발췌 표시를 유지한다.
- 공개 HTTP 발언 입력의 3,000자 제한은 기존대로다. 구독 음성 입력의 내부 전달 경로가 허용하는 단일 조각을 처리한다.

## 방송 종료와 재시작

새 방송을 시작할 때 기존 `Studio.resetCounters()`가 새 발언함을 만든다. 이미 진행 중인 방송에 `start()`를 다시 호출하면 기존 영수증을 보존한다. 입력의 필수 방송 ID 검사는 이전 방송의 지연 입력을 거부한다.

AI 요청의 오류 처리에서도 방송 세대를 먼저 확인한다. 이전 방송의 `ai_cancelled`·`ai_blocked` 응답이 새 방송의 같은 ID 발언을 처리 완료로 지울 수 없다. 현재 방송의 차단 응답은 기존대로 해당 요청의 입력을 정리한다.

## 저장 호환성과 복귀

대화 기억의 저장 형식은 버전 1을 유지하며, 기존 3,000자 이하 기록·ID·고정 여부·목격 관객은 그대로 읽는다. 기록·잔액을 초기화하지 않는다.

3,001~4,000자 원문을 저장할 때는 대화 기억 인덱스를 확정하기 전에 프로필의 최소 reader를 4로 올린다. 이 표식으로 보호되는 핫클립의 기본 저장 파일도 먼저 준비하므로, 핫클립이 없는 새 프로필이 재시작할 수 있다. reader 3인 이전 앱은 기존 시작 검사를 통해 프로필을 거부하므로, 긴 원문이 유효하지 않다며 예전 인덱스를 자동 복원하지 않는다. 긴 기록을 나중에 삭제해도 호환성 표식을 낮추지 않는다. 짧은 원문만 있는 프로필의 reader 2·3 표식은 유지한다. 표식을 기록하지 못하면 새 인덱스를 확정하지 않으며, 지원 범위를 넘는 표식은 읽기·쓰기 전에 거부한다.

이전 코드의 대화 기억 검사기는 3,001~4,000자 기록을 읽을 수 없다. 실제 업데이트 전 별도 프로필 백업을 보존해야 하며, 이전 버전으로 복귀할 때는 그 버전과 업데이트 전 백업을 함께 복원한다. 새 기록을 잘라 이전 코드에 맞추거나 현재 프로필을 덮어쓰지 않는다. 설치·업데이트 검증은 `STABLE-INSTALLATION.md`와 `SERVICE-RELEASE-POLICY.md`를 따른다.

## 검증

`test/speech-input-liveness.test.js`는 다음을 확인한다.

- 실제 입력 스키마와 전사 조립기를 통과한 3,001자·4,000자 조각의 순서, 마지막 부정 문장, 캡처 보존
- `Studio`의 관객 요청·화면 문맥·채팅·대화 기억에 원문 전달, 이어지는 발언 처리
- 일반 묶음·대기열·영수증 한도와 재전송·방송 재시작 경계
- 이전 방송의 지연 취소로부터 새 발언 보호, 현재 방송 차단의 기존 정리 동작
- 실제 `JournalStore` 저장·재시작 후 긴 원문과 기존 기록 보존, 초과 원문·교정문 거부 시 이전 저장 상태 보존
- 호환성 표식 기록 실패·미지원 reader의 인덱스 변경 방지, 긴 기록 삭제 후 최소 reader 보존
- 핫클립 기본 파일이 없는 새 서비스의 긴 원문 저장·종료·재시작

집중 검사:

```powershell
node --test test/speech-input-liveness.test.js test/subscription-voice-inbox.test.js test/speech-content.test.js test/speech-publication.test.js test/speech-flow.test.js test/speech-screen.test.js test/speech-retention.test.js test/journal-store.test.js test/conversation-journal.test.js test/profile-capabilities.test.js
```

이 검사는 합성 발언·관객 응답을 사용한다. 실제 계정의 음성 인식 정확도, 물리 마이크·게임 소리 또는 설치본의 동작을 입증하지 않는다. 정식 배포 전에는 최신 통합 코드의 `npm run check`와 관련 실제 실행·설치·데이터 보존 검증을 별도로 수행한다.
