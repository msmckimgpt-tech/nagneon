# 추가 구성의 설치 상태 확인

경량 구성형 배포는 공통 음성 처리, 시스템 소리 인식, 한국어 마이크 인식, GPU 가속을 앱과 별도로 설치한다. `설정 > 연결·사용량 > 추가 구성`에서 설치 상태를 확인할 수 있다.

## 재실행과 업데이트

앱을 시작하면 `RuntimeComponents.inspectInstalled()`가 기존 설치를 비동기로 확인한다. 설치 확인 때문에 서버 시작이나 텍스트·화면 대화를 기다리게 하지 않는다. 별도의 다운로드, 압축 해제, 캐시 삭제, 음성 작업자 또는 마이크·GPU 실행은 발생하지 않는다.

기본 캐시는 `%LOCALAPPDATA%\Nagneon\runtime`이며, 별도 프로필을 지정하면 해당 프로필의 `runtime`을 사용한다. 구성은 `installed/<구성 ID>-<contentId 앞 32자리>`에 위치한다. 앱 버전이나 실행 파일 폴더가 달라져도 카탈로그의 구성 내용과 캐시 경로가 같으면 재사용한다. 이미 존재한다는 이유나 이전 실행의 완료 표시만으로 준비 완료를 판정하지 않는다. 현재 카탈로그의 파일 목록, 크기, SHA-256과 링크 경로 검증을 그대로 적용한다.

| 상태 | 표시와 동작 |
| --- | --- |
| 검증 중 | `설치 확인 중`. 다운로드 크기를 확정한 것처럼 안내하거나 재설치 버튼을 활성화하지 않는다. |
| 전체 파일 정상 | `준비됨`. 해당 기능에 필요한 구성이 모두 정상이면 준비 버튼도 `준비됨`으로 표시하고 비활성화한다. |
| 현재 contentId의 설치 폴더 없음 | `필요 시 설치`. 다른 contentId의 과거 설치를 임의로 재사용하거나 삭제하지 않는다. |
| 설치 폴더의 파일 누락·손상 | 문제를 표시한다. 자동 복구하지 않으며 사용자가 해당 기능을 준비하면 기존 검증·원자적 복구 절차를 사용한다. |
| 경로 링크·접근 실패 | 준비 완료로 간주하지 않는다. 오류에 로컬 경로나 다운로드 URL을 노출하지 않는다. |

정상적인 시작 시 확인만으로 방송실에 설치 진행 안내나 설치 취소 버튼을 표시하지 않는다. 설정에서는 확인 과정을 볼 수 있다. 한 구성의 실패가 다른 정상 구성의 확인을 막지 않는다. GPU 구성도 이미 설치되어 있으면 확인하지만, CPU 모드에서 GPU 구성을 자동 설치하지 않는다.

## 동시 요청과 종료

설치 확인과 명시적인 준비가 겹치면 동일 구성의 검증을 공유한다. 정상 구성은 추가 다운로드 없이 사용한다. 확인 후 설치가 필요하더라도 취소된 요청이 뒤늦게 다운로드를 시작하지 않도록 요청 수명을 유지한다.

설치 취소는 명시적인 준비와 다운로드를 취소하며, 앱 시작의 읽기 전용 확인은 유지한다. 조회가 기존 다운로드에 합류한 경우에는 조회 자체를 다운로드 소비자로 계산하지 않는다. 마지막 실제 소비자가 취소하면 다운로드가 종료된다. 앱 종료는 확인과 준비 모두 취소하고 정리가 끝날 때까지 기다린다.

서버 상태의 `runtimeComponents.preparing`은 명시적인 준비가 진행 중인지 나타낸다. 구성별 `checking`과 구분하여 UI에서 단순 확인을 설치 작업으로 오인하지 않도록 한다.

## 회귀 검증

```sh
npm ci
npm run check
npm audit --audit-level=high
node --test test/runtime-component-readiness.test.js test/runtime-components.test.js test/runtime-pack.test.js test/runtime-download.test.js
node node_modules/electron/cli.js scripts/verify-runtime-readiness-ui.cjs
node node_modules/electron/cli.js scripts/verify-runtime-components-ui.cjs
```

준비 상태 회귀는 작은 합성 구성과 실제 파일 검증을 사용한다. 재실행, 다른 앱 리소스 폴더, 오프라인, 빈 캐시, 부분 설치, 내용 변경, 동일 크기 손상, 접근 실패, 링크 경로, 동시 준비, 취소, 종료와 인증된 HTTP 상태를 검사한다.

Electron 검증은 `artifacts/runtime-readiness-ui`의 독립 프로필과 합성 캐시에서 첫 실행 및 재실행의 설정 화면, 확인 중 표시, 준비 완료 버튼, 설치 요청 0회와 420px 화면 폭을 검사한다. 결과와 캡처는 같은 디렉터리에 남긴다. 이 검증은 사용자의 설치본을 교체하거나 실제 음성 인식·GPU 성능을 측정하지 않는다.
