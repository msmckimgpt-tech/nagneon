# 관객 자율성과 자연스러운 방송 진행

2026-09-13 사용자 변경 요청을 코드에 반영했다. 기존 화면 선택창 검증은 `docs/CAPTURE-PICKER.md`, 이번 변경의 실제 범위와 검증은 아래와 같다. 실행 중이던 사용자 앱/프로필을 강제로 재시작하거나 초기화하지 않았다.

## 구현된 동작

- 서버가 관객 명단을 소유한다. 신규 프로필에는 관객 후보가 없으며 기본 방송 도우미만 존재한다. 도우미는 관객 수에서 제외된다. 이전에 만난 관객의 ID와 기록은 유지하고, 이전 버전에서 만들었지만 만나지 않았던 후보는 보관 영역으로 옮겨 앞으로 입장시키지 않는다.
- 실제 AI 방송 중 첫 만남 50P로 한 명을 만난다. 첫 체험 60P로 시작할 수 있다. 이름/내적 성향은 유입 시 실제 Astra low 요청으로 구성한다. 클라이언트는 이름·성향·유입 경로를 지정할 수 없다. 총 명단 상한은 기본 도우미 포함 40명이다.
- 누적 실제 방송 10분 이후 분당 3% 자연 유입 기회를 확인한다. 실제 관객 클립은 생성 후 1분부터 7일간 분당 8% 발견 기회를 갖는다. 한 클립의 성공 유입은 1명, 유입 사이 최소 5분이다. 앱 휴면 시간을 방송 시간으로 한꺼번에 적립하거나 밀린 입장을 몰아서 처리하지 않는다. 이 수치는 조사된 실제 전환율이 아니라 현재의 시뮬레이션 조정값이다.
- 생성 중 포인트 보관, 완료 시 관객·지갑·영수증 확정, 실패·방송 종료 시 반환을 `world.json` 한 저장 단위로 처리한다. 같은 요청 ID는 재시작 후에도 중복 생성하지 않는다. 미확정 보관 금액은 재시작 때 반환한다. 기존 settings/audience/economy 파일은 최초 이전 입력으로만 읽고 덮어쓰지 않는다.
- 내적 성향·유입 경로·친밀도·개인 기억/관계는 공개 설정/API/SSE/내보내기의 기본 관객 카드에서 제외한다. 관객 수첩 30P, 관계 지도 25P로 각각 해금한다. 해금 권한은 구매 내역을 정리해도 남는다. PC 소유자가 로컬 원본을 직접 읽는 것을 막는 DRM은 아니다.
- 관객은 자기 시청 중 나온 발언을 근거로 취향을 조금씩 바꿀 수 있다. 최소 시청 5분, 변화 간격 10분, 닉네임 변경 간격 24시간, 사교성 변화 한 번에 ±0.05로 제한한다. ID는 바꾸지 않고 이름 이력과 스트리머 메모를 유지한다. 메모는 관객 모델 입력에서 제외한다. 제거한 관객의 옛 채팅·지갑·메모·클립 저자 기록은 삭제하지 않는다.
- 핫클립의 새 생성자는 관객이다. 조용한 잡담, 웃긴 실패, 취향이 통하는 말 등 개인적 선택을 후원 판정과 분리한다. 방송실·핫클립·기획/시즌의 수동 생성 버튼/API는 닫았다. 기존 클립은 그대로 볼 수 있다. 관객별 5분, 전체 1분 간격으로 도배를 막고 실제 목격자만 선택할 수 있다.
- 미디어·기록 탭에서 관객의 장면 기록을 허용해야 새 클립이 저장된다. 영상 버퍼도 허용했고 선택 시점이 현재 메모리 버퍼에 남아 있을 때만 영상과 공유된 출력 소리/켜진 마이크를 붙인다. 과거 장면 대신 늦게 찍힌 다른 영상을 붙이지 않는다. 화면/소리/마이크 공유를 자동으로 켜지 않는다.
- 방송 놀이터는 일반 채팅의 축하·라디오·취향·즉흥 놀이·도전·회상 흐름으로 연결한다. 별도 무대 생성/단계 전환 UI와 새 기획/시즌 시작 API는 닫고, 예전 기록과 별도의 대응 연습은 보존했다. 말로 거절하거나 쉬자고 하면 흐름을 중단한다. 현재는 주제 단서와 제한된 대화 문맥을 사용하는 첫 자연 진행 구현이며 장기적인 사건/관계 시뮬레이션 전체를 완성했다는 뜻은 아니다.
- 설정은 방송 / 분위기·훈수 / 연결·사용량 / 매니저·채팅 / 미디어·기록 / 게임의 6개 탭이다. 초안 유지, 저장 실패 안내, 키보드 방향키/Home/End, Tab/Shift+Tab/Escape, 작은 창과 200% 확대를 지원한다.

## 확정된 방향

- 스트리머는 관객을 직접 만들거나 아직 만나지 않은 관객을 사전 설정할 수 없다. 제거는 가능하다.
- 장시간 방송의 낮은 확률 유입, 핫클립을 통한 유입, 포인트를 사용한 한 명씩의 유입만 허용한다. 유입 시점에 백그라운드에서 새 관객을 구성한다. 유입 경로가 초기 취향과 말투에 영향을 준다.
- 관객의 취향과 성격은 대화 경험으로 변화할 수 있고, 닉네임도 스스로 바꿀 수 있다. 내부 관객 ID는 유지하며 스트리머의 메모, 관계, 기억, 지갑, 핫클립 작성자 기록을 같은 사람에게 연결한다.
- 관객의 내적 성향은 기본 비공개이며 포인트 보상으로 해금한다. UI를 숨기는 것만으로 완료하지 않고 공개 API/SSE/내보내기에서 해금 전 내부 성향이 노출되는 경로도 검토한다.
- 핫클립의 생성 주체는 관객이다. 각 관객이 개인적으로 좋아한 장면을 선택한다. 스트리머의 수동 생성 동작을 제거하고 기존 클립/기록은 보존한다.
- 방송 놀이터의 대부분은 일반 방송 중 자연스럽게 제안되거나 일어나는 상황으로 통합한다. 별도 모드 선택이나 장면 진행 버튼을 필수 경로로 두지 않는다. 연습용 도구를 남길 경우 자연 발생 상황과 명확히 구분한다.
- 방송 설정은 구간별 탭으로 나눈다. 키보드 이동, 현재 탭 안내, 수정 초안 보존, 저장 오류, 작은 화면과 확대에서도 검증한다.

## 구현 시 지킬 기준

- 기존 관객과 기록을 초기화하지 않는다. 새 정책으로의 마이그레이션은 다시 실행해도 중복 생성·중복 차감되지 않아야 한다.
- 유입/포인트 해금/관객 생성의 실패·취소·재시작에서 유령 관객이나 포인트 손실이 없어야 한다. 포인트 유입도 미리 만들어 둔 캐릭터 선택권을 주지 않는다.
- 새 이름과 취향은 장면·대화 경험에 근거하며 갑자기 전혀 다른 인격으로 덮어쓰지 않는다. 실제 사람의 성향이나 실제 커뮤니티 가입 이력을 추론하는 기능이 아니다.
- 포인트로 정보가 해금되어도 그것은 관객의 가상 성향 설명이다. AI 모델의 비공개 사고 과정을 공개한다고 표현하지 않는다.
- 소리/마이크/화면 캡처는 기존의 명시적 사용자 선택을 유지한다. 관객이 클립을 원해도 미공유 화면이나 사용자가 끈 녹화를 자동으로 켜지 않는다. 저장 가능한 당시 장면·대화·허용된 버퍼로 구성한다.
- 자동 상황은 스트리머의 현재 말, 거절, 휴식 요청을 우선한다. 기존 방송 호출 예산·음성 우선순위·스포일러·매니저 규칙을 지키며 매번 사건을 강요하지 않는다.

기존 persona 설정/API와 spectator 생성 책임, 최초 방송의 첫 만남, 시간 기반 유입 확률과 실제 시청 시간, 클립 관심도와 유입 연계, 포인트 가격/재충전/환불, 비공개 성향 스키마와 해금 범위, 대화 기반 변화의 근거/주기, 닉네임 이력과 스트리머 메모, 관객별 클립 선택/중복 합치기, 자연 발생 상황의 쿨다운/거절/기억/후속 대화, 저장 마이그레이션과 실제 장기 수용 시험을 코드와 함께 정한다.

검토 권고 중 다음은 그대로 채택하지 않는다.

- 별도 파일의 관객 저장을 `economy.change` 안에서 호출하는 것만으로 원자성이 생기지 않는다. 관객 생성/유입 영수증/포인트 정산은 하나의 권위 있는 저장 단위로 커밋하거나 검증된 복구 트랜잭션을 사용해야 한다. 저장 실패·프로세스 중단 양쪽 순서를 실제로 검사한다.
- 사용자가 특정 유입 관객의 분위기를 미리 고르는 메뉴는 만들지 않는다. 기존 방송 성향과 실제 유입 경로를 조건으로 현장에서 생성한다.
- 보장된 자동 첫 관객은 세 유입 경로 제한을 느슨하게 만들 수 있다. 첫 체험 포인트로 한 명을 만날 수 있게 안내하는 방향을 우선하며, 이름/성향은 결제 전에 정해 보여주지 않는다. 기본값의 미리 만든 관객을 새 사용자에게 숨겨 둔 풀로 사용하지 않는다.
- 관객이 좋아할 장면은 강한 긍정적 후원 사건에 한정되지 않는다. 조용한 취향 대화, 웃긴 실수, 긴장감, 자기 관심사 등 개인적 이유로 클립을 고를 수 있다. 포인트 후원 판정과 클립 선호 판정은 구분한다.
- 관객 제거 시 과거 기록을 일괄 삭제하지 않는다. ID의 은퇴 표시와 이름 이력으로 옛 채팅/클립/지갑/메모를 연결하고 재사용을 막는다.
- 별도 기획 모드를 단지 자동으로 열거나 승인 버튼을 늘리는 것으로 자연스러운 상황 전환을 대체하지 않는다. 일반 방송의 대화/관객 반응과 거절·휴식에 따라 상황이 이어져야 한다.

구현 순서는 관객의 서버 소유 데이터/공개 투영/기존 기록 마이그레이션 → 유입과 포인트 원자 정산 → 대화 기반 변화와 닉네임·메모/해금 → 관객별 클립과 미디어 동의 → 자연 발생 상황의 대화 진행이다. 설정 탭은 이 책임 분리에 맞춰 방송·연결·채팅 규칙·미디어/기록 등으로 정리한다. 출처 검토의 추측이나 권고를 사용자 확정 조건으로 바꾸지 않는다.
