# 갱신되는 사진에서 연속 장면으로

2026-09-13. 사용자 보고: 관객이 영상을 함께 보는 대신 새 사진이 올 때마다 확인하는 느낌이다. 작업 기준은 main `3a4f9a0c8f6aa65105706c4f0601d6a3ad9feecd`, 개발 위치는 `G:/dev/ai/00_game_backseat-worktrees/temporal-viewing`, 브랜치는 `codex/temporal-viewing`이다. 클립 유입 기억 작업은 제품 수정 전에 보류하고 이 요청을 우선했다.

## 원인과 지원 범위

이전 `useMedia`는 관객 요청 직전에만 canvas 한 장을 만들었다. 요청 중에는 다음 화면을 수집하지 않았다. 따라서 시작과 끝이 같은 점프, 왕복, 잠깐의 실패·위험이 사라졌고 서버의 단일 이미지 해시로는 중간 변화를 알 수 없었다. 이전 장면 요약과 소리만으로 빠진 움직임을 복원할 수 없다.

[공식 Astra 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-astra)는 이미지 입력을 지원하고 영상·음성 직접 입력은 지원하지 않는다고 명시한다. 현재 설치된 공식 Codex CLI 0.154.0의 `exec --help`에서 `--image <FILE>...`를 확인했고, 실제 `gpt-6-astra` / `low` 호출에서 여러 이미지를 시간순으로 받는 것을 검증했다. ChatGPT 구독 로그인과 모델은 유지한다. auth.json·토큰을 읽지 않았고 API 키 과금 경로로 바꾸지 않았다.

## 구현

- 화면 수집과 AI 응답을 분리했다. 선택한 화면의 독립 video에서 500ms마다 수집하며 AI가 응답하는 동안에도 계속한다. 새 장치나 화면을 자동 선택하지 않는다. 방송·화면 연결·카테고리 변경, 종료와 컴포넌트 해제 때 버퍼를 비운다. 미리보기 탭이 사라져도 독립 수집은 유지한다.
- 메모리 버퍼는 최대 16초·33개·6,400,000 데이터 URL 문자다. 이미지의 긴 변은 최대 960px이고 JPEG 압축 후 320,000문자를 넘으면 품질·크기를 한 번 더 낮춘다. 이 제한은 전체 프로세스 RAM 상한이 아니다. 실제 FPS/CPU/GPU 비용은 장치 검증이 필요하다.
- 한 호출에 최대 8장만 고른다. 처음·최신 장면, 픽셀 변화가 큰 구간의 전후, 남은 시간 간격을 채우는 장면을 시간순으로 전달한다. 픽셀 변화는 중요 사건의 판정이나 광학 흐름 추정이 아니다. 같은 픽셀 구간은 경계 이미지와 동일 표본 수·시각으로 줄여 정지 관찰을 잃지 않는다.
- 승인된 마지막 시각을 다음 묶음의 연결 지점으로 유지한다. 실패·취소·불확실한 음성 교정은 그 묶음을 처리했다고 표시하지 않는다. 최대 창을 넘긴 간격은 모델에 누락 시간으로 알린다. 프레임 순서·범위·용량·세션·미래 시각을 검증하고 오래되거나 순서가 뒤집힌 요청은 사용하지 않는다. 기존 3MiB HTTP 본문 제한 안에서 처리한다.
- 서버는 모든 현재 목격자의 입장 이후 화면만 공통으로 전달한다. 늦은 입장 때 앞부분을 실제로 제거하며, 한 모델 호출 안에서 이미지를 숨기라는 지시만 믿지 않는다. 이 때문에 신규 입장 직후 기존 관객도 잠깐 더 짧은 구간을 받는다.
- 모델에는 이미지 번호, 실제 시각, 간격, 이전에 처리한 부분과 마지막 상태를 제공한다. 기존 시스템 소리와 마이크 발언의 수집 시각도 같은 요청에 유지한다. 이동·시도·결과를 연결하되 보이지 않은 버튼 입력·원인·소리를 만들지 않게 한다. 기존 위험이 마지막 장면에 없으면 늦은 회피 훈수를 하지 않도록 지시한다.
- 시작/끝 이미지가 같아도 중간 변화가 있으면 새로운 입력으로 인정한다. 이미 처리한 중첩 구간이나 정지 화면은 재반응하지 않는다. 중간에 움직였는데 '같은 이미지가 계속 유지됨'이라고 표시하던 모순도 제거했다.
- 새 연속 화면의 화면 전용 반응은 최신 표본 후 20초를 넘으면 채팅·후원·클립·기억에 반영하지 않는다. 대기 채팅도 같은 만료를 따른다. 명시적 발언·기획 답변에는 기존 대화 정책을 유지한다. `/api/viewing-end`는 해당 세션·화면 연결의 처리와 대기 채팅만 취소하며, 아직 답하지 못한 발언은 보존한다. 사용자 앱을 재시작하지 않는다.
- 설정 이름을 'AI 반응 최소 간격'으로 바꾸고 수집 주기와 응답 주기를 구분해 설명했다. 반복 대기 요청마다 큰 이미지를 재전송하지 않도록 다음 요청 시각을 제한하되 새 발언은 우선한다.

## 검증과 증거

모든 원본은 개발 worktree의 `artifacts/` 아래 보존한다. 테스트는 사용자 장치·게임·앱·수집 데이터에 접근하지 않는다. 합성 PNG, 순수 수집기/타이머 대역, 격리된 Node HTTP 서버와 공식 CLI만 사용한다.

- `test/temporal-viewing.test.js`: 수집 중 응답 대기, 짧은 중간 변화, 정지 표본 압축, 메모리 상한, 디코더 정지, 수집 종료, 입장 시각, 요청 용량/순서, A-B-A 변화, 음성/소리 시각, 지연 폐기, 소스 취소·발언 재시도, 다중 첨부 파일 순서와 삭제, HTTP 실제 경로를 검사한다.
- 필수 `npm run check`는 전체 Node 테스트와 TypeScript/Vite 빌드를 포함한다. 최종 로그는 `artifacts/check-verified.log`다.
- `scripts/verify-temporal-viewing.mjs`: 동일한 마지막 화면을 가진 합성 점프·좌/우 이동, 정지, 발언 없는 장면을 실제 Astra에 보낸다. '단일 마지막 장면'도 같은 최종 모델 지시를 사용하므로 입력 방식의 비교이며 구버전 전체 앱 성능 비교는 아니다. 각 결과에 입력 시간표·이미지 해시·응답·토큰·벽시계 시간·제품 소스 해시를 남긴다.
- 초기 HTTP 테스트 401은 시험용 로컬 접근 헤더 누락이었다. 테스트에 자체 서버 접근 값을 넣어 수정했고 제품 인증은 변경하지 않았다. 최초 모델 실행의 매니저 ID 누락도 합성 설정 오류였으며 모델 호출 전에 실패했다. 실패 로그와 `temporal-astra-5BCnH6`를 보존한다.
- 중간 실제 모델 결과 `temporal-astra-kl3ZBm` 5회, `temporal-astra-9BpBdr` 6회를 보존한다. 정지 프레임 압축 뒤 두 장만 보냈다는 이유로 중간 관찰이 사라지던 표현을 보고 동일 표본 수·시각을 추가했다. 이 중간 결과를 최종 코드 증거로 사용하지 않는다.

## 남는 범위

영상 직접 입력이나 모든 프레임을 보는 시스템은 아니다. 500ms보다 짧은 동작, 선택되지 않은 장면, 긴 응답/관찰 간격, 작은 HUD 글자, 카메라 이동·편집·가림은 여전히 놓치거나 오해할 수 있다. 의미 기반 핵심 장면 선택, 더 긴 문맥을 위한 별도 인식 계층, 실제 게임 FPS/지연과 장기 채팅 자연스러움은 추가 검증 대상이다. 모델을 바꾸거나 추가 과금 서비스를 도입한 것으로 간주하지 않는다.

네이티브 Electron·Steam 게임·화면/마이크/출력 장치·사용자 앱 재실행 검증은 수행하지 않았다. Computer Use 중단 지침은 그대로다. main 코드 통합과 사용자가 이미 켜 둔 실행본에 반영되는 것은 다르며, 새 패키지/실행본 교체를 했다고 보고하지 않는다. Steam 판매 준비 목표는 미완료 상태다.
