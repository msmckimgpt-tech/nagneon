# 화면 없는 방송의 음성 핫클립

2026-09-13, `codex/audio-hotclips`, 기준 `28d358c0bd393697b5474a7173612f46cb4ac6cd`.
[지연된 클립 복구](CLIP-BUFFER-RECOVERY.md)에 이어 Just Chatting의 음성 기록과 녹음 시각을 연결했다. 화면·장치 조회/조작, 게임 실행, 사용자 앱 재시작은 하지 않았다.

## 실제 동작

기존 **방송 중 영상·음성 클립 버퍼 사용** 설정이 켜져 있을 때 작동한다. 기본값은 계속 꺼짐이다. 화면을 명시적으로 공유하면 영상 클립, 마이크나 출력 소리만 연결하면 Opus WebM 음성 클립을 보관한다. 별도 방송 모드나 수동 클립 생성 버튼은 없다. 관객의 장면 기록 허용 설정도 켜져 있어야 클립을 남긴다.

- 음성만 공유한 display stream에 영상 트랙이 들어 있어도 그 트랙을 조회하거나 복제하지 않는다. 마이크만 켜져 있어도 동작하며, 입력이 없거나 코덱을 지원하지 않으면 버퍼를 시작하지 않는다.
- 마이크와 시스템 출력은 한 음성 트랙으로 섞는다. 스피커 재생에 연결하지 않고, 같은 입력 트랙이 중복 전달되면 한 번만 사용한다. 실패·중단 때 자신이 만든 복제본·출력 트랙·AudioContext만 정리한다.
- 기존 15초 단위 녹화, 완료 후 120초/10구간/24MiB 보관, 활성 구간 20MiB 한도, 직렬 전송과 유한 재시도를 재사용한다. 설정·소스·방송 세션 변경 때 임시 자료를 비운다. 이미 저장된 클립은 사용자가 핫클립에서 삭제할 수 있다.
- `audio`와 `video` 상태를 구분하고 둘을 한 클립에 동시에 연결하지 않는다. 음성은 `/api/clips/:id/audio`로 저장하며 `/api/clips/:id/media/audio`가 `audio/webm`과 범위 요청을 제공한다. 기존 영상 경로·메타데이터는 유지한다. 저장 실패 때 파일/메타데이터를 되돌리고 음성 파일도 삭제·공간 계산에 포함한다.
- 핫클립 목록의 **음성** 표시와 접근성 이름이 있는 audio 플레이어를 추가했다. 자동 재생하지 않으며 다른 클립을 선택하면 플레이어를 새로 만든다. 댓글·대댓글, 방송 날짜·게임·관객 분류, 재시작 후 조회는 동일하게 적용한다.

## 인식 완료 시각과 실제 발언 시각

ASR가 늦게 끝난 뒤의 침묵을 녹음한 말로 저장하면 안 된다. `VoiceBoundary`가 실제 발성 시작/끝의 샘플 시각을 기록하고, 큐/발언 전송이 `capture.startedAt/endedAt`을 함께 운반한다. 원문 전사나 서버 공개 메시지의 수신 시각을 바꾸지는 않는다.

서버는 방송 범위와 15초 이하 길이, 미래 시각, microphone 출처를 검증한다. 발언 ID의 재전송 확인에 녹음 범위도 포함하고, 같은 ID로 범위를 바꾸는 요청을 거부한다. 발언 처리 시점에 현재 관객 중 녹음 시작 이전부터 입장해 있던 관객을 `hearers`로 기록한다. 이 자료는 발언 처리 큐의 임시 정보이며 새 사용자 원음 저장소가 아니다.

모델에 현재 처리할 발언의 `liveSpeech.messageId`와 녹음 범위/청취자, 관객별 `heardSounds`를 전달한다. `clipPicks`는 다음 중 하나를 선택한다.

- **speechId**: 이번 발언 묶음 중 실제 선택한 메시지. 녹음 범위가 있으면 그 구간의 중앙을 클립 기준 시각으로 삼는다. 여러 늦은 발언 중 마지막 말을 무조건 대신 쓰지 않는다. 늦게 들어온 관객은 입장 전 녹음을 선택할 수 없다.
- **soundId**: 그 관객에게 실제 제공된 최근 시스템 출력 소리. 다른 관객만 들은 소리, 무음, 만료·미래 구간, 제공되지 않은 ID는 거부한다. 선택한 소리 구간의 중앙 시각을 사용한다.
- **빈 ID**: 화면 또는 ID가 없는 기존 직접 발언 방식의 장면 기록. 실제 녹음의 근거가 없는 키보드/기존 발언 기록에는 관계없는 현재 마이크 음성을 자동 연결하지 않는다.

두 ID를 동시에 지정할 수 없다. 모델이 녹음 시각을 만들어 넣는 구조도 아니다. 늦은 음성이 근거인 클립에는 현재의 다른 화면을 썸네일로 붙이지 않고, 해당 발언 원문은 수신이 늦었어도 그 클립의 대화 기록에 연결한다. 모델 응답 대기 중 발언을 삭제하면 그 ID는 클립 근거에서 제거한다.

소리 추정은 계속 로컬 인식 결과다. 음악 제목/화면 밖 상황을 검증한 사실처럼 확정하지 않는다. [W3C MediaStream Recording 초안](https://w3c.github.io/mediacapture-record/#data-handling)의 완료 녹화 단위를 사용하며, 서로 다른 녹화의 WebM 청크를 임의로 이어 붙이지 않는다.

## 검증과 증거

- 자체 `npm ci`, 최종 **351개 Node 검사 + TypeScript/Vite 빌드 통과**. 새 검사 28개는 소스/복제본 소유권, 음성·영상 구분, 믹서 정리, 실제 React SSR 플레이어, 메타데이터/기존 기록 호환, 재시도, 발성 시간/전송, source ID·청취자, 삭제된 발언을 다룬다. `artifacts/audio-check-final.log`.
- `test/clip-speech-timing.test.js`: 실제 로컬 speech HTTP 입력과 Studio를 사용했다. 가상 시계에서 녹음은 5~9초에 끝나고 40초에 전사가 전달됐으며 provider가 추가 45초 뒤 답했다. 클립은 85초가 아니라 **발성 구간 중앙인 7초**를 가리켰다. 첫 시험은 Studio와 Clips의 시험 시계를 다르게 설정해 생성 시각 기대값이 실패했고, 양쪽의 가상 시계를 맞춘 뒤 통과했다. 이는 실제 장치 지연 측정이 아니다.
- `scripts/verify-clip-transfer.mjs artifacts/audio-synthetic.webm artifacts/audio-workflow-complete audio`: 합성 WebM을 실제 로컬 speech HTTP → Studio/관객 선택(provider 대역) → 지연 버퍼 → 업로드 → 디스크 → HTTP 조회로 연결했다. 선택한 발언은 100초 전 구간이며, 뒤의 6개 구간은 다른 바이트다. 서버 저장 성공 응답을 의도적으로 유실시켰을 때 **POST 1회 + GET 1회**로 복구됐다.
- 음성 MIME, HTTP 206 범위 조회, 원본과 내려받은 파일의 SHA-256 일치, 댓글·대댓글 저장, 별도 시험 서버 재시작 후 재조회, HTTP 삭제 후 음성 파일 제거를 통과했다. 버퍼 허용 해제/장면 기록 해제/다른 방송/다른 시각/녹음 근거 없음은 실제 HTTP에서 각각 409로 거절됐다.
- 최종 파일은 **160,384바이트**, SHA-256 `17e5991a5094a2bf782a21552ec9728ab91be624db65e9974dd8c73f7855dd65`. 내려받은 `audio-workflow-complete/retrieved.webm`을 PyAV로 다시 읽어 **영상 트랙 0, 음성 트랙 1, 15.0초, 합성 440Hz·880Hz**를 확인했다. `artifacts/audio-workflow-decode.json`.
- 같은 전송 검증기를 기존 영상에도 실행해 원본 영상 해시, video MIME, 저장/범위 조회/재시작을 확인했다. `artifacts/video-transfer-regression.log`.
- 공식 Codex CLI의 **gpt-6-astra / low 실호출 총 6회**. 최초 3회에서는 소리만 받은 모모가 그 소리 ID로 클립을 골랐다. 발언 ID를 추가한 최종 계약의 3회에서는 모모가 정확한 speechId로 43초 전 녹음 중앙을 골랐고, 무입력에서는 채팅·클립 모두 없었다. 최신 소리 사례에서는 클립을 고르지 않았으며 이는 허용되는 관객 선택이다. `artifacts/audio-model-1789286893842/`, `artifacts/audio-model-1789287475012/`. 모든 입력/응답을 보존했다. 입력은 합성 텍스트·로컬 소리 추정값이며 실제 사용자 자료나 원음은 보내지 않았다.

## 한계와 다음 수용 검사

브라우저 MediaRecorder와 장치의 실제 인코딩, Windows 마이크·loopback 전환, 실제 React 렌더러의 장시간 사용은 아직 검증하지 않았다. 현재 테스트는 주입한 캡처 이벤트와 실제 파일/HTTP/React SSR/모델 호출을 구분한다. 음성 구간은 15초 단위라 발언 전체가 구간 경계를 넘으면 일부만 담길 수 있다. 서버의 기존 WebM 크기/헤더 검사는 완전한 미디어 디코더 검사가 아니다.

이전 클라이언트의 녹음 시각 없는 전사나 키보드 입력은 계속 전달되지만 음성 핫클립 근거로 승격하지 않는다. 댓글 AI는 계속 클립 설명과 채팅을 읽으며, 파일 음성을 새로 청취했다고 표시하지 않는다. 새로운 설정을 강제로 켜거나 사용자 자료를 변경하지 않았다. 실행 중 사용자 앱과 기존 배포 폴더는 그대로이며, 변경본의 실제 앱 적용·장치 검증은 후속 단계다. Computer Use 중단은 시간이 지나도 자동 해제하지 않는다. Steam 판매 준비 완료를 뜻하지 않는다.
