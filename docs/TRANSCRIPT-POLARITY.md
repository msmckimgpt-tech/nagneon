# 음성 교정의 부정 의미 보존

맥락 교정은 원래 전사에 붙이는 주석이며 원문을 덮어쓰지 않는다. 가까운 발음이라는 이유만으로 말한 의도를 뒤집는 제안은 받아들이지 않는다.

- `안 갈래요` → `난 갈래요`, `오늘 안 갈게요` → `오늘 다 갈게요`는 부정 표현이 사라지므로 거절한다. 반대로 부정을 추가하는 제안도 거절한다.
- `안 갈래요` ↔ `안갈래요`처럼 부정을 유지하는 띄어쓰기 교정은 허용할 수 있다. 기존 신뢰도·숫자·말투·훈수 의도·물음표·음운 거리 검사도 모두 통과해야 한다.
- 영어의 `can't`, `didn't`, `isn't`, `shouldn't` 등 부정 축약형을 보존한다. `can’t` → `can't`처럼 따옴표 표기만 바꾸는 교정은 같은 부정 표현으로 검사한다.
- 거절한 교정을 전제로 생성된 채팅은 게시하지 않는다. 원문은 기록에 남으며 잘못된 교정 주석을 저장하지 않는다. 별도 교정 모델이나 자동 재시도 호출을 추가하지 않는다.

훈수 판단도 영문 단어 안의 따옴표 표기를 통일한다. `Don’t give me a hint`, 도움 주기 동사를 직접 부정한 `You shouldn’t give me a hint`, `Can you not give me a hint?`는 거절로 처리한다. 거절하면 이전의 미전달 힌트와 진행 중 힌트 요청을 취소하며, 종속 조언과 공략 검색을 허용하지 않는다. `I can’t solve this game, can you help me?`나 `Why not give me a hint?` 같은 실제 요청은 유지한다. 따옴표로 인용한 남의 요청이나 거절은 스트리머의 권한으로 사용하지 않는다.

`test/transcript-polarity.test.js`는 양방향 부정 변경 차단, 정상 띄어쓰기·따옴표 교정, 실제 Studio 처리와 저널 저장 후 재로드를 검사한다. 위험한 교정에 따른 채팅이 대기열에 들어가지 않고, 다음의 안전한 교정은 처리되며 원문과 주석이 구분돼 저장되는지 확인한다. 훈수 거절 뒤 실제 검색 허용이 닫히고 늦은 힌트가 무시되며, 새로운 요청으로 다시 열 수 있는지도 검사한다. 기존 교정 설정·키보드 입력 제외·저장 실패·늦은 응답·관객별 회상 검사는 `test/transcript-correction.test.js`와 관련 음성 검사에서 유지한다.

검증 입력과 제공처는 합성이다. 물리 마이크의 한국어 인식 정확도, 모든 문장의 의미 판별, 감정·억양 인식이나 게임 중 자연스러움을 입증하지 않는다. 맥락 교정의 보수적인 수용 검사이며 실제로 무엇을 말했는지 확정하는 기능은 아니다.
