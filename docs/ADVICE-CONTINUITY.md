# 한 가지 힌트와 대화 연속성

2026-09-14. [실제 게임 검증](LIVE-GAME-ACCEPTANCE.md)에서 “힌트 딱 하나만”에 답한 뒤, 새 발언 없이 같은 관객의 다른 훈수가 이어졌다. 두 문장의 숫자와 표현이 달라 일반 채팅 중복 검사는 막지 않았다. 이전 구현은 요청 여부만 전달했고 요청당 힌트 수, 응답 재시도의 전달 상태를 따로 관리하지 않았다. 당시 모델 호출 원문은 보존되지 않았으므로 두 번째 문장의 생성 경로를 특정한 재현이라고 주장하지 않는다.

## 변경

- 일반 라이브에 현재 발언의 `advicePolicy`를 전달한다. 요청 시에만 훈수하는 설정에서는 지난 채팅의 요청이나 새 화면 표본이 허락을 갱신하지 않는다.
- “하나만 / 한 가지만 / 딱 하나”는 전체 관객을 통틀어 한 가지 힌트, 한 채팅으로 제한한다. 항상 훈수 설정에서도 명시적인 한 가지 요청·거절은 이후 새 요청까지 우선한다. 판정은 보관 중인 실제 스트리머 발언에 근거한다.
- 모델이 새 조작·전략·해법을 권하는 채팅을 `advice=true`로 구분한다. 서버는 이 분류에 대해 허용 여부와 건수를 검사한다. 감상·축하·일상 대화, 현재 질문에 맞춘 이전 답의 이유 설명은 계속 가능하다.
- 음성 수신 ID 또는 직접 입력한 발언 ID로 한 가지 요청을 묶는다. 이미 표시한 힌트와 아직 전달 가능한 대기 힌트를 함께 세므로, 후속 저장 오류로 재시도해도 두 번째 힌트가 표시되지 않는다. 차단·스포일러 필터에 걸린 제안이나 취소된 대기 답변은 사용한 힌트로 취급하지 않는다.
- 실제 표시한 힌트만 개인별 `conversationRhythm.deliveredAdvice`에 포함한다. 대기·취소된 답변, 늦게 들어온 관객이 못 본 말, 삭제한 말은 이 문맥에 들어가지 않는다. 전달됐다는 사실을 정답 또는 실행 완료로 바꾸지 않는다.
- “훈수는 그만”처럼 명시적으로 거절하면 생성 중인 일반 라이브 응답을 취소한다. 늦게 완료된 응답도 큐에 들어가지 않는다. 특수 기능·기획 방송의 별도 경로는 유지한다.

## 검증

- `npm run check`: **557 tests passed**, TypeScript/Vite 빌드 통과. `artifacts/advice-check-verified.log`.
- 새 회귀 7개: 요청 범위·정정·항상/금지 정책, 여러 관객의 중복 힌트, 새 화면과 새 요청 구분, 필터 후 건수, 설명 유지, 생성 취소, 개인별 목격·삭제, 실제 제공처 스키마, 저장 실패 전후 재시도. 각 테스트에 여러 조건이 포함된다.
- 첫 전체 실행의 신규 테스트는 관객 출석 난수 때문에 실패했다. 테스트의 출석·이탈 난수를 고정한 뒤 전체 검사를 통과했다. 제품 출석 확률을 바꾸지 않았다.
- 공식 ChatGPT CLI의 **gpt-6-astra / low**, 최종 코드로 실제 6회 호출. `scripts/verify-advice-continuity.mjs`; 최종 원본과 문맥은 `artifacts/advice-continuity-Pt0Dft/result.json`. 이 작업의 합성 카드 상황과 빈 PNG 표본이며 사용자 원본 기록·장치·게임 화면을 수집하지 않았다.

최종 응답을 직접 읽어 확인한 결과:

1. 한 가지 요청 → “수비 두 장이면 방어도 10이라 공격 6을 전부 막을 수 있어요.” 한 건.
2. 새 발언 없는 표본 두 번 → 두 호출 모두 채팅 없음.
3. 이유 질문 → 한 장 5와 공격 6의 차이를 설명. 새 행동 권유 없음.
4. 다음 턴의 새로운 한 가지 요청 → “말씀하신 수치라면 타격 한 장으로 적 체력 6을 다 깎을 수 있어요.” 한 건.
5. 훈수 중단 → “넵, 지켜볼게요!” 한 건.

초기 실제 검증에서는 “피해 없이 … 힌트 하나만”의 ‘없이’를 거절로 오인해 아무 답도 못 했다. 훈수 명사에 직접 붙은 ‘없이’만 거절로 판정하도록 수정하고 해당 표현을 회귀에 추가했다. 실패 원본은 `artifacts/advice-continuity-INiwFu/result.json`. 중간 수정본도 6회 통과했으며 `artifacts/advice-continuity-2hPDd1/result.json`에 보존했다. 최종 실행은 재시도 전달 예산과 고정된 출석 조건까지 반영한 별도 실행이다.

## 범위와 다음 검증

서버가 문장의 의미를 독립적으로 증명하는 장치는 아니다. 모델이 힌트를 감상으로 잘못 분류하거나 한 문장에 여러 힌트를 섞을 가능성, 보수적인 요청 표현 인식의 한계가 남는다. 저장 형식 호환을 위해 기존의 분류 없는 관찰은 `advice=false`로 읽고, 실제 모델의 출력 스키마에는 분류를 필수로 요구한다.

이번 실제 모델 검증은 합성 대화이며 게임 화면 정확도·물리 마이크·실제 방송 응답 지연 검증이 아니다. 기존 Windows 검증 패키지에는 이 커밋을 아직 재포장하지 않았다. 다음 단계에서 새 패키지로 실제 카드 전투와 짧은 마이크 후속 질문을 확인하고, 정적인 장면의 자발적 대화 및 시각 수치의 신뢰도 문제를 이어서 점검한다. Steam 출시 품질 목표는 계속 진행 중이다.
