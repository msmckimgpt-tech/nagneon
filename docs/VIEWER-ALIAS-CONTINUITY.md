# 닉네임이 바뀐 관객의 호명

관객이 닉네임을 바꾼 뒤에도 저장된 이전 이름을 부르면 같은 관객 ID의 호명으로 처리한다. 조용히 시청하던 관객의 발언 후보 선정, 개인 대화 맥락의 호명 표시, 공개 채팅의 관심도, 관객 간 언급 기록이 같은 이름 해석을 사용한다. 호명은 응답 기회이며 채팅을 강제하지 않는다.

현재 이름의 소유자는 이전 이름보다 우선한다. 현재 소유자가 부재중이거나 비활성 상태여도 예전 소유자로 대신 연결하지 않는다. 같은 이전 이름을 여러 관객이 공유하면 임의로 한 명을 고르지 않는다. `모모친구`에 포함된 `모모`처럼 이름이 겹치면 긴 이름이 해당 구간을 차지하고, 별도로 나온 `모모`는 다시 해석할 수 있다. 영문 이름은 다른 영숫자 단어의 일부와 일치시키지 않는다.

호명 해석은 발언 후보를 추리기 전 전체 관객 목록에서 수행한다. 부재, 원래 발언을 들은 관객 목록, 이번 방송의 입장 시각 제한은 그대로 적용한다. 닉네임을 추측하거나 음성 전사 원문을 바꾸지 않으며 개인 메모를 모델 입력에 추가하지 않는다. 저장 형식, 기존 기록·메모, 모델 호출 수와 제공처는 변경하지 않는다.

## 검증

- `node --test test/viewer-alias-continuity.test.js`: 이전 이름, 중복 소유, 이름 겹침, 부재·청취·입장 경계, 실제 Studio 입력 및 개인 메모 제외를 검사한다.
- `npm run check`: 형식 검사, 874개 테스트, TypeScript/Vite 빌드 통과.
- `npm audit --audit-level=high`: 취약점 0건.
- `node scripts/verify-viewer-alias.mjs --live`: 공식 계정의 Astra low를 한 번 호출하는 선택 검사. 합성 관객 `모모 → 구름산책`을 예전 이름으로 부르면 같은 ID가 현재 이름으로 답하는지 실제 Studio 경로에서 검사한다. 결과·모델 입력·소스 해시는 격리 작업 공간의 `artifacts/viewer-alias-*`에 보존한다.

2026-09-23 Windows에서 실제 모델 검사 1건을 통과했다. 관객은 “지금은 구름산책으로 활동해요. 모모라고 불러주셔도 좋아요!”라고 답했다. 사용자 대화·녹화·마이크·화면을 사용하지 않은 합성 대화이며, 일반적인 자연스러움이나 모든 게임 상황의 합격 근거로 확대하지 않는다.

같은 날 최신 main의 화면 전송 변경과 합친 격리 코드에서 `npm run check` 879개 테스트와 빌드가 통과했다. 실제 모델 검사를 한 번 더 실행하여 “지금은 구름산책으로 활동해요!”라는 동일 ID의 응답을 확인했다.

## 한계와 복귀

이름 언급만으로 실제 의도를 확정할 수 없다. 일반 단어와 같은 닉네임이나 역사적 인물을 이야기하는 상황의 최종 응답 여부는 기존 대화 맥락에 맡긴다. 여러 관객은 한 모델 호출에서 생성되므로 호명 단서만으로 모델의 모든 오답을 방지하지는 못한다.

문제가 있으면 이 변경을 되돌려 기존 현재 이름 방식으로 복귀할 수 있다. 데이터 마이그레이션이 없어 메모·이전 닉네임·잔액을 초기화할 필요가 없다. 이 검증은 소스 통합 범위이며 설치본 업데이트·패키지 릴리즈는 별도 검증한다.
