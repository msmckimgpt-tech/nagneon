## 원인과 변경

전사에는 녹음 시작/끝 시각이 있었지만, 관객 반응은 전사가 도착한 뒤의 `TemporalFrames.window(Date.now())`를 보냈다. 화면 보관은 16초이며 이미 처리한 구간은 제외하므로 늦은 발언의 대상 장면이 사라질 수 있었다. 인식 대기열이 차거나 worker 준비가 실패하면 마이크를 끄는 동작도 있었다.

- 녹음 종료 시점에 기존 화면 표본 중 발언 시작 500ms 전부터 끝까지 첫/중간/마지막 최대 3장을 보존한다. 이미 처리한 화면도 발언의 근거로 쓸 수 있다. 오디오와 같은 작업에 묶어 전사 대기/재전송 중 유지하며 현재 화면으로 교체하지 않는다.
- HTTP에서 이미지 크기, 장수, 시각 순서/범위, 세션을 검증한다. 서버 영수증 해시에 이미지 내용까지 포함하고 대기 자료는 깊은 복사로 분리한다. 시간 정보가 있는 발언은 서로 다른 요청으로 처리한다.
- 관객 요청은 현재 화면과 발언 당시 화면의 첨부 번호를 구분한다. 새로 입장한 수신자가 볼 수 없는 과거 화면, 종료된 소스, 120초를 넘긴 자료는 제외한다. 과거 화면만 쓰는 요청도 해당 화면 종료 시 취소된다. 과거 화면은 현재 시청 커서를 이동시키지 않는다.
- 발언 당시 화면이 없으면 `speechScreen.status=unavailable`을 전달하고 현재 장면으로 과거 대상을 추정하지 않도록 지시한다. OBS 입력에는 아직 같은 캡처 시점의 화면 보존 경로가 없어 이 상태를 사용한다. 500ms 표본과 3장 선택은 모든 영상 순간을 기록하는 방식이 아니다.
- 실제 방송 시작 시 마이크를 자동 연결한다. 활성 마이크 버튼은 상태 표시로 사용한다. 준비 실패는 재연결하고, worker 재준비 오류는 같은 오디오를 한 번 재시도한다. 인식 오류가 장치/녹음을 끄지 않는다. 대기 음성 8개가 차면 처리 중인 작업은 유지하고 가장 오래된 대기 1개를 제외하며 사용자에게 알린다. 장치 단절은 재연결하고 방송 종료는 녹음과 재연결을 끝낸다. 권한 거부나 물리 장치 단절 상태를 정상 연결로 표시하지 않는다.
- 짧은 음성의 첫 encoder 입력을 8초 고정에서 4초(음성 ≤2.5초), 6초(≤4.5초)로 줄인다. 실제 음성과 최소 1.5초 패딩, medium/CPU/int8/beam3, 낮은 확신의 30초 재처리를 유지한다. 그보다 긴 입력은 기존 경로다.

화면 자료는 대기 작업 메모리에만 추가한다. 상태/SSE/대화 저널에 원본 이미지를 넣거나 영구 녹화를 새로 켜지 않는다. Codex 제공처는 기존과 같이 요청 이미지를 임시 파일로 전달하고 요청 종료 후 정리한다. 텍스트에 대한 모델의 올바른 해석 자체를 결정적 테스트가 보장하지는 않는다.

## GPU 검토

이 PC의 RTX 2070 8GB를 CTranslate2 4.8.2가 감지했고 `int8_float16` 지원을 확인했다. 원래 환경의 GPU 전사는 `cublas64_12.dll` 부재로 실패했다(`gpu-probe.log`). 프로젝트/전역 Python을 바꾸지 않고 NVIDIA PyPI wheel `nvidia-cublas-cu12==12.4.5.8`, `nvidia-cudnn-cu12==9.1.0.70`을 시험 폴더 `gpu-libs`에 설치했다. DLL 탐색 경로도 시험 자식 프로세스에만 지정했다.

`gpu-benchmark.json`은 동일 medium/beam3/변경된 encoder 정책과 동일 6개 합성 문장 × 2회의 CUDA/int8_float16 결과다. 처리 중앙값 **738.5ms**, 두 번째 회차 중앙값 **676.5ms**, 범위 **411~1,961ms**. CPU 수정본과 정규화 전사 12건이 같았다. GPU 모델 최초 준비를 포함한 별도 단일 시험은 총 9,579ms였다(`gpu-ready-probe.log`). 작업 중 GPU 전체 잔여 메모리는 약 3,238 → 2,773MiB였으나 게임 등도 실행 중이므로 차이를 STT 전용 메모리 사용량으로 주장하지 않는다. FPS/장시간 GPU 메모리 압박/실제 목소리 정확도는 미검증이다.

**GPU 가속은 유망하며 실제 전사까지 검증했다. 제품 기본 장치는 아직 CPU다.** GPU 배포 적용에는 CUDA/cuDNN 라이선스와 payload 무결성/설치 크기 처리, 시작 시 여유 메모리 확인, DLL 부재/OOM/장치 오류 시 CPU 재시도 및 준비 상태 표시, 게임 병행 장시간 검증이 필요하다. 현재 앱의 GPU 모드를 바꿨다고 주장하지 않는다. 참고: [faster-whisper 고정 버전](https://github.com/SYSTRAN/faster-whisper/tree/v1.2.1), [CTranslate2 하드웨어 지원](https://opennmt.net/CTranslate2/hardware_support.html).

## 웹 보조 검토 및 적용 범위

`artifacts/web-review`에 초기 설계/기준 소스 묶음을 준비했다. [웹 정합성 검토](https://chatgpt.com/c/6aa81887-571c-83e8-b11c-aac47f1615c4)는 완료된 답변을 확인했다. 픽셀을 포함한 영수증, 불변 캡처, 결정적인 화면 선택/첨부 번호 의견을 원본 코드와 대조했다. 해당 답변의 '공유 요청에서 관객별 다른 이미지 사용' 제안은 현재 공통 이미지 접근 구조에 맞지 않아 채택하지 않았고, 'encoder 최소 8초 유지' 제안도 현재 최적화 구조를 오독하여 채택하지 않았다. 성능 검토 요청은 보냈으나 CDP timeout/Debugger unattached로 완료 원문을 확인하지 못했고 웹 종합도 미실행이다. 로컬 검사를 웹 검토로 표시하지 않는다.

소스 통합과 이미 실행 중인 배포 앱은 별개다. 사용자 앱/게임을 종료하거나 재시작하지 않았다. 실행 중인 기존 배포본은 이 소스 변경을 아직 사용하지 않는다. 최신 소스로 다시 빌드/실행해야 마이크 자동 연결과 화면 정합성 수정이 적용된다.
