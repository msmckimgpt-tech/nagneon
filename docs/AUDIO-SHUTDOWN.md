# 음성 입력 종료와 저장 완료

일반 마이크 중지는 이미 도착한 원음과 짧은 유예 시간 안의 전사를 복구 기록에 보존한다. 중지된 입력은 관객에게 새 발언을 전달하지 않는다. 앱 전체 종료는 새 입력을 차단하고, 종료 전에 수락한 원음 저장과 화면 근거·처리 기록까지 기다린다.

`NativeAudio.close()`와 `SubscriptionVoice.close()`는 처음 호출할 때 입력 수락을 닫고 주기 타이머를 해제한다. 반복 호출은 같은 완료 Promise를 기다린다. 기록 저장이나 한 구성의 종료가 실패해도 나머지 소유 정리를 시도한다. 실제 저장 오류와 호스트 종료 미확인은 호출자에게 전달하며, 여러 실패가 있으면 원본 오류를 포함한 `AggregateError`로 보고한다.

`AudioLifetime`은 콜백 실행 전에 비동기 작업을 등록한다. 이미 수락한 작업이 종료 중에 만드는 후속 작업도 기다리지만, 외부의 새 요청이나 이미 끝난 작업의 지연 콜백에 입력 수락 권한을 주지 않는다. 원음의 서버 경로는 캡처부터 로컬 보존, 해당 마이크·시스템 소리의 후속 기록까지 같은 입력 소유자에 등록한다. 진행 중 작업이 기록을 더 만들지 않는 시점에 마지막 쓰기 큐를 기다린다. 복구 준비에서 뒤늦게 타이머가 설치되지 않도록 중지 상태를 다시 확인한다.

호스트 종료 성공은 기존 `SubscriptionVoiceHost`의 자식 종료 관측을 따른다. 전송 요청 확인이나 종료 명령을 보냈다는 사실만으로 성공 처리하지 않는다. 기존 구독 연결, 모델 설정, 원음 보존 기간 및 관객 목격 범위는 유지하며 추가 제공처나 모델 호출을 도입하지 않는다. Node 기본 `AsyncLocalStorage`를 사용하며 새 패키지 의존성은 없다.

회귀 검사는 합성 원음과 명시적인 대기 지점으로 저장·전사·응답 계획·보존 조회·복구 준비와 종료의 순서를 확인한다. 실제 파일 저장 실패도 소유 테스트 경로에서 확인한다. 이 검사는 실제 계정, 물리 마이크·오디오 장치, 사용자 설치나 임의의 외부 어댑터 종료까지 검증한 결과는 아니다.

원음 저장 실패 시 마이크와 시스템 소리의 중지를 각각 시도한다. 한쪽 중지나 상태 알림이 실패해도 최초 저장 오류를 덮어쓰지 않는다. 원음 저장 경로의 `AbortError` 역시 저장 실패로 전달하며, 원격 처리의 의도적인 취소와 구분한다.

캡처 검증이 실패해도 원음 저장은 계속한다. 두 입력의 중지는 각각 시작하며, 중지 결과를 기다리느라 원음 저장의 시작을 미루지 않는다. 저장과 중지 정리가 끝난 뒤 실제 실패를 보고한다.

서버 전체 종료도 구성별 정리를 시작하기 전에 완료 Promise를 등록한다. 방송 종료 상태를 받은 콜백에서 종료를 다시 요청해도 동일한 Promise를 반환하고 HTTP·음성 정리를 중복 시작하지 않는다.

구성별 정리 실패 후에도 자신의 프로필 잠금 해제를 한 번 시도한다. 잠금 해제도 실패하면 앞선 정리 오류와 함께 보고한다. 소유권이 바뀐 잠금은 삭제하지 않는다.
