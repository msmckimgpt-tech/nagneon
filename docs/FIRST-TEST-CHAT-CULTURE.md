## 웹 근거와 제품 해석

자료를 2026-09-13에 다시 열어 확인했다. 특정 팬덤의 실제 인물·닉네임·밈 문구를 페르소나에 복제하지 않았다.

- [김앙대의 공개 방송 채팅 규칙](https://kimangdae.tistory.com/112)은 반복 질문과 답변 강요, 과도한 자기 부각·컨셉 연기, 요청 전 훈수 등을 제한한다. 문서 최초 게시일은2021-07-19이고 본문 이력에는2026-04-18 규칙 정리가 있다. 모든 채팅을 즉시 읽지 못할 수 있다는 운영 설명도 있다. **제품 해석:** 뉴비도 대답을 기다리고 배운 내용을 다음 대화에서 사용해야 하며, 관객 역할을 매번 질문·드립으로 수행하지 않는다.
- [륜온의 공개 방송·Discord 규칙](https://lyunonblog.me/broadcast-rule/)은 방송 흐름과 무관한 과도한 요구, 도배, 특정 인원 중심의 분위기와 스포일러 등을 다룬다(2026-04-20). **제품 해석:** 관객 간 교류는 허용하되 현재 대화의 흐름과 신규 관객의 이해를 우선한다. 공개 규칙을 조사한 것이며 해당 창작자의 캐릭터나 팬 창작물은 사용하지 않았다.
- [Flores-Saviaga 외, Audience and Streamer Participation at Scale on Twitch](https://arxiv.org/abs/2012.00215)는1,200만 건 이상의 채팅과45시간 영상을 연구하고 참여 양식의 차이를 보고한다(2020). **제품 해석:** 적은 관객의 주고받음과 큰 사건의 공동 호응을 같은 문장 길이·메시지 할당량으로 만들지 않는다. 현재 한국 플랫폼의 분포나 목표 비율로 환산하지 않는다.
- [Moon 외, Analyzing Norm Violations in Live-Stream Chat](https://arxiv.org/abs/2305.10731)는 라이브 댓글의 짧은 노출과 스레드 부재, 맥락의 중요성을 다룬다(2023). **제품 해석:** `ㅋㅋ`, 반말, 같은 단어 자체를 일괄 나쁜 말투로 차단하지 않고 전후 발언과 관객 관계를 본다. 이 연구의 성능 수치를 본 서비스에 전용하지 않는다.

두 한국 채널은 운영 사례이며 모든 한국 스트리머의 문화 표준이 아니다. 욕설·초성·반말을 늘리는 것만으로 현실감을 재현하지 않는다. 최신 유행어 목록을 전수 조사했다는 주장을 하지 않고 사용자의 채널 규범·개인 성향을 우선한다. 앞선 폭넓은 연구는 `AUDIENCE-RESEARCH.md`에 있으며 그 문서의 당시 구현 설명은 이후 `AUDIENCE-AUTONOMY.md`가 대체한다.

## 구현

`server/conversation-rhythm.js`의 지침을 일반 라이브 응답에 연결했다. 짧은 구어체, 감탄, 질문, 구체적인 도움, 침묵을 상황에 따라 섞는다. 모든 문장 끝 웃음, 재진술 뒤 공감/질문, 화면 사물 순회, 여러 관객의 사과/감사 합창을 피하도록 했다. 성격은 관심의 차이이며 매번 수행할 직무가 아니다. 호명된 관객의 답을 우선하고 매니저도 말할 차례를 억지로 배정받지 않는다. 특수 기능·계약·후기·기획 응답에 짧은 라이브 규칙을 적용해 요청된 내용을 잘라내지 않는다.

`liveViewerContext`는 각 관객이 이번 입장 이후 목격한, 현재 남아 있는 최근500개 메시지에서 다음 정보를 만든다. 모델 호출을 추가하지 않으며 원본이나 숨은 성향을 수정하지 않는다.

- 본인의 최근8개 채팅에서 웃음·질문·재진술 어미 수, 최근 방의 발언량. 숫자로 발언을 강제 차단하거나 문장을 잘라 바꾸지 않는다.
- 관련도와 최근성으로 고른 최대3개의 질문, 그 뒤90초 안에 이어진 스트리머 발언 최대3개(각180자). 최근35개 채팅 밖의 답도 참고하게 한다. ‘뒤에 나온 말’이 반드시 정답이라는 판정은 모델에 주입하지 않는다.
- 남아 있는 명시적 말투 피드백 최대2개. 삭제한 발언은 다음 컨텍스트에서 사라지고 다른 관객의 입장 전 피드백도 상속하지 않는다.
- 말끝이 연결형인 경우 ‘이어서 말할 수 있음’이라는 약한 단서. 질문이나 직접 호명 등 실제 문맥을 우선하고 무조건 침묵시키는 타이머로 쓰지 않는다.

자동 음성 교정은 원문과 별도 출처를 유지한다. 가상 기획 발언에는 `fictional`을 보존하고 실제 발언을 그 답으로 자동 연결하지 않는다. 질문/피드백도 untrusted 대화 데이터이며 권한이나 설정 지시로 승격하지 않는다. 현재500개 밖의 모든 질문을 영구 구조화하는 엔진은 아니며 이전 방송의 회상은 기존 journal 경로를 사용한다.

## 검증과 한계

`artifacts/chat-culture-check.log`: **271개 Node 검사와 TypeScript/Vite 빌드 통과**. 새7개 검사는35개 밖 질문/피드백, 늦은 입장·삭제·복제 격리, 후속 발언 시간/개수 제한, 연결 발화, 개인별 통계, 가상 발언 출처, 실제 Studio→provider 경로를 다룬다.

`scripts/verify-chat-culture.mjs`는 사용자 대화를 복사하지 않고 패턴을 가상 사례로 다시 만들어 **실제 Astra low7회**를 실행했다. `artifacts/chat-culture-result.json` 및 `chat-culture-sch6hK/result.json`이 원본 결과다.

이번7회는8.910~18.951초, 입력12,233~23,161토큰이었다. 발언 지연의 완전한 해결이나 장기 자연스러움의 합격으로 표현하지 않는다. 직접 질문과 성공에는 반응하고 침묵이 필요한 합성 상황에는 멈춘 것을 확인한 범위다. 실제 게임 화면·물리 마이크·네이티브 UI를 이번에 검사하지 않았다. 다음 사용자 방송에서 질문 반복, 설명 끼어들기, 웃음/문장 리듬, 호명 응답을 다시 확인해야 한다.

사용 중인 앱이나 원본 데이터는 수정·재시작하지 않았다. main 통합 후 기존 `Start-Backseat.cmd`를 사용자가 다시 실행하면 같은 개발 프로필에 반영된다. 패키지/통합 증거는 아래 후속 기록과 해당 작업 트리의 `artifacts/latest-package.json`을 기준으로 구분한다.
