# 조용한 관객의 자율 대화

2026-09-14, `codex/quiet-viewing-company`, 기준 `4dca94006fa5707a0dfb5c1bc940a9412f629bd7`.

[직전 Steam 검증](RELEASE-LATENCY-ACCEPTANCE.md)에서 카드 보상 화면을 오래 지켜보는 동안 자율 채팅이 관찰되지 않았다. 일반 호출 67회 중 모델 침묵 62회였으며, 그 기록의 일부 구간에서 일반 관객은 lurking, 시스템 매니저만 active였다. 기존 진단에는 잡담 기회 구분이 없어 모든 침묵을 같은 원인으로 단정할 수는 없다.

## 원인과 변경

기존 `Ambient.idle`은 잠수 관객도 포함한 목격자가 있으면 75–135초의 잡담 기회를 소비했다. 그러나 `Audience.context`는 active 관객만 후보로 넘겼고, 모델 지침 역시 active만 발언하도록 했다. 시스템 매니저만 전달되거나, 후보 선정만 고쳐도 모델이 여전히 잠수 관객의 발언을 막는 두 단계의 문제가 있었다.

- 일반 관객이 실제로 있는 때만 잡담 기회를 사용한다. 매니저만 남아 있을 때 다음 관객의 기회를 미리 소모하지 않는다.
- 해당 기회에 한해 현 방문에서 함께 보는 잠수 관객 최대 한 명을 발언 후보에 포함한다. 기존 성향·유입 관심과 무작위 점수로 고르며, 접속·친밀도·방문 시각을 조작하지 않는다. 모델은 현재 게임 흐름을 우선하거나 침묵할 수 있다.
- 모델의 active 제한에도 같은 예외를 적용한다. 시스템 매니저가 빈 채팅창을 대신 채우지 않는다.
- 기존 60초 대화 간격과 75–135초 재기회 간격, 침묵 요청, 새 발언 우선, 중복 제한, 훈수 정책을 유지한다. 화면 변화가 없는 잡담으로 진행·포인트·핫클립을 만들지 않는다. 새 화면을 받는 기회에는 최신 영상과 만료·퇴장 검사를 계속 적용한다.
- 진단 JSON에 `company`(idle/watching/null), `eligibleViewers`, `lurkingEligible`를 추가했다. 원문·관객 ID 없이 후보 누락과 모델의 침묵을 구분할 수 있다.

## 검증

`npm run check`: 590개 테스트, 실패·취소·건너뜀 0, TypeScript/Vite 빌드 통과. 새 회귀는 잠수 유지 및 전달, 매니저 단독 기회 보존, 한 명 제한·퇴장·비활성·미목격 제외, 침묵 요청·호명 우선, 최신 영상 보존·생성 중 퇴장, 진단의 개인정보 배제를 검증한다.

실제 Astra(`gpt-6-astra`, low)로 후보만 고친 중간 버전에서는 두 기회 모두 채팅이 없었다. active 전용 모델 지침을 바로잡은 최종 소스에서는 다음 네 호출이 통과했다. 합성 대화 및 통제된 시계로 실행한 결과이며 실제 사용자 세션의 발언 빈도나 물리 마이크 지연을 측정한 것은 아니다.

1. 첫 잡담: 퍼즐 그림에서 작은 가게 풍경을 좋아한다는 개인 취향, 10,151ms.
2. 다음 잡담: 취미 중 가사 없는 음악을 선호한다는 다른 소재, 11,919ms. 동일 문장 재생 없음.
3. 조용히 해 달라는 요청: 채팅 없음, 7,956ms. 140초 뒤에도 추가 모델 호출 없이 침묵 유지.
4. 다시 호명한 질문: 퍼즐을 선호하는 이유를 답함, 10,498ms.

`node scripts/verify-quiet-viewing-company.mjs --live`로 재실행할 수 있다. 테스트에는 기존 사용자 대화·미디어·게임 세이브가 들어가지 않는다. 실제 모델 사용량은 발생한다. 기계적 판정과 별도로 대사의 자연스러움·반복 여부를 검토해야 한다.

첫 전체 검사에서는 `onboarding.test.js`의 재시작 후 HTTP 요청에 `fetch failed`가 한 번 발생했다. 해당 파일의 단독 검사와 최종 전체 검사는 통과했다. 원인을 해결했다고 처리하지 않았으며 최초 실패 로그를 보존했다.

## 실제 앱 확인

같은 소스의 Electron 앱을 별도 `native-profile-02`로 실행했다. 이전 AI 검증용 데이터만 복사하고 Just Chatting, 잠수 비율 0.9로 설정했다. 이는 오류 재현을 위한 테스트 조건이며 제품 기본값 변경이나 자연 발생 빈도 실험이 아니다. 화면·마이크·출력 소리는 연결하지 않았다.

키보드로 퍼즐을 좋아한다는 이야기 한 건을 보낸 뒤 추가 발언 없이 기다렸다. 80,616ms 뒤 관객이 스스로 퍼즐의 한 조각을 맞추며 다음 자리까지 떠오르는 순간을 좋아한다는 채팅을 올렸다. 진단에서 `hasSpeech=false`, `company=idle`, `lurkingEligible=1`, `eligibleViewers=1`, 생성·실제 전달 각 1을 확인했다. 전체 내보내기에서도 그 관객은 계속 lurking이었다. 모델 시간은 13,285ms였다. 이어서 혼자 생각할 수 있게 조용히 봐 달라고 요청했고, 진단 저장 시점까지 최소 92,725ms 동안 추가 잡담 호출이 없었다. 표시된 대화와 진단의 전달 시각도 50ms 이내로 대응한다.

첫 준비 프로필에는 검증 스크립트가 잠수 비율 1을 잘못 넣어 최대 0.9인 설정 스키마를 위반했다. 앱이 백업으로 복구한 사실을 UI에서 확인한 뒤 이 실행을 대화 검증에서 제외했다. 두 번째 프로필은 앱 실행 전에 `Settings.parse`로 검증했다.

두 소스 앱에서 창이 사라진 뒤에도 Electron 프로세스가 남는 현상이 관찰됐다. 방송은 정상적으로 OFFLINE으로 전환했지만 프로세스 종료를 통과로 판정하지 않는다. 프로세스 경로·PID·생성 시각·자식·소켓 상태를 보존하고 소유한 테스트 프로세스만 정리한다. `desktop/graceful-quit.cjs`와 `server/index.js`의 종료 대기 단계를 실제 소스 앱에서 추적하는 것이 다음 수용 항목이다. 종료 문제는 이번 잠수 관객 수정으로 해결했다고 주장하지 않는다.
