# 연속 화면 인코딩

연속 화면 샘플은 최대 변 960픽셀로 캔버스에 복사한 뒤 비동기 `toBlob`과 `FileReader`로 JPEG data URL을 만든다. 500ms 샘플 주기, JPEG 품질 0.6 → 0.35 → 65% 축소 후 0.35, 프레임당 320,000자 제한과 최대 8프레임 전달 계약은 유지한다. HTTP/JSON/base64 전송 형식은 바뀌지 않는다.

## 순서와 취소

- 인코딩은 한 번에 하나만 수행한다. 진행 중인 샘플 주기는 큐에 쌓지 않는다.
- 기록 시각은 변환 완료 시각이 아니라 캔버스에 복사한 시각이다. 오래 걸린 변환이 새 화면으로 취급되지 않는다.
- 방송·화면 식별자가 바뀌거나 캡처가 중지되면 늦게 완료된 결과와 오류를 버린다. 새 방송의 버퍼를 지우지 않는다.
- 크기 초과 재시도는 이미 복사한 화면에서 진행한다. 변환 중 앞으로 재생된 영상으로 바꾸지 않는다. 최종 축소는 복사된 960픽셀 이하 캔버스 기준이므로 큰 원본을 직접 다시 축소하던 이전 경로와 픽셀 단위 차이가 있을 수 있다.
- 종료 시 타이머와 캔버스를 정리한다. 브라우저가 이미 시작한 `toBlob` 연산 자체의 강제 취소는 지원하지 않으며, 완료 결과를 수용하지 않는 방식이다.

## 합성 Electron 비교

MCKIM / Electron 44.3.0, 숨겨진 offscreen 렌더러. 동일 프로세스에서 기준 커밋 `930261d59b4c83096d2baa4650fd55794fd29c5b`와 수정 함수를 비교했다. 각 조건별 20회 준비 후 60회 측정했다. 단위는 ms, 값은 중앙값이다.

| 합성 화면 | 호출 반환 전 점유: 이전 → 수정 | 미리 예약한 UI 작업 대기: 이전 → 수정 | 이미지 준비 완료: 이전 → 수정 |
|---|---:|---:|---:|
| 960×540 노이즈 | 9.2 → 2.4 | 9.3 → 4.9 | 9.2 → 17.1 |
| 960×960 노이즈·3단계 인코딩 | 32.5 → 3.9 | 32.6 → 4.8 | 32.5 → 45.1 |
| 960×960 단순 도형 | 8.0 → 3.8 | 8.1 → 5.4 | 8.0 → 18.1 |

비교한 3개 정적 합성 화면의 최종 이미지 문자열은 바이트 단위로 같았다. 전체 입력에 대한 동일성 보장은 아니다. 이미지 완료까지 걸리는 시간은 증가하지만, 그동안 다른 UI 작업을 처리할 수 있다. 실화면 캡처·비디오 디코더·게임과의 자원 경쟁·일반 가시 창 부하·AI 응답 지연은 측정하지 않았다. 이 수치는 모델 응답 속도 개선이나 실방송 FPS 개선을 의미하지 않는다.

검증 원본은 작업 폴더의 `artifacts/verify-canvas-responsive.cjs`, `artifacts/canvas-responsive/result.json` 및 `artifacts/canvas-responsive.log`다. 데이터는 합성이며 사용자 화면·음성·계정은 사용하지 않았다. 비동기 중복 방지, 시각 보존, 중지·화면/방송 교체 후 늦은 성공/실패, 크기 초과 재시도와 오류 정리는 `test/temporal-capture-async.test.js`에서 검사한다. 기존 시간순 목격·화면 전달 회귀도 유지한다.
