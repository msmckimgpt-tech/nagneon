# 핫클립 미디어 검사와 저장 취소

작업: `codex/clip-media-validation`, 별도 worktree `G:/dev/ai/00_game_backseat-worktrees/clip-media-validation`. 기준 main은 `2fc6cc65984df92b271a743bb863337c2332d645`다. Computer Use·사용자 앱 재시작·게임 및 장치 캡처를 중단한 조건에서 파일과 별도 서버로 검증했다.

## 재현한 문제와 변경

기준 커밋의 HTTP 클립 업로드 라우트를 그대로 추출하여 합성 파일로 재현했다. WebM 식별자 뒤에 0만 채운 124바이트 파일도 음성 클립으로 저장됐고, 실제 영상+음성 파일을 음성이라고 제출해도 HTTP200으로 저장됐다. `artifacts/baseline-clip-route-result.json`과 추출 소스 SHA-256을 보존했다.

이제 업로드는 저장 전에 별도 Python/PyAV 프로세스에서 모든 패킷을 디코딩한다. 파일 경로나 URL을 넘기지 않고 stdin으로 최대20MiB만 전달한다. ASR·소리 모델이나 AI 계정을 호출하지 않으며, 검사 전 파일을 임시 저장하지 않는다. 배포본은 기존 음성용 Python의 PyAV를 사용하고 `speech/clip_inspector.py`를 패키지 무결성 목록과 필수 실행 파일 검사에 포함한다.

WebM 문서 구조, 각 요소의 경계, VP8/Opus 코덱, 실제 트랙 종류·수, 프레임 손상과 타임스탬프를 확인한다. 음성이라고 제출한 파일에 영상이 있거나 `hasAudio`와 실제 트랙이 다르면 거부한다. 무음도 실제 Opus 트랙이 있으면 유효하다. 녹음기의 시작 지연을 고려하여 실제 디코딩 길이와 요청 길이의 차이는 최대2초 또는15%까지 허용한다. 메타데이터 Duration 값만으로 판단하지 않는다.

MediaRecorder의 길이 미정 Segment·Cluster도 허용한다. 처리 구조는 [Matroska 문서 구조](https://www.matroska.org/technical/diagram.html)와 [요소 명세](https://www.matroska.org/technical/elements.html)를 참고했다. 프레임과 끝부분 flush 패킷까지 확인하는 방식은 [PyAV demux/decode 문서](https://pyav.org/docs/stable/api/container.html)에 근거한다.

동시에 업로드 본문1개·검사 프로세스1개만 허용한다. 본문을 읽기 전에 자리를 확보하고, 업로드30초·디코더15초 제한을 둔다. 업로드가 중간에 멈추면 HTTP408을 보낸 뒤 해당 요청 연결을 닫아 본문이 계속 쌓이지 않게 한다. 검사기 출력8KiB, EBML 요소10만개, 패킷3만개, 트랙당 프레임1만개, 누적 영상120억 픽셀·음성450만 샘플을 상한으로 한다. 영상8192×4320·음성48kHz/2채널까지 확인하며 VP8 키프레임의 자체 해상도도 디코딩 전에 검사한다. 이는 처리량 상한이며 OS 수준 메모리 격리나 모든 화면 크기의 실시간 처리 보장은 아니다.

클립 삭제·방송 종료/재시작·세션 변경·버퍼 설정 철회·연결 중단 시 검사 취소를 전달한다. 검사기의 뒤늦은 성공만으로 저장하지 않고 커밋 직전 클립·방송 epoch·세션·설정·시각을 다시 확인한다. 검사와 저장 실패 후에도 관객이 남긴 텍스트 기록은 유지된다. 서비스 종료는 자신이 실행한 검사기의 실제 종료까지 기다린다.

손상·불일치는 HTTP422, 혼잡429, 실행기 부재503, 검사 시간 초과504다. 클라이언트는 영구 오류를 반복 제출하지 않으며, 일시적 혼잡·서버 오류·전송 실패만 기존 횟수 안에서 재시도한다. 마지막 성공 응답이 유실됐거나 이미 저장된 충돌이어도 GET으로 커밋 여부를 확인한다. 요청 제한 시간은 디코딩 대기를 고려해25초로 조정했다.

## 검증

- `npm run check`: **372 Node 검사 + TypeScript/Vite 통과**, `artifacts/validation-release-check.log`. 새 검사21개는 검사기 프로세스 수명, 실제 자식 프로세스 종료, HTTP 경합/취소/삭제/설정 변경, 미완료 본문 제한, 영구·일시 오류 재시도를 포함한다.
- 실제 PyAV 검사 **13개 통과**, `artifacts/decoder-python-tests.log`. 정상 영상/음성/영상만/무음/길이 미정 Segment·Cluster, 여러 절단 위치, 트랙 불일치, 코덱 손상, 과대 키프레임, 빈 패킷, 위조 길이, 덧붙인 데이터 등을 확인했다.
- 실제 HTTP+검사기+파일 저장 경로 **10사례 통과**, `artifacts/http-validation/result.json`. 잘못된 파일8종은422·미디어 미저장, 정상2종은200·원본 바이트 일치. 검사기 실행 파일이 없으면503이며 헤더 검사만으로 대체 저장하지 않는다. 검사 중 별도 상태 조회도 응답했다. 이 수치는 사용자 방송의 지연/FPS 측정이 아니다.
- `artifacts/audio-validated-transfer/`와 `video-validated-transfer/`: 이전 구간 선택 → 검사 → 실제 저장 → 성공 응답 유실 → GET 확인 → HTTP206 범위 조회 → 서버 재시작 후 재조회 통과. 음성은 합성 발언부터 관객 선택·댓글/대댓글·삭제까지 연결했다. 모의 관객 응답을 사용했으며 실제 사용자 자료나 모델 호출은 없다.
- 합성 음성: 160,384바이트, SHA-256 `17e5991a5094a2bf782a21552ec9728ab91be624db65e9974dd8c73f7855dd65`. 합성 영상+음성: 163,888바이트, `aa896dc3cf81a4cb00065d98a7809a481ee4d2fc287021bf7c54ee88491399dc`. 실제15초를 디코딩하여 음성751프레임, 영상75프레임을 확인했다.

첫 검사는 런타임 복사가 끝나기 전에 실행되어 입력 파일 부재로 실패했고, 복사 종료 확인 후 재실행했다. 회귀 검사에서 기존 '409도3회 재시도' 기대1건이 새 정책과 충돌했다. 영구 오류1회 제출·마지막 GET·오류1회 표시로 기대를 갱신하고,429 재시도와 응답 유실 복구 검사를 함께 유지했다. 실패 로그를 통과 로그로 덮어쓰지 않았다.
