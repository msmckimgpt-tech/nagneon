# 선택 로컬 모델 준비

2026-09-16 추천 상위 3종을 이 머신에 설치하고 0.1.4 연결 및 실제 추론을 확인했다. **연결 성공과 서비스 대체 가능성은 다르다.** [최신 경량 모델 실측](LOCAL-LLM-VALIDATION-20260916.md)에 실패·제한, 짧은 worker 비교, 재실행 방법을 기록했다.

기본 제공처는 Codex 구독이다. 방송 설정 → 계정과 모델 연결 → **AI 제공처 선택**에서 Ollama로 전환할 수 있다. 모델별 적합성 확인이 필요하며 아래 실측 모델은 품질 기준에 미달했다.

1. [Ollama 공식 사이트](https://ollama.com/)에서 Windows 런타임을 설치한다.
2. PC 메모리에 맞는 로컬 GGUF 모델을 별도로 준비한다. 게임 화면을 함께 보려면 vision 지원 모델이 필요하다. 앱이 모델을 자동 다운로드하지 않는다.
3. 앱에서 **이 PC의 Ollama**를 고르고 모델명·로컬 주소·문맥 크기를 입력한 뒤 **선택한 제공처 적용**을 누른다. 설치된 모델 확인이 실패하면 기존 제공처를 유지한다. 방송·연습·로그인·모델 요청 중에는 전환할 수 없다.

앱에서 저장한 선택이 환경 변수보다 우선하며 다음 실행에도 유지된다. 최초 선택 전에는 아래 환경 변수를 사용할 수 있다. 개발 실행은 `.env`, 설치 버전은 실행 프로세스의 환경 변수를 사용한다.

```dotenv
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=설치한-모델의-정확한-이름
OLLAMA_CONTEXT_SIZE=65536
```

모델 이름은 `ollama list`에서 확인한다. 위 모델 이름은 자리표시자이며 추천 모델이 아니다. 문맥 크기는 4096~131072 안에서 모델이 지원하는 크기로 지정한다. 큰 문맥은 메모리를 더 요구한다. 예산 초과 안내가 나오면 지원하는 모델/문맥 크기 또는 참여 관객과 화면 입력을 조정한다. 이미지 토큰 사용량은 모델마다 달라 실제 장면 검증이 필요하다.

4. 방송 설정의 연결 화면에서 **연결 상태 새로고침**, **로컬 모델 응답 확인 · 1회**를 실행한다. 설치 확인과 한국어 인사 응답은 실제 게임 반응 품질·속도의 검증과 다르다.

클라우드 모델과 원격 서버는 이 어댑터에서 지원하지 않는다. localhost 서비스가 임의로 바뀌는 것까지 앱이 보장하는 네트워크 격리는 아니다. 웹 검색 옵션은 끈다. 화면 미지원 모델에는 이미지를 보내지 않고 설명을 표시한다. 마이크는 기존 로컬 음성 인식을 사용한다. 로컬 모델의 JSON 형식 오류·잘린 응답은 채팅으로 표시하지 않는다.

Codex로 돌아가려면 앱의 **AI 제공처 선택**에서 **ChatGPT 구독 · Codex**를 적용한다. 기존 계정과 `gpt-6-astra`/`low` 설정을 사용한다. 이 기능을 위해 기존 계정을 로그아웃할 필요는 없다.

선택은 앱 프로필의 `provider-choice.json`에 제공처·모델명·주소·문맥 크기만 저장한다. API 키는 저장하지 않는다.

### 실제 로컬 모델 시험 (2026-09-14)

별도 포트·프로필·모델 저장소에서 Ollama 0.34.0과 `qwen3-vl:2b-instruct`를 실행했다. RTX 2070 8GB, 문맥 65536, 기본 관객 지침 전체와 합성 도형 PNG를 사용했다. **이 2B 모델은 현재 앱의 대화·장면 인식용으로 권장하지 않는다.** 한국어 출력과 JSON 통과는 가능했지만 질문 반복, 잘못된 장면 설명과 근거 없는 취향 생성이 관찰됐다.

기본 f16 캐시는 CPU/GPU 분할 적재 후 두 요청 모두 60초 제한을 넘겼다. [공식 KV 캐시 설정](https://docs.ollama.com/faq#how-can-i-set-the-quantization-type-for-the-kv-cache)에 따라 시험용 Ollama 서버에 `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_KV_CACHE_TYPE=q8_0`, `OLLAMA_NUM_PARALLEL=1`을 설정하자 응답이 가능했다. 이는 Ollama **서버 실행 환경** 설정이며 앱의 환경 변수만 바꿔서는 적용되지 않는다. 다른 모델·PC의 품질이나 속도를 보장하지 않으며 기본 Codex 선택은 유지한다.

실제 추론에서 발견한 replyTo UUID 불일치를 고쳐, 로컬 생성 스키마를 앱의 Observation 검증 스키마에서 직접 만든다. 길이·범위·UUID 제약을 함께 전달하며 결과 검증도 유지한다. 스키마 통과가 응답의 사실성이나 자연스러움을 보장하지 않는다.

재현 도구는 `scripts/verify-ollama-live.mjs`다. 별도로 준비한 서버에 `OLLAMA_BASE_URL`, `OLLAMA_MODEL`을 지정하고 `node scripts/verify-ollama-live.mjs --image=<합성 PNG 경로>`를 실행한다. 모델을 자동 설치하거나 화면을 캡처하지 않는다. 매 실행의 원본 응답·시간·사용량은 독립 `artifacts/ollama-acceptance-*`에 저장되며 의미 품질은 따로 검토해야 한다. 이번 최종 시험은 `ollama-acceptance-WFu8sd/result.json`: 형식 2건 통과, 10.3초/5.6초, 의미 품질 미달이다. 실제 게임·물리 마이크와 다른 로컬 모델의 적합성 검증은 남아 있다.

같은 조건의 [Gemma 3 4B](https://ollama.com/library/gemma3:4b)도 시험했다. `ollama-acceptance-JBDtS6/result.json`에서 28.6초/16.5초로 형식은 통과하고 도형 종류·색은 설명했지만 채팅은 없었다. 이어 실제 Studio의 기본 관객·호명·대기열을 거친 합성 세션(`ollama-session-gvaZmV/result.json`)에서도 10.0초/14.1초 응답에 올바른 관객 채팅이 없었다. 첫 인사에는 침묵했고 두 번째에는 `streamer`를 발신자로 잘못 생성하여 전달되지 않았다. 따라서 이 모델 역시 현재 앱의 검증된 대체 모델로 추천하지 않는다. 단일 스키마 통과나 낮은 지연을 제품 적합성으로 확대하지 않는다. 시험 서버와 모델은 종료했으며 사용자 선택은 바꾸지 않았다.
