# 선택 로컬 모델 준비

기본 제공처는 Codex 구독이다. 방송 설정 → 계정과 모델 연결 → **AI 제공처 선택**에서 Ollama로 전환할 수 있다. 실제 모델 품질 검증은 아직 남아 있다.

1. [Ollama 공식 사이트](https://ollama.com/)에서 Windows 런타임을 설치한다.
2. PC 메모리에 맞는 로컬 GGUF 모델을 별도로 준비한다. 게임 화면을 함께 보려면 vision 지원 모델이 필요하다. 앱이 모델을 자동 다운로드하지 않는다.
3. 앱에서 **이 PC의 Ollama**를 고르고 모델명·로컬 주소·문맥 크기를 입력한 뒤 **선택한 제공처 적용**을 누른다. 설치된 모델 확인이 실패하면 기존 제공처를 유지한다. 방송·연습·로그인·모델 요청 중에는 전환할 수 없다.

앱에서 저장한 선택이 환경 변수보다 우선하며 다음 실행에도 유지된다. 최초 선택 전에는 아래 환경 변수를 사용할 수 있다. 개발 실행은 `.env`, 설치 버전은 실행 프로세스의 환경 변수를 사용한다.

```dotenv
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=설치한-모델의-정확한-이름
OLLAMA_CONTEXT_SIZE=65536
```

모델 이름은 `ollama list`에서 확인한다. 위 모델 이름은 자리표시자이며 추천 모델이 아니다. 문맥 크기는 4096~131072 안에서 모델이 지원하는 크기로 지정한다. 큰 문맥은 메모리를 더 요구한다. 예산 초과 안내가 나오면 지원하는 모델/문맥 크기 또는 참여 관객과 화면 입력을 조정한다. 이미지 토큰 사용량은 모델마다 달라 실제 장면 검증이 필요하다.

4. 방송 설정의 연결 화면에서 **연결 상태 새로고침**, **로컬 모델 응답 확인 · 1회**를 실행한다. 설치 확인과 한국어 인사 응답은 실제 게임 반응 품질·속도의 검증과 다르다.

클라우드 모델과 원격 서버는 이 어댑터에서 지원하지 않는다. localhost 서비스가 임의로 바뀌는 것까지 앱이 보장하는 네트워크 격리는 아니다. 웹 검색 옵션은 끈다. 화면 미지원 모델에는 이미지를 보내지 않고 설명을 표시한다. 마이크는 기존 로컬 음성 인식을 사용한다. 로컬 모델의 JSON 형식 오류·잘린 응답은 채팅으로 표시하지 않는다.

Codex로 돌아가려면 앱의 **AI 제공처 선택**에서 **ChatGPT 구독 · Codex**를 적용한다. 기존 계정과 `gpt-6-astra`/`low` 설정을 사용한다. 이 기능을 위해 기존 계정을 로그아웃할 필요는 없다.

선택은 앱 프로필의 `provider-choice.json`에 제공처·모델명·주소·문맥 크기만 저장한다. API 키는 저장하지 않는다.

현재 증거는 로컬 HTTP 규격 시험과 fixture 응답을 사용한 Electron 전환/복귀 검증이다. 이 PC에서는 PATH의 Ollama와 기본 11434 포트 응답을 확인하지 못했다. 실제 Ollama 설치·모델 추론·한국어 품질·VRAM/지연 검증은 미완료다.
