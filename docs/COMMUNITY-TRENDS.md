# 방송 밖 커뮤니티의 사실 입력과 개인 반응

공개 문화 수집기의 본문·URL·분석 시각은 최근 인터넷 화제의 게시 시각이나 화제 크기를 증명하지 않는다. 수집 경로는 `server/culture/trend-fact-schema.js`에 정의된 `TrendFact`와 `server/culture/trend-fact-context.js`의 검증·공개 변환을 재사용하며, 출처 URL, 게시 시각, 관측 시각, 관측 지표, 만료를 별도로 검증한다. 모델 응답이나 나그네온의 가상 글·댓글·추천은 이 사실 입력을 만들거나 인기도를 올리지 않는다.

현재 기본 상태는 **미연결**이다. `studio.social.trends.snapshot(now)`와 social 요약의 `trendInput`에 `disconnected`, `connected`, `synthetic`이 표시된다. 바깥 커뮤니티 화면에는 사실 입력 미연결·유효 근거 없음·합성 입력 상태가 표시된다. UI 연결 설정이나 자동 수집 타이머는 추가하지 않았다. 선택한 게임의 확인된 Steam appId를 사용하는 로컬 연결 코드에서 아래 명시적 호출을 사용할 수 있다. 계정·키·결제·인증 쿠키를 요구하지 않는다.

```js
await studio.social.trends.readSteam({
  appId: verifiedSteamAppId,
  game: gameName,
  now: () => studio.now(),
  signal: operationSignal,
});
```

이 호출은 공식 공개 API에 뉴스 최대 세 개와 게임 동접을 읽는 두 GET만 보낸다. 같은 입력 객체의 재시도는 성공·실패 모두 최소 한 시간 간격으로 제한한다. 외부 게시, 리디렉션, 로그인, 임의 URL 읽기, 사이트 본문 실행을 하지 않는다. 기존 공개 DNS/IP 고정과 문서 용량·시간 제한을 사용한다. 제한·오류·잘린 응답에는 미연결로 전환한다. 외부 본문은 전달하지 않고 공식 공지의 제목과 게시 시각만 사실로 사용한다. 제목 안의 명령도 비신뢰 데이터다.

공식 계약은 [Steam 뉴스 API](https://partner.steamgames.com/doc/webapi/ISteamNews)와 [Steam 게임 통계 API](https://partner.steamgames.com/doc/webapi/ISteamUserStats)를 따른다. 게임 동접은 **게임 관심도의 제한적인 대용 지표**이며, 특정 공지의 인기도·인터넷 검색량·최근 상승 추세를 뜻하지 않는다. 따라서 그 지표의 가중치를 최대 0.35로 제한하고 한 시간 뒤 버린다. 이슈별 댓글·조회·반응 지표는 입력 계약과 합성 검증만 지원하며, 실제 수집 어댑터는 아직 없다. 관측하지 않은 이슈 인기도를 대신 생성하지 않는다.

참여 점수는 관측량의 로그 정규화 × 인물의 명시적 관심사 일치 × 게시/관측 시각의 시간 감쇠다. 정규화 기준과 지연은 대화 빈도를 조절하는 제품 규칙이며 인터넷 전체를 측정한 통계가 아니다. 새 입력으로 시작하는 글과 같은 입력 세션의 댓글은 인물의 성격·가치 문자열에 게임/주제 태그가 실제로 포함된 경우만 후보가 된다. 입력에 포함되지 않은 저장된 사실 글은 기존 저장 문맥의 대화 규칙을 유지하며, 새 입력 연결이나 관심 지표를 요구하지 않는다. 저장된 근거의 유효성은 게시 경과일 대신 관측·만료 시각을 기준으로 판단한다. 인물 ID와 사실 ID에서 안정적으로 정한 서로 다른 참여 문턱과 3~30분의 도착 지연을 사용한다. 한 커뮤니티에서는 같은 사실로 글을 다시 만들지 않는다. 기존 개인·커뮤니티 간격, AI 허용/호출 예산, 읽음 해시, 취소와 프로필 세대 검사는 유지한다.

이슈별 지표는 관측 시각에서 6시간, 게시 시각에서 12시간 반감기로 식는다. 만료는 최대 24시간이다. 게임 동접의 관측 반감기는 한 시간이며 어댑터 만료도 한 시간이다. 이슈별 근거가 유효한 동안에는 몇 시간 뒤 들어온 사람도 기존 댓글에 답할 수 있고, 만료 뒤에는 자동 참여 후보와 늦은 모델 결과를 거절한다. 사용자 수동 댓글은 기존 기능대로 가능하다.

게시글에는 `trendFact`를 별도로 저장한다. API의 `externalFact`와 `externalFactStatus`는 사실 근거와 합성/관측/만료 상태를 표시하고, `text`와 댓글은 `fictional-personal-reaction`인 창작 반응이다. 사실 제목만으로 세부 패치 내용·원인·루머를 추론하지 않도록 지시하며, 출처 URL·숫자·미확인 인기/루머·최신 화제 등 위험 표현의 생성 반응은 보수적으로 보류한다. 이 필터는 모든 자연어 사실 오류를 판별하는 완전한 사실 검증기가 아니다.

목록에는 근거의 합성·만료 여부를 표시한다. 상세에는 출처 링크, 게시/관측/만료 시각, 지표 값·범위·출처·관측 시각을 글과 분리해 표시한다. 이슈 지표가 없거나 게임 동접만 있으면 **이슈 화제 규모: 미관측**으로 표시한다. 유효한 사실이 없으면 ‘최신 소식은 확인하지 않았어요’로 안내하며, API 새로고침이 없어도 UI가 기한을 확인해 만료 표시로 바뀐다. 입력 상태 변경은 기존 로컬 상태 전달 경로로 알리고, 상태의 `validUntil`이 지난 연결 수치도 유효한 최신 근거로 표시하지 않는다.

엄격한 저장 스키마의 새 `trendFact`를 처음 저장할 때만 `profile-format.json`의 최소 reader를 **4**, 최소 앱 버전을 **0.1.18**로 올린다. 기존 capability-specific 저장 경계를 그대로 사용하고 `shared/profile-reader.json`에서 현재 reader 능력을 읽는다. 장문 원본 때문에 이미 reader5가 필요한 프로필의 경계는 낮추지 않는다. 사실 글을 저장하지 않은 기존 프로필은 reader2/3 경계를 유지한다. reader3 앱은 새 프로필을 읽기 전에 거절하고 원본과 백업을 보존한다. 표식 저장 실패는 사실 글의 저장을 막으며, 데이터 저장 실패는 기존 완전한 거래와 보수적으로 올린 표식을 유지한다. 현재 앱의 재시작에서도 사실 근거와 표식은 남고, 외부 입력 연결은 미연결로 시작한다. 구버전으로 돌아가려면 이 기능을 쓰기 전의 백업을 별도 프로필로 사용해야 하며 새 기록을 덮어쓰거나 표식을 낮추지 않는다.

합성 입력은 `evidenceKind: 'synthetic'`으로 명시해야 하며, 이를 실제 연결 자료로 수용하지 않는다. 합성 예시는 다음과 같다. 실제 뉴스나 실제 이용자의 글을 재현한 것이 아니다.

- 사실: 합성 게임의 공식 업데이트 안내, 출처·게시/관측 시각·댓글 관측값·만료를 별도 입력.
- 퍼즐을 좋아하는 작성자: “안내 보니 퍼즐 구성이 궁금해. 나는 천천히 해보고 싶네.”
- 기존 댓글: “나는 퍼즐 배치 쪽이 더 궁금해.”
- 몇 시간 뒤 읽은 다른 인물: “늦게 읽었네. 나는 조작보다 퍼즐 구성이 궁금한데, 그 부분은 어때?”
- 관심 없는 산책 애호가는 후보에서 빠지고, 같은 사실의 점수는 댓글 뒤에도 계속 감소한다.

`test/community-trends.test.js`는 입력 검증, 관측량 차이/감쇠/관심사/개인 지연, API 요청 범위와 비신뢰 본문 배제, 미연결/늦은 결과, 글→댓글→늦은 답글, 미관측 인기도의 후보·모델 요청 없음, reader4 표식과 저장 실패·재시작을 검사한다. 저장 API를 통해 사실 형식 요구와 reader5 경계의 비감소를 검사한다. `test/community-fact-ui.test.js`는 미연결·합성·미관측·만료·잘못된 출처 표시를 검사한다. 실제 공개 API의 연결·뉴스 품질·실제 모델의 대화 품질을 합성 검사로 대신하지 않는다.

화면의 사실 검증과 정규화도 같은 저장 문맥 모듈을 재사용한다. 실제 공개 API 연결·실제 모델 대화·설치 앱 검증은 이 기능의 합성 회귀 검사와 별개다.
