# 이어지는 방송과 관객의 초대장

2026-09-13. 이번 기능은 현실의 방송 연습에 더해, 규모와 설정에 제한받지 않고 관객들과 연속 방송을 만드는 경험이다. 실제 외부 행사·인물·시청자 유입을 실행하지 않는다. 판매 목표는 계속 진행 중이다.

## 사용 흐름

방송 놀이터 → 이어지는 방송에서 시즌을 기획한다. 이름과 세계관을 자유롭게 적고 서가에 저장한다. AI 방송을 켜고 현재 관객 중 1~8명을 선택해 회차를 연다. 미선택이면 최대 6명을 자동 선택한다. 각 회차는 세 장면이며, 진행 멘트·자유 대화·기존 마이크를 함께 사용할 수 있다. 장면 생성마다 모델 1회, 자유 대화는 기존 방송 호출 한도를 공유한다.

세 기획은 각각 3회차/9장면을 거치며 두 갈림길과 두 피날레가 있다. 모든 길을 합치면 15개 회차 설정, 45개 장면 지침, 12개 완주 경로다.

| 기획 | 갈림길 | 피날레 기념품 |
|---|---|---|
| 우리 방 첫 시즌 | 새벽 라디오 또는 문화제 → 편지 또는 앙코르 | 다음 계절의 편지 / 우리 방 앙코르 티켓 |
| 별빛 원정대 | 고요한 도서관 또는 별들의 항구 → 귀환 또는 갈라 | 채팅호 항해일지 / 별빛 원정대 휘장 |
| 크루 리그 | 라이벌전 또는 합숙 → 결승 또는 성장 다큐 | 우리 크루 리그 패치 / 크루 성장 다큐 포스터 |

선택은 다음 회차를 실제로 바꾼다. 완료된 선택을 수정하는 기능은 없다. 다른 길은 새 시즌으로 시작한다. 여기서 쉬어가기·방송 종료·앱 재시작 후에도 진행과 대화가 남지만, 방송이나 모델 호출은 자동 재개하지 않는다. 출연진은 재개할 때 현재 관객으로 바꿀 수 있다. 완결한 회차는 날짜·참여자·대화가 있는 핫클립으로 만들고 기존 댓글/대댓글 기능을 사용한다. 이 기념품은 서가의 기록이며 구매 능력이나 포인트를 주는 보상이 아니다.

## 관객이 제안하는 다음 방송

관객에게 기획 맡기기는 현재 함께하는 관객의 공개 채팅 또는 입장 이후 스트리머 발언에서 출처를 고르고, 그 관객의 말투로 한 장의 초대장을 생성한다. 제안에 원문·시각·메시지 ID·가상 연출 여부를 기록한다. 현재는 공개 대화 기반이며 외부 커뮤니티 글·실제 클립 내용 분석을 통해 자율적으로 기획하는 단계는 아니다. 사적 인터뷰를 공개 출처로 사용하지 않는다.

시즌 기획 선택은 서버의 단순 주제 규칙(우주/원정, 도전/리그, 그 외 우리 방)에 따른다. 모델이 임의의 새 분기 그래프를 작성하지 않는다. 제안의 구체적인 표현과 이유는 모델이 만든다. 수락하면 시즌 초안과 초대장의 연결을 하나의 저장 작업으로 확정한다. 같은 수락을 재전송해도 시즌이 중복 생성되지 않는다. 내일 다시 보기는 24시간 보류하며, 그 사이 별도 버튼으로 다시 펼칠 수 있다. 거절·보류는 친밀도나 포인트를 깎지 않는다.

자동 제안은 기본 꺼짐이다. 사용자가 켰을 때만 라이브 방송 10분·공개 메시지 20개 이후, 응답·다른 기획·대기 채팅이 없는 시간에 시도한다. 방송당 최대 1회, 직전 시도와 최소 1시간 간격이며 세션 호출 한도를 넘지 않는다. 실패한 시도도 디스크에 남겨 반복 호출을 막는다. 오프라인·절전 복귀 시 밀린 제안을 한꺼번에 생성하지 않는다. 미처리 초대장 6개에서는 새 생성을 멈춘다. 모델 실패 시 사용된 구독 호출을 되돌릴 수는 없다.

## 저장과 경계

- `shared/seasons.js`: v1 기획 정의. 저장된 경로가 가리키므로 기존 판본은 변경하지 않고 새 ID/판본을 추가한다.
- `server/seasons-schema.js`: 시즌/회차/분기/초대장 참조·중복·길이·완결 검증.
- `server/seasons.js`: 저장 성공 후에만 메모리 확정, 호출 취소 세대, 현재 출연자 재검사, 초대장과 시즌의 원자적 연결.
- `seasons.json`: 기존 JsonStore의 임시 쓰기/세대 백업/손상 보존 적용. 시즌 12개, 초대장 24개, 회차당 최근 대화 120개. UI 공개 상태는 회차당 최근 12개를 미리 보기로 제공한다. 전체 보존 기록은 `GET /api/seasons/:id`와 내보내기의 `seasonsArchive`에 있다. 장기 무제한 원본 대화 보존은 아니다.
- 시즌 활성 중 일반 발언과 단계 생성에 가상 맥락을 전달한다. 게임 관찰 상태·게임 지식·자동 하이라이트·포인트 보상으로 받아들이지 않는다. 공개 메시지에는 `fictional` 표식, 개인 기억에는 가상 기획 방송 접두어가 남는다.
- 새 출연진은 자신의 기억과 이번 입장 이후 채팅 패킷을 받는다. 이전 회차의 선택/진행 멘트는 읽은 가상 기록으로 제공하고 본인의 직접 목격이라고 주장하지 않게 지시한다. 여러 관객 패킷이 한 모델 입력에 함께 들어가므로 비밀 격리가 아니다.
- 기획 방송과 시즌을 동시에 열 수 없다. 시즌 종료/쉬어가기 이후 늦게 도착한 응답과 대기 반응을 취소한다. 화면·마이크 연결의 기존 중지 동작은 그대로 사용한다.

## 검증과 관찰

`artifacts/seasons-package.log`: 전체 155개 Node 검사 + TS/Vite 빌드 + 독립 배포 생성 통과. 시즌 전용 19개에는 12개 완주 경로, 저장 실패/재시도, 실제 서버 재시작, 출연진 차단·이탈, 늦은 응답, 호출 한도, 자동 제안/보류/수락, 전체 내보내기와 손상 그래프 시작 거부가 있다. `seasons-unit-retry.log`에 원본을 보존했다.

`artifacts/seasons-desktop-test.json`: Electron UI 흐름 7개, 합성 모델. 생성·입장·세 장면·선택·서버 재시작·피날레·핫클립·초대장 보류/수락·900px 화면에서 페이지 가로 넘침 없음. 기존 확장 7개 흐름도 `seasons-expansion-output.log`에 통과했다. 실제 마이크/게임 실사용 증거는 아니다. 초기 UI 스크립트의 렌더 완료 전 입력 및 재시작 중 모든 창 닫힘에 따른 Electron 기본 종료를 고친 후 통과했다. 제품 오류로 혼동하지 않는다.

`artifacts/seasons-live-result.json`: 실제 Astra low로 별빛 원정 9장면과 관객 제안 1회. 키보드로 작성한 한국어 진행 멘트이며 실제 음성이나 게임을 쓰지 않았다. 모모의 휴식 취향, 각보는고양이의 탐사/패턴 취향, 팝콘도둑의 함내 방송 역할이 다음 회차에서 이어졌다. 등장하지 않은 관객을 억지로 발언시키지 않는 현재 출석 필터도 유지됐다. 잔액 60, 게임 지식 비어 있음, 실제 관찰 상태 null을 확인했다. 지연은 10.524~15.354초였다. 좋은 한 번의 샘플이며 장기 자연스러움 합격을 의미하지 않는다.

실제 샘플에서 스트리머가 이미 항로를 말했는데 장면 지침에 따라 다시 선택을 묻는 반응이 한 번 있었다. 반복 질문 억제와 장면 진행 멘트 적응, 중단 후 화면 우선순위·저장 정책·대형 관객 장기 평가가 다음 개선 대상이다. 이 평가는 출력 원문을 읽은 정성 관찰이며 계량적인 만족도 조사로 제시하지 않는다.

새 독립 배포는 `release/2026-09-12T21-26-57-900Z/app/BACKSEAT-win32-x64`이다. 2,437개 파일, 1,583,225,054바이트, 미서명. `seasons-package-integrity.log`: 파일 전체 SHA256/핵심 원본 20개/fuses 일치. `seasons-packaged-runtime.log`: 개발 PATH 제외, 음성 준비 5.219초, 9.4초 합성 한국어 전사 2.204초, 번들 공식 CLI의 실제 Astra 응답 9.533초. 이 추가 1회는 위 시즌 10회와 별개다.

`artifacts/seasons-native-test.json`: 빈 프로필의 실제 배포 창에서 신규 안내 건너뛰기·시즌 카탈로그·초안 저장·seasons.json 확인·정상 종료를 검증했다. 종료 후 해당 배포 경로 프로세스 0개다. `seasons-native-saved.jpg`는 실제 창이며 전체 회차 수행은 별도 Electron 검증이다. 사용자 앱은 기존 11관객과 설정을 유지한 채 새 시즌 페이지를 열어두었다.
