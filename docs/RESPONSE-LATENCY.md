# 첫 채팅의 중복 대기 제거

2026-09-14. 기준 `c555a32cccbf518630a2a0c7fbf41563e1fa219e`, 작업 `codex/response-latency`, 경로 `G:/dev/ai/00_game_backseat-worktrees/response-latency`.

[실제 Steam 전투](LIVE-REACTION-ACCEPTANCE.md)에서 발언 답변까지 약 14초가 걸렸다. 기존 `Studio.accept`는 모델 반환 후 첫 채팅에도 600~2,200ms의 반응 간격을 추가했다. 모델을 이미 오래 기다린 경우에도 같은 대기를 다시 부과하는 것이 이번 수정 대상이다.

일반 라이브 요청의 실제 시작 시각을 전달하고, 첫 **허용된** 채팅의 반응 간격에서 이미 기다린 시간을 뺀다. 느린 응답은 다음 250ms 전달 주기에 표시할 수 있고, 빠른 응답은 남은 반응 시간만 기다린다. 두 번째 이후 메시지는 기존 간격을 유지하므로 여러 관객이 한꺼번에 쏟아지지 않는다. 옛 프레임의 촬영 시각을 대기 시간으로 사용하지 않는다. 슬로우 모드·목격 범위·금칙어·중복·훈수·스포일러·만료·취소 검사를 유지하며, 리허설과 별도 기획의 간격은 변경하지 않는다.

모델·추론 수준·관객 프롬프트·출력 스키마와 전역 계정 설정은 변경하지 않았다. 아직 완료되지 않은 JSON을 채팅으로 내보내는 기능도 아니다.

## 실제 모델 비교

`node scripts/verify-response-latency.mjs --live --label=baseline` 및 `--label=candidate`로 공식 CLI **gpt-6-astra / low**를 각각 4회 호출했다. 별도 메모리 프로필의 합성 키보드 잡담이며 실제 Studio의 250ms 타이머, 단조 시계의 CLI 이벤트와 서버 메시지 시각을 기록했다. 무작위 지연은 두 실행 모두 0.5로 고정했다. 사용자 기록과 물리 장치는 사용하지 않았다.

| 사례 | 기존 모델 처리 / 이후 첫 전달 대기 | 수정 모델 처리 / 이후 첫 전달 대기 |
|---|---:|---:|
| 비 오는 날 휴식 질문 | 10,249 / 1,495ms | 9,668 / 68ms |
| 추리 소설 후속 질문 | 10,815 / 1,445ms | 9,954 / 72ms |
| 두 관객의 휴식 취향 | 11,461 / 1,542ms | 23,009 / 21ms |
| 조용히 기다려 달라는 요청 | 7,878ms / 채팅 없음 | 8,043ms / 채팅 없음 |

각 실행의 생성/전달 수는 1·1·2·0이었다. 전체 원문을 확인했다. 모모는 자기 휴식 취향과 결말을 먼저 읽지 않는다는 생각으로 답했고, 팝콘요정은 코미디 영화를 골랐다. 쉬겠다는 요청에는 답하지 않았다. 불필요한 후원·관객 생성·성향 변경·클립·전사 교정·추천은 없었다. 두 관객의 실제 전달 간격은 기존 1,505ms, 수정 1,503ms로 유지됐다.

**전체 모델 지연 개선이나 실시간 응답 달성을 의미하지 않는다.** 수정 후 세 번째 모델 호출은 23초였고, 전체 첫 답변은 9.763 / 10.034 / 23.032초였다. 순서를 교차하지 않은 소수 사례로 모델 속도를 비교할 수 없다. 확인한 개선은 모델 완료 후 서버가 추가하던 대기 제거이며, 화면 렌더링·마이크 전사·발화 종료 기준 시간은 측정하지 않았다.

원본: `artifacts/response-latency-baseline-result.json`, `artifacts/response-latency-candidate-result.json` 및 각각의 `folder/result.json`. 입력·전체 출력·사용량·소스 해시·CLI 시작/완료·큐 예정 시각·실제 전달·진단 값이 있다. 초기 2회 프로브 `artifacts/probe.json`에서 출력 길이를 low로 설정한 요청은 8.920→10.701초로 빨라지지 않아 제품에 적용하지 않았다. 공식 [JSONL 실행](https://learn.chatgpt.com/docs/non-interactive-mode)과 [요청별 설정](https://learn.chatgpt.com/docs/config-file/config-reference)을 참고했다. 원시 계정 진단이나 토큰 파일은 읽거나 보관하지 않았다.

## 진단과 검증

매니저 응답 진단에 **응답 완료 후 첫 채팅 전달 대기**의 중앙값·95백분위와 표본 수를 추가했다. 실제 채팅을 전달한 요청만 집계하며 모델 침묵·실패·아직 대기 중인 응답은 제외한다. 슬로우 모드와 서버 처리 대기를 포함한다. 기존 시간/건수만 사용하며 원문·신원·장치 자료를 추가 수집하지 않는다.

- 수정 전 회귀 6개 중 3개 실패로 중복 대기를 재현했다 (`artifacts/timing-before.log`). 최종 `test/response-latency.test.js`는 느린/빠른 반환, 관객 간 간격, 필터 뒤 첫 유효 반응, 슬로우 모드·이탈·차단·종료, 오래된 장면, 리허설/기획 경계를 확인한다.
- 전달 대기의 별도 집계는 실제 전달 표본만 포함하고 초기화에서 지워지는지 검사했다. 전체 **581개 테스트 및 TypeScript/Vite 빌드 통과**, `artifacts/check.log`.
- 실제 Electron 매니저에서 새 문구와 표본 수, 인증된 JSON 다운로드, 오류 표시 후 재조회 복구를 통과했다. 합성 지표이고 추가 모델 호출은 0회다. `artifacts/reaction-diagnostics-ui-result.json`과 `reaction-diagnostics-ui-1789334495911/panel.png`에서 배치를 확인했다.
- 첫 UI 실행은 PowerShell이 GUI 실행 직후 반환하여 로그 파이프가 끊긴 `EPIPE` 오류였다. Computer Use로 실제 오류 창을 확인했다 (`artifacts/ui-launcher-error.txt`, `ui-launcher-error-repeat.txt`). watchdog 실패를 성공으로 처리하지 않았다. 소유 PID·생성 시각·실행 경로를 확인해 실패한 검증 프로세스만 종료하고, 파일 핸들을 유지하는 Node 실행기로 재검증했다 (`artifacts/run-ui.mjs`, `ui-stable.log`). 제품 코드를 바꿔 검사를 우회하지 않았다.

별도 통합 worktree의 `npm ci`, 필수 검사, main 및 작업 브랜치 push·원격 일치·CI는 `artifacts/response-latency-release-result.json`으로 연결한다. 사용자 실행본/설치 패키지를 교체하지 않았다. 다음 단계는 갱신된 패키지의 실제 게임·음성 응답 검증과 모델 처리 구간의 추가 개선이며 Steam 판매 수용 기준은 계속 남아 있다.
