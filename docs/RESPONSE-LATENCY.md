# 첫 채팅의 중복 대기 제거

2026-09-14. 기준 `c555a32cccbf518630a2a0c7fbf41563e1fa219e`, 작업 `codex/response-latency`, 경로 `G:/dev/ai/00_game_backseat-worktrees/response-latency`.

[실제 Steam 전투](LIVE-REACTION-ACCEPTANCE.md)에서 발언 답변까지 약 14초가 걸렸다. 기존 `Studio.accept`는 모델 반환 후 첫 채팅에도 600~2,200ms의 반응 간격을 추가했다. 모델을 이미 오래 기다린 경우에도 같은 대기를 다시 부과하는 것이 이번 수정 대상이다.

일반 라이브 요청의 실제 시작 시각을 전달하고, 첫 **허용된** 채팅의 반응 간격에서 이미 기다린 시간을 뺀다. 느린 응답은 다음 250ms 전달 주기에 표시할 수 있고, 빠른 응답은 남은 반응 시간만 기다린다. 두 번째 이후 메시지는 기존 간격을 유지하므로 여러 관객이 한꺼번에 쏟아지지 않는다. 옛 프레임의 촬영 시각을 대기 시간으로 사용하지 않는다. 슬로우 모드·목격 범위·금칙어·중복·훈수·스포일러·만료·취소 검사를 유지하며, 리허설과 별도 기획의 간격은 변경하지 않는다.

모델·추론 수준·관객 프롬프트·출력 스키마와 전역 계정 설정은 변경하지 않았다. 아직 완료되지 않은 JSON을 채팅으로 내보내는 기능도 아니다.

## 실제 모델 비교

각 실행의 생성/전달 수는 1·1·2·0이었다. 전체 원문을 확인했다. 모모는 자기 휴식 취향과 결말을 먼저 읽지 않는다는 생각으로 답했고, 팝콘요정은 코미디 영화를 골랐다. 쉬겠다는 요청에는 답하지 않았다. 불필요한 후원·관객 생성·성향 변경·클립·전사 교정·추천은 없었다. 두 관객의 실제 전달 간격은 기존 1,505ms, 수정 1,503ms로 유지됐다.

**전체 모델 지연 개선이나 실시간 응답 달성을 의미하지 않는다.** 수정 후 세 번째 모델 호출은 23초였고, 전체 첫 답변은 9.763 / 10.034 / 23.032초였다. 순서를 교차하지 않은 소수 사례로 모델 속도를 비교할 수 없다. 확인한 개선은 모델 완료 후 서버가 추가하던 대기 제거이며, 화면 렌더링·마이크 전사·발화 종료 기준 시간은 측정하지 않았다.

원본: `artifacts/response-latency-baseline-result.json`, `artifacts/response-latency-candidate-result.json` 및 각각의 `folder/result.json`. 입력·전체 출력·사용량·소스 해시·CLI 시작/완료·큐 예정 시각·실제 전달·진단 값이 있다. 초기 2회 프로브 `artifacts/probe.json`에서 출력 길이를 low로 설정한 요청은 8.920→10.701초로 빨라지지 않아 제품에 적용하지 않았다. 공식 [JSONL 실행](https://learn.chatgpt.com/docs/non-interactive-mode)과 [요청별 설정](https://learn.chatgpt.com/docs/config-file/config-reference)을 참고했다. 원시 계정 진단이나 토큰 파일은 읽거나 보관하지 않았다.
