# 첫 화면 연결과 전환 복구

2026-09-14. 작업 `codex/capture-preparation-recovery`, 기준 `6fe3331d84269f30dea6ef511264ba4942f37c64`. [실제 게임 대화 검증](LIVE-CONVERSATION-ACCEPTANCE.md)에서 처음 화면이 도착하기 전 대기가 확인돼 연결 수명 주기를 조사했다. 모델 응답 속도를 개선했다고 주장하는 변경은 아니다.

## 발견과 변경

기존 `useMedia.share`는 새 스트림이 도착하면 기존 화면·소리를 먼저 끊고 `capture.play()`를 기다렸다. 이때 준비 상태·취소 버튼·재생 기한이 없고, 화면 트랙 종료 처리는 재생 완료 후에 등록했다. 창이 닫히거나 첫 프레임이 멈추면 무기한 대기할 수 있었다. 수정 전 실제 Electron 렌더러에 지연된 캡처 요청을 넣어 준비/취소 UI 부재를 재현했다 (`artifacts/preparation-baseline-result.json`).

- 연결 요청과 첫 프레임 대기를 표시하며 사용자가 취소할 수 있다. 준비 중 중복 선택은 차단한다.
- 사용자가 데스크톱 선택창에서 이미 고른 대상의 연결은 30초, 스트림을 받은 뒤 첫 영상 재생은 15초까지 기다린다. 브라우저 자체 선택창은 사용자의 선택을 기다리며 앱에서 취소할 수 있다.
- 취소·시간 초과·디코더 실패·준비 중 창 종료는 해당 후보의 모든 트랙과 재생 요소를 해제한다. 취소 후 뒤늦게 도착한 스트림도 즉시 해제한다. OS의 캡처 API 자체가 취소됐다는 뜻은 아니다.
- 재생 가능한 크기의 첫 프레임이 준비돼야 새 화면으로 전환한다. 그전에는 기존 화면과 소리를 유지한다. 전환 성공 후에만 이전 캡처·클립 업로드와 이전 화면 반응을 종료한다.
- 소리만 선택한 경우에는 라이브 오디오 트랙을 확인하며 영상 재생·미리보기·첫 프레임 대기가 없다. 마이크는 별도다. 기존 출력 소리를 끄는 명령도 준비 중 후보를 취소하므로 늦은 연결로 소리가 되살아나지 않는다. 소리 전용 공유를 끌 때는 더 이상 쓰지 않는 원본 영상 트랙도 함께 해제한다.

화면 선택 목록의 픽셀 없는 조회와 썸네일 조회 분리는 유지한다. 크기 0의 썸네일 요청이 캡처 처리 시간을 줄인다는 [Electron 공식 문서](https://www.electronjs.org/docs/latest/api/desktop-capturer/)와 구별해, 이번 변경은 선택 **후** 준비·전환·복구를 다룬다. 프레임 준비 확인은 재생 성공, `readyState`와 실제 영상 크기를 함께 사용한다. 프레임 콜백의 동작 범위는 [MDN 영상 API](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)를 참고했으나 프레임마다 새 콜백을 도입하지는 않았다.

## 검증 범위

- `test/capture-preparation.test.js`: 가상 시계로 취소/늦은 도착, 네이티브 연결 기한과 브라우저 선택 대기 차이, 첫 프레임 조건, 재생 기한, 창 종료, 디코더 오류, 소리 전용 흐름 7개 검사.
- `scripts/verify-capture-preparation.cjs`: 실제 React/Electron 렌더러와 합성 캡처·오디오로 준비/취소, 기존 화면 유지, 실패 후 재연결, 실제 15초 기한, 소리 전용 선택, 방송 종료를 검사한다. 합성 IPC·미디어이므로 실제 장치 증거로 계산하지 않는다.
- `scripts/verify-capture-lifecycle.cjs`: 이동 중 미리보기 재생이 거절돼도 영상·소리는 계속되고, 복귀·방송 종료·재생 오류·늦은 도착 처리가 유지되는 5개 회귀 흐름.
- `scripts/verify-capture-preparation-native.cjs`: 자신이 만든 빨강/파랑 Windows 창만 앱 선택창에서 골라 실제 캡처한다. 영상 픽셀과 크기, 방송 인식 경로 도착, 이전 트랙 종료, 선택한 창 종료 시 미리보기 해제를 확인한다. 시스템 소리·물리 마이크·모델 요청은 하지 않는다. `--package`는 새 ASAR를 검증·추출해 포함된 화면/서버/캡처 코드를 Electron 검사 실행기에서 실행한다. 배포 EXE의 설치·실행 검사는 아니다.

출력은 각각 `artifacts/capture-preparation-result.json`, `capture-lifecycle-result.json`, `capture-preparation-native-result.json`과 해당 `base` 하위 원본에 있다. 숨긴 창의 첫 `capturePage` 이미지는 이전 합성 프레임을 보여 시각 검증에 쓰지 않았다. 창을 표시하고 다음 두 번의 렌더링 프레임을 기다린 이미지에서 준비 안내와 취소 버튼을 직접 확인했다. 1260×900 창의 준비 영역 603px에서 가로 넘침 없이 취소 버튼이 영역 안에 있음을 확인했다.

첫 전체 검사에서는 새 훅 의존성이 마이크 테스트 실행기의 명시적 import 목록에 없어 6개가 실패했다. 실제 모듈을 목록에 추가했다. 이전 미리보기 검사는 불필요한 초기 `play()` 두 번을 전제로 했는데 이제 준비 후 한 번만 호출하므로, 대기 중인 미리보기 한 개로 동일한 화면 이동 경쟁을 검사하도록 바꿨다. 실패 원본은 `artifacts/check-first-failure.log`, `lifecycle-first-failure.json`에 보존했다. 네이티브 첫 검사도 서버 종료 요청 완료를 기다리기 전 상태를 검사해 실패했으며, 서버의 실제 종료 상태를 기다리도록 보강했다 (`native-first-result.json`).

## 배포와 남은 범위

첫 패키지 런타임 증거 재사용은 `conversation-rhythm.js`의 바이트 차이 때문에 거절됐다 (`artifacts/package-continuity-rejected.json`). 판정을 우회하지 않고 새 ASAR에서 Whisper·YAMNet·공식 CLI와 실제 Astra low를 실행했다. 합성 WAV 전사 2,394ms, 소리 4,736ms, 모델 9,842ms였고 해당 입력 한 건의 값이다. 물리 마이크나 게임 중 발언 응답 시간은 아니다.

최종 소리 전용 종료까지 반영한 `npm run check`는 566개 테스트와 TypeScript/Vite 빌드를 통과했다 (`artifacts/check-final-all.log`). 실제 Electron 렌더러의 준비·복구 9개 흐름과 기존 수명 주기 5개 흐름도 통과했다. 소리 전용 종료는 오디오뿐 아니라 사용하지 않는 영상 트랙의 종료까지 확인했다.

최종 패키지는 이 worktree의 `release/2026-09-13T20-08-41-598Z/app/BACKSEAT-win32-x64`다. ASAR SHA-256은 `cbe0377a31acd1fad0a8f6956d1af2df68e3bde39cd062c48cd06da0a8fa221b`이며 2,452개 배포 파일, 76개 원본 일치와 실행 퓨즈를 검사했다. 첫 패키지에서 실제 실행한 런타임과 최종 패키지의 2,388개 런타임 파일·어댑터 비교에 변경이 없어 앞선 Whisper/YAMNet/Astra 증거의 재사용 조건을 통과했다. 최종 패키지에서 실제 모델을 다시 호출했다는 뜻은 아니다.

최종 ASAR의 코드를 실행한 Windows 캡처 검사는 빨강/파랑 창을 각각 1,466ms/1,404ms에 연결하고 484×310 영상 픽셀, 서버 인식 경로 도착, 이전 트랙 종료와 선택 창 종료 후 해제를 확인했다. 이는 추출한 배포 코드의 Electron 실행이며 배포 EXE 설치·시작 검증과는 구별한다. 패키지와 원본 결과·파일 해시, 통합 커밋·원격/CI는 `artifacts/capture-release-result.json`에서 연결한다. 모든 제품 변경은 별도 worktree에서 수행하며 사용자 원본 앱 데이터와 게임 저장은 접근하지 않는다.

실제 Windows 테스트 창의 연결은 약 1.4~1.5초였지만 서로 다른 조건의 게임 메뉴 대기와 직접 비교한 성능 개선률은 아니다. 썸네일을 가져올 때 일부 전체 화면의 DXGI 경고는 계속 발생했다. 게임별 독점 전체화면·최소화·GPU/DPI 차이, 장시간 소리/마이크 장치 교체, 실제 모델의 전투 반응과 출시 서명·설치·Steam 검토는 남아 있다. 이 단계는 Steam 출시 준비 전체의 완료가 아니다.
