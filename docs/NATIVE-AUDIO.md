# 원격 원음 이해

원격 원음 이해는 아직 정식 배포하지 않은 개발 기능이다. 실제 제공처 연결, 물리 마이크, 게임 동시 실행 및 설치 검증을 통과하기 전에는 릴리즈하지 않는다.

## 연결과 비용

마이크 원음은 공식 OpenAI Realtime API의 `gpt-realtime-2.1`에 전달하고, 청취 해석을 기존 관객 반응 경로에 넣는다. 관객 모델 선택은 그대로 유지한다. GPT-6 Sol을 사용하려면 관객 모델 설정에서 선택한다.

ChatGPT 구독 로그인과 원음 API 인증은 별개다. API 키와 원음 전송·사용량 동의가 모두 있어야 연결한다. 키는 앱 메모리에만 두며 설정 파일에 저장하지 않는다. 기존 OpenAI 환경 키도 같은 동의 조건을 적용한다. 동의를 해제하거나 로컬 모드로 바꾸면 보유 키를 지운다. 유료 API 연결을 원하지 않는 경우 키 발급이나 결제 설정을 진행할 필요가 없다.

공식 Codex CLI 0.156.1과 별도 폴더의 0.157.1에서 계정·모델·실험 원음 인터페이스를 확인한 결과, GPT-6 Sol의 입력은 텍스트와 이미지이며 해당 원음 세션은 API 키 인증을 요구했다. 시작 RPC의 접수 응답 뒤 오류 알림이 발생할 수 있으므로 RPC 성공만으로 연결 성공을 판정하지 않는다. 구독 토큰을 추출하거나 비공개 음성 주소를 호출하는 대체 경로는 구현하지 않는다.

데스크톱 ChatGPT Voice의 구독 이용 범위는 외부 앱의 음성 API 이용 권한과 구분한다. App Server는 실험 인터페이스이며 운영용 지원 대상이 아니다.

## 구독 Voice 연결의 검증 범위

2026-09-27 Windows ChatGPT 데스크톱 26.924.2738.0과 번들 호스트 0.158.0-alpha.2.1에서 실제 마이크 발언으로 격리된 로컬 STDIO MCP 진단 도구를 한 번 호출했다. 서버가 새로 만든 확인값, 로컬 수신 기록, 공식 작업의 완료된 도구 호출이 일치했으며 Voice 종료도 공식 이력에서 확인했다. 이 시험에는 기존 구독 포함량을 사용했고 API 키·추가 크레딧·공개 서버·화면 출력 수집을 전달 경로로 사용하지 않았다. 관객 Sol 호출과 나그네온 접수는 이 시험에 포함하지 않았다.

이 결과는 위 API 구현과 별개의 데스크톱 Voice 경로다. [공식 Voice 안내](https://learn.chatgpt.com/docs/features/voice)는 작업과 도구를 음성으로 지시하는 기능을 설명한다. 실제 MCP 호출에는 도구 수신 시각과 작업 메타데이터가 있었지만 원본 발화 시작·종료 시각, 원음 구간 ID, 원음 재제출 참조가 없었다. 공식 호스트의 `thread/timeline/list` 조회에서는 전사 항목 ID·세션 ID·이력 위치·정상 종료를 확인했다. 이력 위치는 저장 순서이며 발화 시각이나 원음 구간에 대한 보장이 아니다.

후속 격리 시험에서는 실제 Baba Is You 창만 캡처해 전사문과 함께 구독 연결의 `gpt-6-sol`에 전달했다. 게임 화면은 비디오 트랙 하나로 제한했고 시스템 소리와 로컬 음성 추론은 사용하지 않았다. 메뉴 화면에 대한 시청자 채팅 표시와 실제 퍼즐의 규칙·캐릭터·글자 블록에 대한 모델의 장면 설명을 확인했다. 화면은 접수 또는 처리 시점에 캡처했으므로 원래 발언 당시 화면과 일치한다고 보장하지 않는다. 이 검사는 설치된 앱의 일반 사용자 흐름과 별도인 시험 경로다.

자동 전달은 두 경로를 구분해 검사했다.

- Voice 모델에 MCP 전달을 맡긴 시험에서는 5개 발언 중 첫 발언이 도구 입력 형식 오류로 접수되지 않았다. 1개는 Voice 중에 접수됐고 3개는 종료 뒤에 접수됐다. 2개 접수에서 실제 시청자 채팅을 확인했지만, 이 방식으로 연속 발언의 즉시 전달을 보장할 수는 없다.
- 공식 실험 이력 API의 사용자 전사 항목을 읽는 제한된 로컬 어댑터에서는 3개 기록 중 2개가 Voice 종료 전에, 마지막 1개가 종료 후에 접수됐다. 원본 항목 ID와 최종 전사문이 접수 기록과 일치했다. 첫 관측부터 접수까지는 8~392 ms였으며, 이는 발화부터 접수까지의 지연이 아니다. 각 입력의 실제 게임 이미지가 Sol에 전달됐고 처리에는 9.1~11.5초가 걸렸다. 이 3회에는 모델이 채팅을 생성하지 않았으므로 장면 이해 성공을 시청자 채팅 표시 성공으로 바꾸어 기록하지 않는다.

이력 페이지는 최신 페이지부터 반환되고 각 페이지 내부는 시간순이었다. 초기 어댑터가 과거 페이지의 커서를 재사용해 새 기록을 놓친 오류는 매 조회를 최신 페이지부터 시작하도록 수정했다. 새 기록 삽입, 같은 문구를 가진 별도 항목의 순서·중복 처리, 이력 연결 확인 실패를 합성 기록으로 검사했다. 오류가 있던 시험의 접수 0건은 제공처의 전달 불가능 근거로 사용하지 않는다. 대화 UI·DOM·클립보드를 읽어 전사를 추출하지 않았다.

답변 스피커를 수동으로 음소거한 뒤 소리가 들리지 않았다는 실사용 확인을 받았다. 새 Voice 세션에서 음소거가 유지된다는 보장은 확인하지 못했다. 발언과 답변 텍스트는 계속 생성될 수 있으며, 답변 오디오 차단과 발언 자동 전달은 별도의 검증 항목이다. 게임을 실제 조작한 앞선 짧은 시험에서 끊김·입력 지연·소리 문제가 없었다는 사용자 관측은 있지만, 고부하 게임이나 장시간 자원 영향은 미검증이다.

확인한 전달·이력 경로에는 원본 발화 시각, 정정 관계, 처리한 원음 범위, 미전달 발언 목록과 원음 재전송 계약이 없다. 서버가 만든 ID나 수신 시각을 추가하는 것으로 이 공백을 해결하지 않는다. 전사문 접수는 나그네온의 원음 수신과도 다르다. 따라서 연속 발언의 완전 전달·발언 당시 화면 및 관객 정합·접수 전 유실 복구를 충족한 제품 연결로 승격하지 않는다. 긴 연속 발언과 설치 검증도 미실행 상태이며 모든 구독 음성 기능의 불가능 판정으로 확대하지 않는다.

## Desktop을 이용하는 원클릭 시작의 검증 범위

외부 앱에서 직접 시작하는 공개 실험 Realtime 경로는 위 번들 호스트에서도 구독 인증에 `realtime conversation requires API key auth` 오류를 반환했다. v2 텍스트 출력과 v3 오디오 출력에서 확인했으며 실제 마이크·원음 전송과 유료 API 호출은 하지 않았다.

[공식 Voice 안내](https://learn.chatgpt.com/docs/features/voice)와 [단축키·딥링크 문서](https://learn.chatgpt.com/docs/reference/commands)를 기준으로 Desktop을 이용하는 시작 경로도 확인했다. 설치본에서는 음성 시작·종료·오디오 단축키가 미할당 상태였다. 시험용 키를 등록한 뒤 전역 시작과 음성 켜기/끄기를 각각 검사했지만 둘 다 선택한 격리 대화가 아닌 새 Voice 대화를 열었다. 종료 단축키는 해당 음성을 중지했다. 이 동작은 권한을 제한한 나그네온 전용 대화에 연결하는 시작 계약을 충족하지 않는다.

따라서 현재 원클릭 음성 인식은 구현·설치 완료 상태가 아니다. 일반 대화를 여는 버튼을 음성 연결 완료로 표시하지 않으며, 비공개 시작 주소·인증정보 추출·상시 화면 출력 수집으로 대체하지 않는다. 전용 대화 시작, 답변 오디오 차단, 발언 자동 전달, 중지·앱 종료 후 마이크 해제까지 같은 사용자 경로에서 확인해야 한다.

## 구현 동작

- 기존 프로필은 로컬 음성 설정을 유지한다. 새 프로필은 원격 모드를 표시하되 동의는 꺼져 있다. 원격 모드에서는 마이크용 로컬 음성 모델 준비를 건너뛰고 이미 실행 중인 해당 워커를 종료한다. 원격 실패 시 로컬 추론으로 자동 전환하지 않는다.
- 시스템 소리와 저장된 클립의 기존 로컬 분석은 별도 경로다. 마이크 원음 동의는 그 소리를 외부로 보내는 동의가 아니다.
- 16 kHz PCM을 기존 연속 캡처에서 보존한다. 2초 단위의 원음 구간을 100 ms 패킷으로 나누고 실제 24 kHz로 변환해 전송한다. 별도 ASR 완료, 음량 임계값 또는 전사문 필터를 원격 이해의 전제 조건으로 삼지 않는다.
- 시간·구간 순서·입력 연결 식별자·발언 당시 화면·관객 목격 범위는 앱이 관리한다. 청취 모델의 문구 후보와 의미 해석은 정확한 전사문이나 관객이 직접 들은 원음으로 취급하지 않는다.
- 원격 접수, 이해, 관객 입력 전달, 디스크 저장은 별도로 집계한다. 불확실한 구간은 무음 성공으로 바꾸지 않는다. 긴 해석은 발언 경계로 나누고 부분 전달 실패를 재시도할 때 이미 전달된 부분이나 모델 호출을 반복하지 않는다.
- 한 입력 연결의 원격 처리는 순차적이다. 구간별 모델 시도는 최대 3회, 이미 이해한 결과의 전달 시도는 최대 12회로 제한한다. 미해결 앞 구간이 뒤의 새 입력을 영구히 막지 않으며 결과에 앞 구간의 미해결 여부를 남긴다.
- 방송·마이크·AI 정책의 중지는 새 송신과 늦은 결과 수용을 차단한다. 같은 방송에서 마이크를 다시 켜면 남은 시도 범위의 미처리 원음을 처리한다. 새 방송에는 이전 방송 원음을 자동 재전송하지 않는다.
- 원격 연결은 55분에 교체한다. 저장이 확인된 원음은 메모리 압박 시 디스크에서 다시 읽고, 미저장 메모리의 과도한 증가나 처리 기록 저장 실패는 원격 처리를 중단한다.
- 원음은 기존 로컬 원음 저장소, 청취 상태와 해석은 `data/native-audio/listening-*.jsonl`에 보관한다. 앱 실행 중 24시간 기준으로 정리하며 청취 기록 정리는 분 단위다. 앱이 꺼져 있는 동안에는 정리 작업도 실행되지 않는다. 이 파일들은 사용자 데이터이며 Git·릴리즈 첨부 대상이 아니다.
- 사용량은 제공처가 보고한 음성·텍스트·캐시 토큰을 구분한다. 정보가 없거나 취소 뒤 실제 사용량을 확인하지 못한 경우 0원으로 단정하지 않는다.

## 현재 검증 범위와 남은 작업

합성 프로토콜·HTTP·상태 검사는 실제 모델의 의미 이해 품질이나 지연을 증명하지 않는다. 초당 네 번의 짧은 발언, 이름·부정·정정 보존, 장시간 송신 처리량, 실제 게임의 자원 영향은 실측이 필요하다. 현재 캡처의 디스크 저장 전송은 1초 묶음을 사용하며 원격 이해는 2초 묶음 이후 실행되므로 100 ms의 실제 송신 지연을 보장하지 않는다.

앱을 완전히 재시작하면 원음·청취 파일은 보존 정책에 따라 남지만 미처리 작업을 저널에서 자동 복원해 재전송하는 기능은 아직 없다. 이 범위는 같은 실행 내 마이크 재연결 복구와 구분한다. 제공처의 실제 응답 형식, 장치 중지, 게임 동시 실행, 패키지 업데이트·기록 보존까지 확인한 뒤 통합·정식 배포를 판단한다.

로컬 검증 명령:

```powershell
npm ci
npm run check
npm audit --audit-level=high
node --test test/native-audio-provider.test.js test/native-audio.test.js test/native-audio-http.test.js test/native-audio-pricing.test.js
node_modules\.bin\electron.cmd scripts/verify-native-audio-ui.cjs
```

UI 검사는 격리 프로필과 합성 관객을 사용하며 물리 마이크를 열거나 API를 호출하지 않는다. 결과와 화면은 `artifacts/remote-native-audio/ui/`에 생성된다. 변경된 기본 프로필·캡처 경로를 실제로 검증하기 전에는 개발 검사 통과를 설치 완료로 보고하지 않는다.
