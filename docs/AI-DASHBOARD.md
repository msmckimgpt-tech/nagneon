# AI 대시보드

사이드바의 **AI 대시보드**에서 앱 전체의 AI 실행 허용, 기능별 실행 조건과 사용 기록을 확인한다. 모든 화면의 상단 상태 버튼에서도 이동할 수 있다. 대시보드 조회 자체는 모델을 호출하지 않는다.

## 기본 정책과 조작

- **방송 밖 자동 AI는 기본 차단**이다. 기존 `communityActivityEnabled=true`인 프로필도 새로운 전체 허용을 켜기 전에는 커뮤니티 자동 활동과 문화 자료 수집·분석을 실행하지 않는다. 직접 누르는 초대·인터뷰·연결 시험은 별도 기능이다.
- **모든 AI 호출 차단**은 즉시 새 호출과 대체 연결 재시도를 막고, 진행 중 요청에 취소를 전달한다. 차단 상태는 재시작 후에도 유지한다. 이미 전송된 요청의 청구 취소를 보장하지 않는다. 취소 후 늦은 응답은 결과로 반영하지 않는다.
- 기능의 **실행 허용**은 실행 명령이 아니다. 방송 상태, 새 입력, 유휴 시간, 기존 기능 설정 등 조건을 함께 만족해야 실행한다. 각 행의 차단 이유와 바로가기를 확인한다.
- **앱의 사용량 상한은 없다.** 사용자가 사용 기록을 확인하고 전체 차단·기능별 허용을 직접 관리한다. 이전 프로필의 `dailyLimit` 값은 읽을 때 제거하며 사용 기록과 나머지 정책은 보존한다. 이전 상한을 초과해도 호출을 자동 차단하지 않는다.
- 차단·해제는 오래된 대화나 화면을 재생하지 않는다. 자동 활동은 다시 유휴 조건을 기다리며 기존 개별 활동의 간격·재시도 제한도 유지한다.
- AI 호출 차단과 마이크·화면 공유·로컬 음성 인식 중지는 다르다. 장치는 방송실에서 조작한다. 로컬 전사는 외부 AI 호출 사용량에 포함하지 않고, 원격 전사는 `remote-stt`로 별도 집계한다.
- 종료된 수동 후기·댓글 API는 계속 HTTP 410을 반환한다. 대시보드에서 다시 활성화하지 않는다.

## 사용량과 보관

오늘, 최근 7일, 이번 방송을 구분하고 기능별 요청 시도·보고 토큰을 보여준다. 방송을 시작해도 오늘의 사용량은 초기화되지 않는다. 최근 요청에는 실제 제공처·모델·연결 ID, 실패/취소/중단, 결과 반영 확인 여부가 남는다. 프로세스 중단 당시 실행 중이던 요청은 다음 시작에 `interrupted`로 표시한다.

제공처가 보고하지 않은 값은 `미보고`다. 보고된 토큰 합계는 실제 청구액이나 계정 전체 사용량이 아니다. 계정의 남은 구독량은 추정하지 않는다. 연결 전 준비 단계에서 실패한 시도도 포함될 수 있으므로 요청 시도 수를 청구된 요청 수로 해석하지 않는다.

### 토큰 예상 비용과 구독 환산

공식 API의 지원 모델은 단가를 따로 입력하지 않아도 계산한다. `server/ai-pricing.js`의 단가표는 2026-09-24 확인한 USD / 100만 토큰의 Standard 가격이며, 앱 조회 시 외부 가격 사이트나 모델을 호출하지 않는다. GPT-6 Astra/Sol/Luna, GPT-5.4 Mini, GPT-5.6 Luna, GPT-5.3 Codex의 정확한 모델 ID를 지원한다. 모델 ID의 접두사나 임의의 날짜 접미사로 가격을 추정하지 않는다. 가격 변경 시 단가표와 확인일을 함께 갱신하고 회귀 검증한다.

`https://api.openai.com/v1`의 실제 backend 연결임을 확인한 새 API 요청에만 공식 단가를 자동 적용한다. OpenAI 호환 프로토콜을 쓰더라도 다른 엔드포인트나 출처 정보가 없는 과거 API 요청에는 OpenAI 가격을 빌려 쓰지 않는다. 이 경우 단가 설정에서 최근 요청의 연결·모델을 선택한 뒤 사용자 단가를 입력한다. 연결 ID와 모델이 정확히 일치하는 사용자 단가가 공식 단가보다 우선한다. 빈 연결 ID는 단일 연결이며 모든 연결에 적용하는 와일드카드가 아니다.

ChatGPT 구독 연결(Codex)은 **구독 사용량의 API 단가 환산**으로 별도 합산한다. 실제 청구액, 구독 잔여량, 추가 과금이나 절약한 금액이 아니다. 턴 합산 입력·출력 토큰을 표준 API 가격으로 비교하며, 실제 API 요청별 장문 배수나 구독 크레딧 소모량은 추정하지 않는다. API와 구독 사용량이 섞여 있어도 두 금액을 더하지 않는다. 로컬 실행도 외부 API 비용과 분리하며 기기 비용을 0으로 단정하지 않는다.

입력·출력 토큰이 보고되면 캐시 읽기와 쓰기를 일반 입력에서 빼서 중복 없이 계산한다. `usage.input_tokens_details.cache_write_tokens`도 보존한다. 캐시 세부값이 없으면 이를 0으로 바꾸지 않고, 보고된 입력 토큰을 읽기·쓰기·일반 입력에 배분할 수 있는 범위의 최솟값~최댓값을 표시한다. 일반 입력과 캐시 쓰기 가격이 같은 이전 모델이나 사용자 단가는 쓰기 구분이 없어도 가격이 같을 수 있다. 사용자 캐시 쓰기 단가를 비워 두면 사용자가 입력한 일반 입력 단가를 사용한다. 합계 토큰만 있고 입력·출력 구분이 없거나 캐시 합계가 입력을 초과하면 금액을 만들지 않는다.

공식 API의 GPT-6 및 GPT-5.6 Luna 요청은 입력이 272,000토큰을 **초과**할 때 전체 요청의 입력·캐시 단가 2배, 출력 단가 1.5배를 반영한다. 금액은 Standard 토큰 비용의 부분 추정이며 검색·음성·다른 도구 요금, 지역 할증, Fast/Flex/Batch 등 요금제 차이·할인, 세금은 포함하지 않는다. 표시 범위도 이런 별도 요금까지 포함하는 청구액의 상한·하한은 아니다.

단가와 산정 결과는 요청별 메타데이터로 남고, 성공 여부와 별개로 제공처가 보고한 사용량을 반영한다. 단가 저장과 재시작 시에는 보관된 최대 500개 요청 중 **미산정 기록만** 보완한다. 이미 산정한 금액은 당시 단가 스냅샷으로 유지한다. 재시작 보완은 먼저 메모리에서 이루어지고 다음 정상 저장에 함께 기록되며, 대시보드 조회만으로 파일을 쓰거나 AI를 호출하지 않는다. 보완을 반복해도 중복 합산하지 않고 보관 기한이 지난 일별·방송 버킷을 재생성하지 않는다. 상세 기록이 이미 제거된 과거 요청의 비용은 복원하지 않으며 미산정 건수에 남긴다. 최근 40개 UI 행으로 전체 기간 합계를 재구성하지 않는다.

기간에 요청이 없으면 $0.0000과 요청 없음 설명을, 단가 누락·토큰 미보고·다른 요금 체계 등은 요청별 사유를 표시한다. 비용이 정확히 0인 유효한 사용자 단가는 미산정으로 처리하지 않는다. 전체 토큰 숫자를 임의의 입력·출력 비율로 나눠 그럴듯한 금액을 만들지 않는다.

단가와 캐시 계산의 근거: [공식 API 가격](https://developers.openai.com/api/docs/pricing), [GPT-5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [캐시 토큰 비용 계산](https://developers.openai.com/api/docs/guides/prompt-caching).

`data/ai-control.json`에 정책과 최대 31일의 일별 합계, 최근 8개 방송 합계, 최근 500개 요청 메타데이터를 저장한다. 화면에는 최근 40개 요청을 표시한다. 프롬프트, 응답 본문, 음성·이미지, API 키는 이 파일에 저장하지 않는다. 비용 필드는 이 AI 사용량 파일에만 추가하며 관객·잔액·기억 형식은 바꾸지 않는다.

구버전 복귀는 업데이트 전 백업을 **별도 프로필**로 복사해 검증한다. 새 사용자 단가의 `cacheWrite` 필드는 기존 단가 스키마의 엄격한 검사와 호환되지 않으므로, 이 필드를 저장한 현재 프로필을 구버전에 그대로 연결하지 않는다. 최신 기록을 과거 백업으로 덮어쓰거나 읽기 오류를 피해 AI 사용 기록을 삭제하지 않는다. AI 대시보드 자체가 없던 더 오래된 버전은 전체 차단 정책도 시행하지 않으므로 자동 실행 설정을 별도로 확인한다.

저장에 실패하면 추가 AI 호출을 차단한다. 백업 복구 시에도 실행 허용 설정이 달라졌을 수 있으므로 새 호출을 차단하고 안내한다. 원본을 보존하면서 저장 오류와 복구 기록을 확인한 뒤 재시작한다.

## 기능을 추가할 때

1. `shared/ai-features.json`에 고유 ID, 한국어 이름, 실행 범위(`live`, `background`, `manual`), 조건, 화면 목적지와 기본 허용을 등록한다. UI와 서버는 같은 목록을 사용한다.
2. `studio.provider.react({ aiFeature: id, ... }, signal)`을 사용한다. 등록하지 않은 ID와 ID 없는 요청은 실패한다. 제공처를 직접 생성해 공통 제어를 우회하지 않는다.
3. 실제 backend 시도는 `runAiAttempt`를 통과해야 한다. 라우터는 fallback마다 별도 시도를 기록하고 `ai_blocked`/`ai_cancelled`를 재시도하지 않는다. 새 제공처는 사용량을 받는 즉시 `onAiUsage`를 호출해 후속 응답 검증 실패에서도 사용량을 보존한다.
4. 모델 응답 뒤 추가 비동기 작업이 있다면 결과 반영 직전에 `studio.ai.assertCurrent(result)`로 정책 세대가 유효한지 확인한다. 성공한 제품 저장 뒤 `accepted(result)`로 반영을 기록한다. 실패한 사용 기록 저장 때문에 이미 완료한 제품 결과를 이중 실행하거나 포인트를 반환하지 않는다.
5. 자동 수집기에는 시작 전 `allowed(id)` 확인과 취소 연결을 추가한다. 비활성 동안 쌓인 입력을 재개 시 몰아서 실행하지 않는다. 유료 포인트 예약 전에도 허용을 확인하고 취소 시 기존 트랜잭션으로 반환한다.
6. 기본 차단, 동시 호출 집계, 이전 상한 제거, 취소/늦은 결과, usage 미보고, restart, HTTP 인증, 화면 연결을 검증한다. 새 외부 서비스나 모델은 자동으로 추가하지 않는다.

## UI 근거와 검증

실행 상태와 최근 실행 이력을 분리하는 [Zapier 실행 이력](https://help.zapier.com/hc/en-us/articles/8496291148685-View-and-manage-your-Zap-history), 기능 태그로 요청을 구분하는 [Helicone 속성](https://docs.helicone.ai/features/advanced-usage/custom-properties), 보고 토큰과 추정 비용을 구분하는 [Langfuse 사용량 추적](https://langfuse.com/docs/observability/features/token-and-cost-tracking)의 원칙을 로컬 방송실에 적용했다. 해당 서비스나 분석 SDK에 데이터를 보내지 않는다.

`npm run check`, `npm audit --audit-level=high`, `node_modules/.bin/electron.cmd scripts/verify-ai-dashboard.cjs`, `node_modules/.bin/electron.cmd scripts/verify-ai-pricing.cjs`로 확인한다. 비용 계산 회귀는 `test/ai-pricing.test.js`에 있다. Electron 검증은 실제 renderer/HTTP/SSE를 사용하지만 합성 제공처이며 실제 계정 청구·물리 장치 검증을 대체하지 않는다. 결과·화면은 실행 worktree의 `artifacts/ai-dashboard/`, `artifacts/ai-pricing/`에 남긴다.
