# 첫 실행 인터랙티브 튜토리얼

2026-09-15 사용자 검토·승인한 구성: 기본 설정 → 첫 관객 초대 → 방송실 탐색 → 리허설 시작·인사 → 채팅 표시·오버레이 → 첫 관객 확인 → 종료·실전 준비.

## 동작

- 처음 실행한 프로필에서 기존 이름·제목·분위기 설정 뒤 **직접 조작하며 배우기**로 진입한다. 계정 없이도 진행 가능하다.
- 실제 메뉴·버튼·입력에 강조 테두리와 설명 연결을 적용한다. 안내는 상단의 별도 영역을 사용한다. 키보드 포커스를 대상에 옮기고 기존 Enter·Space 입력을 유지한다.
- 메뉴 이동, 서버의 실행 상태, 보낸 인사 이후의 리허설 채팅, 내 발언 표시 설정을 관찰하여 진행한다. 오버레이는 직접 투명도를 바꾼 뒤 창의 닫기 버튼을 사용하는 선택 실습이다.
- **이 단계 건너뛰기**, **튜토리얼 건너뛰기**, **나중에 계속하기**, 사이드바 및 설정의 다시 배우기를 제공한다. 시작을 생략하고 인사 단계에 도착하면 실제 시작 버튼을 다시 안내한다.
- 전체 건너뛰기·중단·완료는 튜토리얼이 켠 리허설의 sessionId만 종료한다. 시작 전 모드와 내 발언 표시 설정을 복원한다. 다른 세션이 실행 중이면 종료하지 않고 안내한다.
- `tutorial.json`에 진행 상태·단계·생략한 단계·복원할 설정을 저장한다. 기존 프로필은 자동 시작하지 않고 다시 배우기로 진입한다. 중단된 프로필에는 이어하기 배너를 표시한다.

## 첫 관객 생성

실제 **나의 관객** 화면에서 **첫 관객 초대 · 50P**를 누른다. AI 연결과 기존 첫 만남 비용·포인트 설정을 적용한다. 초기 포인트를 추가 지급하거나 기존 관객을 바꾸지 않는다.

`POST /api/tutorial/arrival`은 기존 관객 생성의 검증·포인트 보관·성공 정산·실패 환불을 재사용한다. 모델 요청 전에 `world.json`에 pending receipt를 저장하고 202를 반환한다. 같은 UUID는 재사용하며 서로 다른 요청도 pending 또는 성공 이력이 있으면 중복 생성하지 않는다. firstTutorial 옵션은 일반 도착 API의 입력으로 허용하지 않는다.

이 작업은 리허설 controller/epoch와 독립적이며 서버 요청 수명주기와 180초 timeout에 연결된다. 튜토리얼 종료·건너뛰기·리허설 종료에도 생성은 유지된다. 생성 중에는 실제 AI 방송 시작을 막고 리허설을 허용한다. 게이트는 영속 pending receipt에서 판단한다. 앱 종료 시 취소·환불 정산을 기다리며, 비정상 종료로 남은 pending은 기존 World.recover가 다음 실행에서 반환한다.

진행 안내의 생성 상태는 별도 복사본이 아니라 canonical receipt에서 읽는다. 생성 완료는 원자 저장 이후 표시하며, 이름·사적 성향을 포함한 원본 receipt를 UI로 공개하지 않는다. 첫 관객 상태 배너는 튜토리얼 밖에서도 보이고 실패 시 관객 화면으로 돌아가 재시도할 수 있다. 리허설 채팅은 준비된 대사이며 실제 AI 응답이 아니다.

## 검증 및 증거

- 작업 브랜치: `codex/interactive-tutorial`. 기준: `bb2189e2b1de0ca7422ea321e7ad67bee3b83734`.
- `npm ci`, `npm run check`: 672개 테스트, TypeScript와 Vite 빌드 통과.
- 반복 검사 한 번에서 기존 HTTP 테스트 4개가 `fetch failed`로 실패했다. 원본은 `check-network-failure.log`에 보존했다. 해당 24개 좁은 검사와 진단을 추가한 전체 672개가 모두 통과했으며, 기본 `npm run check`도 재실행했다. 최초 실패의 하위 네트워크 원인은 재현되지 않아 확정하지 않았다.
- 새 테스트: 생성 중 리허설/전체 skip, UUID 중복 및 8개 동시 요청, 실패 반환·재시도, 앱 종료 abort·정산, pending 재시작 복구, 진행 저장 실패, 다른 리허설 세션 보호, 미연결 프로필에서 실습·skip, 공개 상태의 사적 성향 비노출.
- 실제 Chrome UI: 이름·제목 수정, 분위기 선택, Enter 메뉴 이동·초대·리허설 시작·한국어 채팅 전송, Space 발언 표시 끄기/켜기, 별도 오버레이 투명도 20% 조절·닫기, 생성된 `연습별` 확인, 리허설 종료·완료 및 새로고침 후 자동 재등장 없음. 다시 배우기에서 관객 중복 생성 없이 진행, 중단·새로고침·이어하기, 시작 단계 skip 후 실제 시작 복구, 전체 skip의 STANDBY 복귀 확인.
- 이 UI 실행은 `scripts/serve-tutorial-fixture.mjs`의 **45초 지연 합성 생성 제공처**를 사용했다. 실제 구독 모델의 생성 지연, Windows 네이티브 오버레이, 설치 패키지 배포는 이번 검증에 포함하지 않는다.
- 원본 로그·격리 프로필: 작업 worktree의 `artifacts/tutorial/` (`check-final.log`, `server-tests.log`, `ui-1789406900219/profile`, `ui-acceptance.json`). 연결 파일은 일회용 로컬 인증값을 포함하므로 게시하지 않는다.

웹 보조 경로에서 UX와 생성 수명주기를 별도 대화로 검토한 뒤 별도 대화로 종합했다. 로컬에서는 canonical pending 게이트, 생성 작업과 리허설의 분리, 저장 후 상태 전파, 실제 인사 이후 응답 판정으로 대조·적용했다. 포인터 위치 계산 대신 별도 상단 안내 영역과 실제 요소 테두리를 선택해 클릭을 가리지 않도록 했다. 이 경로는 설계 검토이며 웹에서 소스를 실행하거나 구현한 결과가 아니다. 대화 원문 전사본은 `artifacts/tutorial/web-ux.txt`, `web-lifecycle.txt`, `web-synthesis.txt`에 보존했다. 비용 효과는 미측정이다.
