# 클립을 계기로 들어온 관객의 기억

2026-09-13. 이전 목표 단계는 연속 장면 인식을 main `697afcd8402c3d9e0d3647554759fa144ccc5bb4`에 통합한 진전이었다. 그 전에 보류한 `codex/clip-arrival-context` worktree를 이 기준까지 fast-forward한 뒤 이 작업을 진행했다. 개발 위치는 `G:/dev/ai/00_game_backseat-worktrees/clip-arrival-context`다. 사용자 앱·장치·Computer Use는 사용하지 않았다.

## 확인한 단절

클립 유입 시 `AudienceAutonomy.arrive`는 제목과 장면 요약을 페르소나 생성 요청에 넣었지만, 생성 후에는 `origin.clipId`만 남겼다. 라이브 입력에는 유입 계기의 설명이 없어 “무슨 클립을 보고 왔나”라는 대화가 이어지지 않았다. 성격 서술에 우연히 복사된 내용만 남을 가능성도 있어 원본 변경·삭제와 독립적으로 오래된 이야기가 전달될 수 있었다.

합성 재현은 `artifacts/clip-arrival-before.mjs`다. 수정 전 main 모듈과 수정 후 개발 모듈을 각각 격리된 메모리 서버/데이터 경로로 실행했다. `clip-arrival-before.json`에서는 생성 요청의 '구름찻집'이 라이브 입력에 없고, `clip-arrival-after.json`에서는 개인 유입 기억으로 전달된다. 첫 재현 파일을 수정 후 실행으로 덮어쓴 일을 확인해 수정 후 결과를 `clip-arrival-after-initial.json`으로 보존하고, 아직 수정되지 않은 main 기준에서 이전 결과를 다시 재현했다. 최초 출력 한 번을 원본 파일로 남겼다고 주장하지 않는다.

## 구현

- 유입 원본은 호출자가 건넨 제목/요약 대신 등록된 클립 ID로 다시 읽는다. 존재하지 않는 클립이나 경로 혼합은 호출·포인트 보관 전에 거부한다.
- 소개를 접한 경험은 `arrivalClip` 참조로 남긴다. 버전 1, 클립 ID, 생성 영수증 ID, 접한 시각, 정확히 제공한 제한된 소개의 SHA-256을 담는다. 별도 줄거리 사본은 만들지 않는다.
- 관객·지갑·생성 완료 영수증과 이 참조는 같은 world 저장으로 확정한다. 모델 응답 중 원본이 삭제되거나 제공할 소개가 바뀌면 전체 만남을 취소한다. 댓글 추가는 소개 변경이 아니며, 새 댓글을 읽은 것으로 처리하지도 않는다.
- 저장 스키마는 관객 ID·유입 경로·클립 ID·완료 영수증·접한 시각을 교차 검증한다. 레거시 `origin.clipId`만으로 경험을 소급 생성하지 않는다. 닉네임 변경과 재시작 뒤에도 같은 관객 ID에 연결된다.
- 페르소나 생성에는 유입 경로와 넓은 관심 분야만 전달한다. 클립 줄거리·대사·기존 친분을 영구 성격에 복사하는 경로를 없앴다. 구체적인 소개는 이후 해당 관객의 `viewerContext.arrivalClipMemory`로 전달한다. 세부적인 장면 취향이 성격 형성에 반영되는 깊이는 추후 확장할 수 있다.
- 라이브에서는 클립 원본이 남아 있고 참조 버전이 일치할 때만 제목 100자·게임 100자·요약 600자 이내로 제공한다. 유니코드 문자 절반에서 자르지 않으며 일부 발췌인지 표시한다. 삭제/수정된 원본, 미래 시각의 참조는 전달하지 않는다. 해시는 이 제한된 소개를 대상으로 하므로 발췌 범위 밖만 달라진 동일 입력은 새 경험으로 취급하지 않는다.
- `read-discovery-summary`는 소개를 읽은 간접 경험이다. 영상·소리 재생, 라이브 목격, 원문 채팅·댓글 읽기, 익명 후원자 식별을 부여하지 않는다. 가상 기획은 `fictional` 표시를 유지한다. 개인 게임 시청 시간과 직접 목격 기억은 증가시키지 않는다.
- 원시 참조는 공개 상태/SSE/내보내기와 공용 모델 관객 데이터에서 제외한다. 프로필 해금의 기존 공개 범위는 그대로다. 한 모델 호출 안의 개인 문맥들은 여전히 물리적으로 함께 입력되므로 완전한 실행 격리를 주장하지 않는다.

## 검증

`npm run check`의 전체 437개 테스트와 TypeScript/Vite 빌드가 통과했다. `artifacts/check-first.log`에 전체 결과가 있다. 추가 12개 검사는 등록 원본 사용, 이름 변경/실제 저장 후 재시작, 다른 관객과 레거시의 비목격, 삭제/편집 경쟁, 읽지 않은 댓글, 저장 실패, 스키마의 교차 참조, 발췌·가상 구분, 공개/API 입력 참조 제거를 다룬다.

`test/fixtures/clip-arrival-crash.mjs`는 자체 합성 Node 서버를 보관 직후/완료 직후에 종료 코드 73/74로 즉시 끝낸다. 정상 `close()`를 호출하지 않는다. 부모 테스트가 해당 프로세스의 종료를 확인한 뒤 같은 격리 데이터에서 재시작한다. 보관 단계는 실패한 만남으로 복구되며 기억이 없고, 완료 단계는 관객과 소개 기억이 함께 복구된다. 다른 프로세스를 종료하지 않는다.

기존 자연 유입 검사는 광범위한 대화 관심사를 생성기로 전달하고 구체적인 소개가 승인된 관객의 개인 경험에 남는지를 확인하도록 갱신했다. 첫 새 테스트 실패는 정적 모델 지시에 등장한 필드 이름까지 데이터 누출로 검사한 잘못이었다. 실제 입력 데이터 영역을 검사하도록 고쳤고 제품의 삭제 처리를 완화하지 않았다.

`scripts/verify-clip-arrival-astra.mjs`는 실제 공식 CLI의 `gpt-6-astra` / `low`로 관객 3명을 생성하고, 그 데이터의 독립 복사본을 재시작해 8개 대화 사례를 실행한다. 사용자 데이터·장치·클립 영상/음성은 사용하지 않는다. 생성 요청·원본 저장·개인 문맥·실제 응답·시간·소스 해시를 `artifacts/clip-arrival-astra-*`에 보존한다. 최종 모델 결과와 통합 기록은 후속 항목에 남긴다.

실제 모델 최종 원본은 `artifacts/clip-arrival-astra-fMxdTB/`와 `artifacts/clip-arrival-astra-first.log`, 결과 바로가기는 `artifacts/clip-arrival-astra-result.json`이다. 관객 생성 3회와 재시작 대화 8회, 총 11회가 성공했다. 라이브 응답은 10.625~12.244초였다. '구름찻집이요! 그때 라이브에 있던 건 아니고, 클립 소개에서 읽었어요.'라고 답했으며 이름 변경 후에도 유지됐다. 미열람 댓글의 암호, 다른 관객의 소개 기억, 익명 후원자의 이름을 만들지 않았다. 삭제/변경된 소개는 모른다고 답했고, 가상 정거장은 실제 우주 여행과 구분했다. 각 응답·개인 문맥·후원/클립 제안을 직접 검토했으며 이 사례들에서 새 후원은 없었다.

생성된 소금책갈피·차곡차곡·문구산책은 모두 문구류 취미가 겹쳤고 숙련도도 0.32로 같았다. 기억 연결의 성공이 독립적인 성격 다양성의 성공을 뜻하지 않는다. 기존 관객과 비교한 초기 취향/말버릇 다양성, 유입 경로별 편중은 다음 개선 대상이다.

## 남는 범위

이 단계는 클립 소개가 이후 소통에 이어지는 연결을 구현했다. 실제 저장된 클립 영상·음성을 관객이 재생해서 이해하는 기능은 아직 아니다. 일반 커뮤니티 글을 혼자 읽는 행동, 댓글 없는 자발적 열람 빈도, 소개 이후 변한 원본을 다시 접하는 행동, 장기 취향 형성은 추가 대상이다. 기존 사적 인터뷰/후일담 경로는 원시 참조를 제거하지만 아직 동일 소개를 별도 개인 문맥으로 제공하지 않는다.

소개를 나중에 공개 대화로 언급했다면 그 발언은 별도의 대화 기억이 된다. 클립을 지웠다는 이유만으로 이미 나눈 모든 관련 발언·클립 댓글·다른 저장소의 의미를 자동 지우는 전역 삭제는 구현하지 않았다. 이 참조의 삭제 동작과 전역 기억 삭제를 혼동하지 않는다. 신규 관객부터 경험을 확정하며 과거 클립 유입자의 기억은 자동 복원하지 않는다.

실행 중인 사용자 앱, 패키지, 설치 프로그램을 교체하지 않았다. 수정된 실행본의 장기 실사용과 Steam 판매 준비는 미완료다.
