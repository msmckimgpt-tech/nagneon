# 후원 사건의 기억 보존과 배포 검사

2026-09-13. 기준 main `4e66af6`, 브랜치 `codex/donation-memory-release`, 작업 경로 `G:/dev/ai/00_game_backseat-worktrees/donation-memory-release`. 이전 목표 단계의 채팅 조사·익명 후원 통합은 검증된 진전이었다. 이번 단계는 그 기능이 기억과 배포 경로에서도 유지되는지 확인했다.

## 확인한 결함과 수정

익명 24P 후원을 공개 채팅으로 넣었을 때 `ConversationJournal.record`가 본문만 남기고 `kind`와 `donation`을 버렸다. 따라서 뒤에 회상할 때 금액과 후원 사건이라는 사실이 사라지고, 본문에 후원이라는 단어가 없으면 후원 검색도 0건이었다. `artifacts/donation-memory-before.json`은 수정 전 실제 메모리 경로의 결과다. 기존 사용자 데이터는 변경하지 않았다.

공개 기억에 메시지 종류와 후원 금액·익명 여부를 보존한다. 원문, 당시 공개 이름·ID, 세션, 시각, 함께 있던 관객도 그대로 남긴다. 익명 후원의 실제 후원자 ID는 이 기록에 들어가지 않는다. 전사 교정과 후원 메타데이터는 각각 복제하여 저장 콜백이나 조회 결과를 수정해도 원본을 바꿀 수 없다. 같은 메시지 ID로 종류·금액·익명 여부를 바꾸는 재전송은 거절한다.

불변 조각 저장소의 동일성 비교에도 새 필드를 포함했다. 본문이 같다는 이유로 메타데이터가 달라진 조각을 재사용하지 않는다. 인덱스 저장 실패 시 기존 디스크·메모리 스냅샷을 유지하며, 재시작 후 핀·삭제·목격자 제한이 보존된다.

후원 검색은 실제로 타입이 붙은 후원 사건에만 후원/포인트/익명/금액 검색어를 보탠다. 일반 채팅의 지급 약속을 받은 포인트로 취급하지 않는다. 과거 형식의 종류 없는 기억은 그대로 읽으며, 본문이나 `anonymous`라는 발언자 ID만으로 후원 사건·금액을 추정해 복구하지 않는다. 이미 버려진 정보까지 복원했다고 주장하지 않는다.

라이브·오버레이, 함께 나눈 말, 핫클립 채팅에 같은 `DonationBadge`를 사용해 가상 후원 금액과 익명 여부를 표시한다. 후원자 무료 조회는 경제 기록을 사용하는 기존 별도 창에 남는다. 공개 기억을 삭제해도 포인트나 개인 거래 기록을 환불·삭제하지 않는다. 핫클립에 복사된 대화의 별도 삭제 정책도 유지한다.

## 검증

- `test/donation-memory.test.js`의 8개 검사: 실제 조각 저장과 재시작, 최근 35줄을 지난 검색, 새 관객의 이전 목격 제한, 일반 지급 약속/옛 기록, 잘못된 메타데이터·익명 이름, 같은 ID 충돌, 복제 격리, 인덱스 실패·재시도, 삭제, 당시 공개 이름 보존.
- `test/donation-badge.test.js`: 실제 React 서버 렌더로 가상 포인트·익명 표시와 일반 채팅에서의 배지 부재 확인. 창을 직접 조작한 검사는 아니다.
- 개발 트리 `npm run check`: **394개 검사와 TypeScript/Vite 빌드 통과**. 원본 `artifacts/check-release.log`. 앞선 `check-final.log`는 회상 표현 지침을 더하기 전 결과라 구분한다.
- `scripts/verify-donation-memory-flow.mjs`: 새 합성 프로필에서 실제 서버와 HTTP, 두 번의 서버 재시작. 실제 경제 보상 30P 후원 기록, 검색, 목격 회상, 핫클립, export, 401 인증 거절, 닉네임 변경 후 무료 조회, 기억 삭제 후 재시작, 잔액 보존을 확인한다. 장치·사용자 프로필·실제 AI를 쓰지 않는다. 최초 소스 실행은 `artifacts/donation-memory-source-flow/result.json`에 있다.

공식 CLI `gpt-6-astra`, `low`의 실제 회상 호출은 별도 `scripts/verify-donation-memory-astra.mjs`로 진행했다. 합성 24P 후원과 일반 채팅의 190P 지급 약속을 디스크에 저장하고 다시 읽은 뒤 묻는다. 최종 세 사례 모두 금액·목격·지급 여부 기준을 통과했다. 목격한 관객은 24P를 회상했고, 나중에 온 관객은 모른다고 했으며, 190P 약속은 받은 후원으로 바꾸지 않았다. 과거 후원에 새 포인트를 생성하지도 않았다. 최종 10.737~15.822초이며 실제 사용자 음성 지연이나 장기 방송 성능을 측정한 수치는 아니다.

말투는 별도 미해결 항목이다. 첫 실행 `donation-memory-astra-RU4LKb`에서 보고서 같은 표현을 발견해 직접 겪은 말로 답하도록 지침을 추가했지만, 최종 `donation-memory-astra-TLfpsX`에도 ‘남아 있는 내역’이라는 표현이 남았다. 기계적 사실 기준 통과를 자연스러운 말투 합격으로 보고하지 않는다. 단순 금칙 표현 교체보다 직접 목격과 나중에 읽은 자료의 표현을 구분하는 후속 평가가 필요하다. 두 실행의 원본을 모두 보존했다.

## 배포본과 수용 범위

새 배포본: `release/2026-09-13T09-55-22-753Z/app/BACKSEAT-win32-x64`, **2,445개 파일, 1,599,514,597바이트, 미서명**. 최근 채팅 주목·익명 후원·후원 기억 수정이 포함된다. 사용자의 기존 실행 앱·설치본은 교체하거나 재시작하지 않았다.

패키지 전체 파일 해시를 검사하고 ASAR의 실제 서버와 화면 빌드 파일이 검증한 원본과 같은지 확인한다. ASAR를 격리 폴더에 추출하여 Node로 서버를 실행하는 파일 기반 수용 검사이며, Electron 창을 띄우거나 설치 프로그램을 실행하는 검사가 아니다.

- `artifacts/donation-memory-packaged-flow/result.json`: 배포된 서버로 앞의 HTTP·두 번 재시작·후원·기억 흐름을 검증한다. 화면 빌드 파일도 이름·해시를 비교한다.
- `artifacts/packaged-clips/result.json`: 배포본의 실제 Python 디코더로 합성 오디오/영상 업로드와 전체/범위 다운로드, 잘못된 트랙 거절을 검사한다. 최근 클립 수정을 배포 갱신이 되돌리지 않는지 확인한다.

두 실행 결과와 통합 상태는 후속 기록에서 확정한다. 설치·서명·깨끗한 Windows·Steam 판매 조건·물리 장치·장기 자연스러움은 [판매 준비 기준](RELEASE-GATES.md)의 미완료 항목으로 유지한다. Computer Use 중단 지침에 따라 창/화면 조회·입력·게임 실행·장치 캡처를 수행하지 않는다.

배포 파일 검사 결과: 위 두 검증 모두 통과했다. 같은 ASAR SHA-256 **`ef41590e2adc4f63171c2cea6247ef9e0943bc4cd4986cc796e84d706ce1d11a`**, 2,445개 파일 해시가 일치했다. 후원 검사는 화면 빌드 3개 파일과 서버 소스 해시·HTTP/재시작 6개 흐름을 확인했다. 클립 검사는 오디오/영상 업로드 200, 각각 전체 다운로드와 Range 206, 영상이 섞인 오디오 위장 업로드 422를 확인했다. 이는 실제 네이티브 앱이나 설치 프로그램의 출시 수용 결과가 아니다.

## 통합과 다음 행동

제품 **`424209f166167a60f31b069d26f02ff7b7004954`**, 변경 13개 파일. 별도 통합 트리의 `npm run check` **394개 검사와 빌드**, 같은 트리의 실제 서버·HTTP·두 번 재시작 흐름 6개가 모두 통과했다. 원본은 `live-capture-integration/artifacts/donation-memory-integration-check.log` 및 `donation-memory-integration-flow/result.json`이다. main·개발·통합 트리와 원격 기준을 확인하고 소유한 잠금 안에서 main에 fast-forward했다. 잠금은 해제했고, push·사용자 앱 재시작·설치 교체는 하지 않았다. `artifacts/donation-memory-integration-result.json`에 결과를 남겼다.

증거 목록과 해시는 `artifacts/donation-memory-evidence/manifest.json`. 새 패키지의 공식 런타임·모델 자산을 자체 폴더에 복사하고 검증했으며 사용자 인증 파일이나 대화 수집물을 넣지 않았다. 테스트 프로필은 합성 데이터만 사용한다.

다음 단계에서는 직접 목격한 회상의 말투와 간접 기록을 읽는 말투의 차이를 실제 모델로 더 검증해야 한다. 금액·출처 정확성을 줄이는 방향으로 말투를 바꾸지 않는다. 기존 세계/포인트 저장과 공개 대화 저장은 여전히 서로 다른 커밋이며 모든 저장소를 하나의 트랜잭션으로 만들었다고 주장하지 않는다. 종류가 없던 과거 기억의 금액 복원, 장기 보관량 이후 의미 기억, 설치·실제 장치·상용 배포 조건도 남아 있다. 판매 준비 목표는 계속 진행 중이다.
