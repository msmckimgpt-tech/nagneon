# 바깥 커뮤니티와 내 이야기 찾기

`방송 밖 이야기` 안에서 `방송 커뮤니티`와 `바깥 커뮤니티`를 선택한다. 기존 방송 커뮤니티의 글·관계·기억은 그대로 유지된다.

바깥 커뮤니티는 공략연구소, 클립정류장, 인디산책, 심야라운지, 자유난장의 가상 주민 공간이다. 현실 사이트에 접속하거나 글을 게시하는 기능이 아니다. 주민은 독립적인 일상 글을 쓰며, 방송을 실제 목격한 관객만 해당 공개 발언을 근거로 방송 이야기를 올릴 수 있다. 글을 읽은 다른 주민이 관심을 보이면 다음 실제 방송부터 같은 인물로 방문할 수 있다. 자연 방문은 0P이며 기존 50P 수동 유입과 첫 관객 튜토리얼은 유지된다.

주민 자동활동과 자연 방문의 새 기본값은 ON이다. 저장된 OFF, AI 대시보드의 전체 일시정지·기능 차단·방송 밖 호출 차단은 존중한다. 리허설이나 계정 미연결 상태에서는 실제 생성하지 않고 이유를 표시한다. 신규 프로필은 방송 밖 활동을 허용하지만 별도 문화 수집 기능은 자동으로 켜지지 않는다. 기존 커뮤니티 활동과 하나의 요청 슬롯 및 시간당 최대 6회 시도 한도를 공유한다. 방송 요청이 우선하며 앱을 종료하면 작업을 취소한다.

`내 이야기 찾기`는 방송인 이름으로 저장된 글을 검색한다. 검색·목록·상세 열람은 모델 호출, 생성, 주민의 읽음 기록이나 방문을 유발하지 않는다. 검색·커뮤니티 필터·북마크·페이지 이동을 함께 사용할 수 있다. 글 숨기기는 표시 설정이며 복원 가능하다. `글 잊기`는 해당 글을 논리적으로 삭제하여 파생 기억과 방문 근거에서도 제외한다. 커뮤니티나 주제를 끄면 관련 자동활동과 해당 글을 근거로 한 새 방문도 차단된다.

주민의 게시글 읽기는 전달한 본문과 게시글 해시를 보존한다. 방송을 보지 않은 주민에게는 간접 기억만 전달하며 직접 목격 기록을 만들지 않는다. 설정 OFF, 방송 중지, 글 삭제 또는 원본 수정 중 완료된 늦은 응답은 수용하지 않는다. 모델이 침묵하거나 관심을 보이지 않는 것은 정상 결과다. 앱을 처음 켠 즉시 다섯 공간에 글이 모두 채워지는 방식은 아니다.

## 저장 호환성과 복귀

0.1.7은 world.json을 v2로 저장한다. v1 원본은 변환 전에 migration-backups에 SHA-256 검증 사본을 만들고 파일 내용을 동기화한 후 변환한다. 기존 관객·포인트·설정과 명시적인 OFF를 보존한다. 기존 실험 사회 데이터는 검증되지 않은 이력으로 보존하며 읽기·목격 증거로 승격하지 않는다.

동일 프로필은 한 서버만 쓸 수 있다. v2 기본 파일이 없거나 손상되면 삭제한 기억이 복구되지 않도록 자동 백업 복귀를 거절하고 원본을 보존한다. 방송 대화 또는 클립 저장소가 백업에서 복구되면 사회 기능을 격리한다. 오류가 발생하면 원본과 백업을 별도로 보존한 상태에서 복구해야 한다.

고정 실행기와 설치기는 profile-format.json의 최소 앱 버전을 검사한다. 구버전으로 복귀하려면 업데이트 전 백업을 별도 프로필로 복사하여 구버전을 연결한다. 현재 v2 프로필을 과거 EXE에 직접 연결하거나 과거 백업으로 덮어쓰지 않는다.

## 검증 도구

- `npm run check`: 형식 검사, 전체 테스트, TypeScript/Vite 빌드.
- `scripts/verify-social-runtime.cjs`: 격리 Electron에서 합성 공급자와 실제 HTTP/렌더러를 연결해 내부 구획, 검색 순수성, 북마크, OFF 반영과 좁은 화면을 검증한다.
- `scripts/verify-social-live.mjs`: 검증용 입력과 실제 Codex 계정으로 주민·글·읽기·방문 경로를 확인한다. 실행 시 구독 사용량이 소비된다. 설정한 모델/effort를 확인한 후 명시적으로 실행하며 사용자 프로필을 수정하지 않는다.
- `test/social-runtime.test.js`: 늦은 응답, 삭제 실패, 저장 실패, 공유 예산, 프로필 배타성, 복구 격리, 튜토리얼 및 자연 유입 회귀.

합성 검사는 실제 콘텐츠의 품질 또는 물리 장치 검증을 뜻하지 않는다. 실제 모델의 침묵·관심 없음과 런타임 오류를 구분한다.

AI 대시보드의 자동 활동은 게시글 작성뿐 아니라 주민 준비·글 읽기·댓글도 포함한다. 최근 요청에는 실제 활동 종류와 저장 후 반영 결과를 구분해 표시하며, 결과 위치에서 바깥 커뮤니티·방송 커뮤니티·핫클립을 바로 연다. 과거 요청의 상세 종류가 저장되지 않았다면 결과를 추정하지 않는다. 바깥 커뮤니티 탭의 숫자는 검색 조건과 무관한 표시 가능한 전체 게시글 수다.

## 일반 주민과 관객 작성자

방송에 오지 않은 일반 주민도 자기 공동체의 일상 글을 계속 쓴다. 비관객 주민의 일상 글을 기존 관객의 글보다 우선 가중하며, 허용된 주제를 순환해 공동체의 취향을 드러낸다. 방송 대화나 홍보를 일상 글의 근거로 전달하지 않는다. 주민의 글 작성 자체는 관객 추가가 아니며, 글을 읽은 뒤에도 관심이 없으면 일반 주민으로 남는다. 실제 관심 기록과 다음 방송 조건을 충족할 때만 기존 자연 방문 절차를 사용한다.

현재 관객 명단에 실제로 등록된 작성자의 글은 목록과 상세에서 민트색 테두리·배경과 `나의 관객` 배지로 표시한다. 글을 쓸 때 일반 주민이었어도 나중에 관객이 되면 과거 글에도 표시되며, 명단에서 제거되면 표시를 해제한다. 게시글 원문이나 과거 소속을 다시 쓰지 않는다.

자유난장은 반말·자조·빈정거림·가벼운 비속어·취향 논쟁을 쓰는 가상 익명 게시판이다. 주민은 고정된 인물로 유지되고, 실존 서비스 접속이나 게시글 수집은 하지 않는다. 다섯 공동체와 열 주제의 개별 OFF를 지원하며 기존 설정은 유지한다. 새 공동체가 저장된 프로필을 이전 네 공동체만 지원하는 개발 빌드로 열지 않는다. 복귀에는 업데이트 전 별도 프로필 백업을 사용한다.

게시글 상세를 열면 글 시작 부분을 보여주고, 목록으로 돌아오면 읽던 스크롤 위치와 게시글 버튼의 키보드 초점을 복원한다. 커뮤니티 구획·분류를 전환할 때 상단 선택 버튼의 화면 위치를 유지하며, 자동 활동으로 목록이 갱신되어도 현재 페이지를 첫 페이지로 돌리지 않는다.

## 겹치는 주제와 게시글 대화

주민별 작성 간격에 더해 같은 공동체의 새 글 사이에 20분을 두며, 최근 사용한 주제를 분산한다. 일상 글 요청에는 최근 하루의 공개 일상 글 최대 12개를 전달해 다른 소재를 고르게 한다. 저장 직전에도 최근 하루의 글과 겹치는 문장·표현을 검사하고, 유사 글은 새 게시글로 저장하지 않는다. 의미가 비슷한 모든 표현을 완벽히 판별하는 것은 아니며 기존 게시글은 지우지 않는다.

일반 주민과 관객 모두 게시글과 댓글을 읽고 자발적으로 댓글·답글·추천을 남길 수 있다. 직접 작성한 댓글은 최대 600자, 게시글당 댓글은 150개이며 답글은 한 단계로 모아 표시한다. 사용자의 추천은 한 번만 집계하고 취소할 수 있다. 댓글 삭제는 답글 구조를 유지한 채 삭제 표시로 바뀐다. 댓글·추천이 늘어도 기존 본문의 열람/방문 근거를 소급 변경하지 않는다. 게시판을 여는 동작은 생성이나 읽음 사건을 일으키지 않는다.

## 실제 첨부와 창작 이미지

게시글 상세에서 PNG/JPEG/GIF/WebP 이미지(8MB), MP4/WebM 영상(24MB)을 글당 최대 4개 첨부한다. 이미지 미리보기와 영상 재생을 지원하며 자동 재생하지 않는다. 선택한 실제 파일은 프로필의 `data/social-media`에 저장하고 총 200MB로 제한한다. 실행 파일·HTML·SVG·임의 URL은 첨부로 실행하거나 가져오지 않는다. 코덱에 따라 재생 가능 여부는 달라질 수 있다.

주민의 방송 이야기에는 해당 주민이 실제로 함께 본 공개 발언이 들어 있는 기존 클립만 연결한다. 원본 클립이 없어지면 첨부가 없다고 표시한다. 주민에게 첨부 이름만 전달한 댓글 요청은 영상이나 이미지를 본 경험으로 취급하지 않는다.

`커뮤니티 설정 → 주민 창작 이미지 · 픽셀 그림`은 기본 OFF다. ON이면 기존 텍스트 모델이 일상 글과 함께 16×16 색상 격자를 선택적으로 구성하며, 앱은 검증된 숫자·색상만 256×256 PNG로 저장한다. 별도 유료 이미지 API나 외부 사이트를 사용하지 않는다. 그림 없이 글만 남기는 것도 정상이다. OFF 변경은 진행 중인 자동활동을 취소하며 이미 저장한 그림은 보존한다.

댓글·추천·첨부가 있는 새 기록은 이 구조를 모르는 이전 개발 빌드로 직접 열지 않는다. 업데이트 전 백업을 별도 프로필로 복사해 복귀하고 현재 기록과 첨부는 보존한다.
