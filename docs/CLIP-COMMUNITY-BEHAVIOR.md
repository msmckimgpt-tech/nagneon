# 핫클립 소리와 커뮤니티 글쓰기·설정

## 핫클립 오디오

`useMedia`는 화면 공유 원본을 핫클립에 전달하고, 시스템 소리 분석에는 `useSoundAnalysisSource`가 만든 오디오 전용 복제 스트림을 전달한다. 분석기의 오류나 복제 트랙 정리는 원본 화면·시스템 소리 트랙을 종료하지 않는다. 화면 공유 중단, 사용자의 소리 중단, 원본 장치 종료, 방송 종료의 기존 정리 경로는 유지한다.

`clip-source`는 살아 있는 별도 시스템 오디오를 우선한다. 별도 오디오가 없거나 종료되었으면 명시적으로 공유된 화면 스트림의 오디오를 사용한다. 두 입력에 동일한 Windows 출력이 들어 있을 수 있으므로 둘을 동시에 혼합하지 않는다. 마이크는 기존처럼 별도 파일로 유지한다. 소리만 공유했을 때 전달하지 않은 영상 트랙을 복사하거나 녹화하지 않는다.

화면 선택의 **시스템 출력 소리도 공유**를 꺼두면 시스템·게임 오디오를 임의로 취득하지 않는다. 클립 버퍼와 공유 소리가 모두 연결되어야 해당 소리를 녹음할 수 있다는 안내를 표시한다. Windows 전체 출력에는 다른 앱의 소리도 포함될 수 있다. 이번 변경은 과거에 이미 무음으로 저장된 파일의 소리를 복구하지 않는다.

## 커뮤니티 글쓰기

`server/community-writing.js`는 기존 제공처 공통 payload의 커뮤니티 전용 요청에만 글쓰기 지침을 추가한다. 출력 스키마, 글자 제한, 제공처·모델 선택, AI 활동 예산, 기존 페르소나 데이터는 변경하지 않는다. 추가 추론이나 외부 사이트 자동 게시를 수행하지 않는다. 일반 라이브, 주민 생성, 비공개 인터뷰에는 이 지침을 추가하지 않는다.

### 조사에서 반영한 구성

2026-09-23 공개 게시판의 개별 제목·본문을 질적으로 대조했다. 특정 사이트 이용자 전체의 성향이나 유형별 비율을 추정한 조사는 아니다. 동적 댓글 본문은 충분히 확보하지 못했으므로 실제 댓글 대화를 분석했다고 주장하지 않는다. 실존 작성자의 닉네임·원문을 모델 지침에 복제하지 않는다.

### 생성 조건

게시글에는 상황, 작은 발견, 막힌 지점, 짧은 감상 등 선택 가능한 초점을 제공한다. 최근 글과 주민 ID를 이용한 선택은 재현 가능하며 인격을 무작위로 바꾸지 않는다. 초점이 소재에 맞지 않으면 다른 방식이나 침묵을 선택할 수 있다. 모든 글에 질문·결론·교훈을 강제하지 않는다.

댓글은 실제 전달된 글이나 댓글의 구체적인 내용에 연결한다. 원문을 반복 요약하거나 각자 독립적인 입장을 발표하지 않는다. 실제 댓글 ID만 답글 대상으로 사용한다. 댓글·추천·새 글은 독립적인 자발적 선택이다.

개인의 말투와 공동체 규범을 유지하고 전원을 존댓말·반말·유행어로 통일하지 않는다. 지적받았다는 사실만으로 성격이나 표현 방식을 자동 수정하지 않는다. 일상 주민은 스트리머와 무관한 작은 가상 상황을 이야기할 수 있지만 실제 사용자 정보·방송 사건·현실 뉴스·과거 친분을 날조하지 않는다. 방송 목격, 나중에 읽은 게시글, 실제로 전달받은 미디어의 범위를 구분한다.

다음은 방향을 설명하기 위해 작성한 예시이며, 실제 모델 생성 결과나 외부 게시글 인용이 아니다.

> 제목: 같은 데서 또 길 잃음
>
> 정면 문만 세 번 확인했는데 옆에 계단 있었네. 지도 켜놓고도 이걸 못 봤다.

이와 달리 조용한 주민은 같은 주제를 존댓말로 쓰거나 짧게 질문할 수 있다. 위 예시를 고정 대사로 주입하지 않는다.

## 첨부 권한

주민 게시글에서 스트리머의 파일 입력과 업로드 처리를 제거한다. 인증된 사용자라도 `POST /api/social/threads/:id/attachments`는 본문 파싱 전 `403 / resident-attachments-only`로 거절한다. 임의의 주민 역할 헤더나 주민 ID를 전송해도 허용하지 않는다. 비인증 요청은 기존 인증 단계에서 거절한다.

기존 첨부 열람, 주민의 내부 창작 그림 생성, 목격 근거가 있는 클립 첨부, 텍스트 댓글·답글·추천, 기존 관리 기능은 보존한다. 업로드를 막기 위해 기존 파일을 삭제하거나 기존 첨부의 작성 주체를 다시 쓰지 않는다.

## 설정 UI

자동활동, 다음 방송 방문, 창작 이미지, 개별 공간 활동은 설명이 있는 스위치로 표시한다. 관심 주제와 북마크 필터는 선택 상태가 드러나는 버튼을 사용한다. 기본 설정값과 저장 키는 그대로다. 상위 기능을 꺼도 하위 선택을 삭제하지 않는다.

스위치는 이름이 고정된 네이티브 버튼과 `role=switch`, `aria-checked`, 설명 연결을 사용한다. 관심 주제는 `aria-pressed`로 선택을 전달한다. 키보드 초점, 움직임 감소, 고대비 모드 스타일을 제공한다. 저장 중 중복 요청을 막고, 서버가 확인한 뒤 표시 상태를 갱신한다. 실패 시 저장되었다고 표시하지 않는다.

접근성 기준: https://www.w3.org/WAI/ARIA/apg/patterns/switch/
화면·시스템 소리 취득 기준: https://www.electronjs.org/docs/latest/api/desktop-capturer

## 검증 재현

- 전체 검사: `npm run check`
- 의존성 보안 검사: `npm audit --audit-level=high`
- 추가 회귀: `test/clip-system-audio.test.js`, `test/community-writing.test.js`, `test/community-controls.test.js`
- 네이티브 합성 검사: `node scripts/verify-clip-community.cjs`

네이티브 검사는 매번 새로운 `artifacts/clip-community-native-*` 디렉터리와 별도 Electron 프로필을 사용한다. 실제 화면·마이크·AI 계정에는 접근하지 않는다. 합성 화면과 440Hz 시스템 음원, 880Hz 마이크 음원을 녹음하고 분석 복제 트랙 종료 이후 구간을 디코딩해 분리를 확인한다. 실제 커뮤니티 컴포넌트의 키보드 입력, 저장 실패, 연타 방지, 좁은 화면 배치도 확인한다. 생성된 JSON, PNG, WebM은 로컬 검증 자료이며 배포 파일이 아니다.

자동화가 통과해도 설치된 앱에서 실제 게임·Windows 출력 장치 조합을 확인한 것과 같지 않다. 실제 모델이 여러 게시물에 걸쳐 자연스럽게 표현하는지에 대한 품질 평가는 별도로 필요하다.
