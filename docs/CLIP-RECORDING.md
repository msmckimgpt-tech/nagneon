# 영상·음성 클립과 장면 기록

## 2026-09-23 녹화·업로드 복구

`ClipBuffer`가 브라우저 `setTimeout`/`clearTimeout`을 clock 객체의 메서드로 호출해 Electron에서 `Illegal invocation`이 발생했다. 녹화 시작 직후 구간 회전 타이머와 정리가 실패했다. `ClipUploads`도 전역 `fetch`를 업로드 객체의 메서드로 호출해 같은 오류로 파일 전송에 실패했다. 두 경로를 전역 함수를 호출하는 래퍼로 변경했다. Node에서 주입한 가짜 타이머·요청만 사용하는 기존 검사는 브라우저의 receiver 제약을 재현하지 못했다.

녹화 초기화·인코더 오류와 선택 시점의 버퍼 누락은 한국어 오류로 알린다. 설정 동의·방송 세대·취소·최근 구간 제한·서버 미디어 검사·저장 용량 제한은 유지한다. 화면과 마이크를 자동으로 새로 연결하지 않는다.

## 표시 및 호환성

- 영상 또는 음성 파일이 연결된 기록은 핫클립에서 재생한다.
- 사진·대화 기록은 방송 밖 이야기 → 방송 커뮤니티의 `장면 기록` 게시글로 표시한다. 사진은 첨부파일로, 당시 채팅은 펼쳐보기로 제공한다.
- 원본 clips 저장소·ID·제목·작성 관객·댓글/답글·추천·미디어 파일을 그대로 참조한다. World 게시글을 중복 생성하거나 파일을 옮기는 마이그레이션은 없다. 기존 삭제 API의 의미를 유지한다.
- 버퍼 구간이 완성되어 미디어가 저장되면 핫클립 목록에 표시한다. 녹화가 없던 과거 기록은 사진·대화로 보존하며 영상·음성을 만들어 복원하지 않는다.
- 저장 스키마 변경이 없어 이 변경만으로 프로필 변환은 필요 없다. 제품의 다른 변경에 따른 프로필 최소 버전은 기존 설치 계약을 따른다.

## 검증

작업별 원본은 해당 worktree의 `artifacts/`에 보존한다.

- `npm run check`: format 검사 → 886개 테스트 → TypeScript/Vite 빌드 통과 (`check-complete.log`).
- `npm audit --audit-level=high`: 취약점 0건 (`audit.log`).
- `scripts/verify-clip-capture.cjs`: 실제 Electron, 실제 기본 타이머/fetch, 합성 canvas·게임음 440Hz·마이크음 880Hz를 사용했다. 실제 MediaRecorder → 업로드 → 서버 디코더 → 디스크 → 실제 ClipMedia 재생, 마이크 음성 끄기 시 영상 재생 유지, 서버 재시작 후 파일/메타데이터와 Range 응답을 확인했다. `clip-capture-1790145340764/result.json`.
- `scripts/verify-recorded-clip.py`: 저장된 영상의 게임음, 별도 마이크 파일, 화면 없는 음성 파일을 디코딩해 기대 주파수가 실제로 담겼고 다른 소리와 분리되는지 확인한다. 같은 폴더의 `audio-spectrum.json`.
- `scripts/verify-scene-community.cjs`: 사진 기록의 핫클립 제외, 커뮤니티 첨부 표시, 기존 댓글·답글 보존, 새 댓글 저장, 렌더러 재시작과 삭제 확인. `scene-community-1790145178272/result.json`, `community.png`.
- 브라우저 receiver 제약 회귀 검사를 기본 타이머와 기본 fetch 경로에 추가했다. 시험 harness의 CSS/TSX 의존성은 실제 컴포넌트를 번들하여 검사한다.

위 검증은 합성 입력이며 물리 마이크·게임 화면·실계정 AI 검증이 아니다. 사용자 프로필을 시험 자료로 복제하거나 실행 중인 사용자 앱을 변경하지 않았다. 패키지 생성·무결성 확인은 실제 사용자 앱 설치·업데이트·장치 검증과 구분한다. 이 문서의 통과 항목만으로 정식 릴리즈나 설치 완료를 선언하지 않는다.
