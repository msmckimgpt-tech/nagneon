# 마이크 연속 청취와 로컬 원음 복구

실제 방송에서 마이크를 켜면 장치 입력 트랙을 연속으로 읽어 16 kHz 단일 채널 PCM으로 변환합니다. 1초 분량을 앱 프로필의 `data/speech-recovery/<방송 ID>/<입력 epoch>/` 아래에 저장한 뒤 그 범위를 로컬 음성 인식기에 전달합니다. 설치 앱은 같은 프로세스의 원음 저장소에 직접 기록하므로 음성 인식 대기나 HTTP 요청 지연으로 녹음을 멈추지 않습니다. 인식 결과는 발화 순서에 따라 관객에게 전달합니다. 짧은 인식 실패에는 보존된 원음을 다시 읽어 처리하며, 대기 음성의 오래된 항목을 임의 삭제하지 않습니다.

**원음은 민감한 음성 데이터입니다.** 마이크와 게임·시스템 출력은 입력 epoch와 출처를 구분하여 저장합니다. ChatGPT 구독 음성을 선택했다면 동의한 원음도 제공처로 전송합니다. 로컬 인식 모드는 전사와 선택 화면을 제공처에 전달하며 원음을 그 모드에서 보내지는 않습니다. 원음 폴더를 동기화 서비스나 공개 이슈에 올리지 마세요.

연결 설정의 **원음 보관**에서 기간(1·6·24·72·168시간)과 최대 용량(256 MB·1·2·4 GB)을 설정합니다. 기본값은 24시간·2 GB입니다. 변경은 방송을 중지한 뒤 적용하며, 기간을 줄이면 만료 기록이 바로 정리될 수 있습니다. 앱 시작 시와 실행 중 1분마다 만료 파일을 정리하고, 앱이 종료돼 있던 동안의 만료 파일은 다음 실행 때 정리합니다. 현재 방송과 다운로드·복구 중인 원음은 보호합니다. 용량을 채우기 위해 아직 보관 기간이 남은 원음을 자동 삭제하지 않습니다. 여유가 부족하면 입력을 중단하고 조치를 안내합니다.

**원음 보관** 목록에서 출처·용량·만료 시각을 확인하고 WAV로 다운로드하거나 종료된 원음을 삭제할 수 있습니다. 삭제 확인 후 해당 입력의 PCM만 지우고 기존 채팅·관객·클립 기록은 보존합니다. 삭제 표시를 남겨 늦은 저장 재시도가 삭제한 원음을 다시 만들지 않게 합니다. CLI로 내보내려면 앱을 종료한 뒤 다음 명령을 사용할 수 있습니다. `--data-dir`은 실제 설치본 프로필의 `data` 폴더를 지정합니다. 출력 파일은 새 경로여야 하며 기존 파일을 덮어쓰지 않습니다.

```powershell
node scripts/export-speech-recovery.mjs --data-dir '<앱 프로필의 data 경로>' --list
node scripts/export-speech-recovery.mjs --data-dir '<앱 프로필의 data 경로>' --session '<방송 ID>' --epoch '<입력 epoch>' --output '<새 WAV 파일 경로>'
```

마이크 장치·입력 트랙 처리가 실패하면 앱은 오류를 표시하고 해당 입력을 다시 연결합니다. 원음 저장 자체가 오래 실패해 미저장 원음이 64 MiB를 넘으면 마이크를 멈추고 오류를 표시합니다. 음성 인식 지연·실패만으로는 이 한도를 적용하지 않습니다. 저장 재시도는 방송 중단 뒤에도 이어지지만, 앱 자체가 종료되면 아직 디스크에 확인되지 않은 부분은 보존되지 않습니다. 디스크 또는 앱 프로세스가 중단된 시점의 마지막 미저장 버퍼도 복구되지 않을 수 있으므로, 발언 누락이 절대 없다고 보증하지 않습니다.
