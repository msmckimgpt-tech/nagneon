# 발화 전달과 대화 우선순위 개선

2026-09-13. 이 단계는 짧은 발화의 입력 대기·누락과 기획 방송의 반복 질문을 개선한다. 모델 자체의 실시간 응답 목표를 달성했다고 선언하지 않는다.

## 실제 동작

- 마이크는 사용자가 켠 뒤에만 녹음한다. 50ms 단위 음량 표본으로 발화 구간을 구분한다. 200ms 이상 음성이 있고 650ms 조용해지면 전사로 넘긴다. 짧은 휴지는 이어 붙이고 긴 발화는 최대 12초에서 나눈다. 배경 소음과 작은 목소리에 따른 오검출은 실제 사용자 평가가 필요하다.
- 이전 전사가 진행 중이어도 뒤의 녹음은 순서대로 기다린다. 8개 대기 구간을 넘으면 마이크를 멈추고 취소된 발언을 다시 말하도록 명확히 안내한다. 무한 메모리 누적이나 조용한 버림을 하지 않는다.
- 마이크를 끄면 대기 녹음과 진행 중 HTTP/STT 결과를 취소한다. Python에서 이미 계산 중인 전사를 강제 중단하는 방식은 아니며, 취소된 UUID 결과가 뒤 요청을 오염시키지 않게 분리한다. 방송 종료는 화면·마이크와 전달 대기 글도 정리한다.
- 모델 요청 중 들어온 발언은 메시지 ID로 보존한다. 성공한 요청에 실제 포함된 ID만 지우므로 뒤에 추가된 말이 잘리지 않는다. 한국어와 이모지가 섞여도 HTTP 글자 제한 내에서 서로게이트 쌍을 보존해 분할한다.
- 전사가 도착하면 관객 요청을 즉시 시도한다. 이전 모델 응답이 진행 중이면 기존 직렬 처리 후 전달한다. 1.5초 보조 폴링은 유지된다.
- 기획 장면의 일반 질문보다 스트리머가 방금 밝힌 선택·거절·감정을 우선하도록 관객 지침을 수정했다. 실제 회차 전환은 기존 사용자 조작으로만 확정된다.

## 모델 입력 문맥

공식 Codex CLI의 요청별 `skills.max_context_tokens=1` 설정으로 이 서비스에서 쓰지 않는 개발 스킬 카탈로그가 입력에 포함되지 않도록 했다. 사용자 전역 설정, 로그인, `gpt-6-astra` 모델과 `low` 추론 수준은 유지한다. 비교용 `BACKSEAT_MINIMAL_SKILL_CONTEXT=0`은 기존 동작을 선택한다. [공식 설정 문서](https://learn.chatgpt.com/docs/config-file/config-reference)

실제 12회(잡담·선택·화면 각 2쌍, 실행 순서 교차) 비교:

| 조건 | 평균 입력 토큰 | 평균 요청 시간 |
|---|---:|---:|
| 기존 카탈로그 문맥 | 13,670.8 | 11.921초 |
| 축소 문맥 | 8,127.3 | 11.737초 |

입력은 평균 5,543.5토큰(40.6%) 감소했다. 표본이 작고 사례별 시간이 엇갈려 지연 개선의 증거로 삼지 않는다. 모든 12회가 스키마에 맞는 응답을 반환했다. 원문·사용량·시간: `artifacts/spectator-context-benchmark.json`, `.log`.

별도 실제 6회 선택 우선순위 비교에서는 항로와 피날레의 기존 반응이 선택 질문을 반복했다. 수정본은 이미 정한 방향에 반응하거나 미래의 우리에게 편지를 썼다. 사연 중단/휴식 요청은 양쪽 모두 존중했다. 3쌍의 정성 표본이며 일반적인 자연스러움 보장은 아니다. `artifacts/conversation-priority-live.json`, `.log`.

## 실행 검증

- `test/speech-flow.test.js`: 발화 경계, 느린 전사와 순서 보존, 취소 세대, 오류 회복, 명시적 대기 한도, 요청 중 새 발언 보존, 이모지, 실제 HTTP 취소 전달.
- `test/local-speech.test.js`: 취소된 UUID의 오류가 새 요청을 거절하지 않음, 잘못된 성공 ID 무시, 시작 실패와 프로세스 종료.
- `scripts/verify-speech-flow-desktop.cjs`: 별도 프로필에서 실제 AudioContext/MediaRecorder/WebM/HTTP를 사용한다. 음원과 관객 모델은 합성이다. 느린 3초 전사 중 3개 구간 보존, 인식 순서, 마이크 끄기/늦은 결과 억제를 검증한다.
- 같은 스크립트의 `--real-speech`: 배포에 포함된 Python/한국어 모델로 합성 한국어 음원 2.8초를 입력했다. 첫 구절은 입력 후 2.204초에 전사 요청, 4.190초에 전사 완료, 4.195초에 관객 요청에 도달했다. 결과는 “안녕하세요 여러분”. 다음 구간은 테스트 종료 때 취소했다. 물리 마이크나 실제 사람 발화 시험은 아니다. `artifacts/speech-flow-real-desktop-test.json`.
- 초기 실제 음성 UI 검증의 실패 두 원인은 테스트의 방송 시작 대기 누락과 renderer 코드의 최상위 await였다. 실제 페이지/오류를 확인해 테스트를 고쳤다. 관련 원본: `speech-flow-real-harness-failure.json`. 제품 성공으로 간주해 넘어가지 않았다.

## App Server 조사 경계

공식 App Server stdio의 초기화·일시 스레드·구조화 출력·agentMessage delta를 시험했다. 단일 실제 호출의 첫 JSON 조각은 3.583초, 완료는 7.632초였지만 초기 조각은 대부분 메타데이터였고 표시 가능한 완전한 채팅은 뒤에 나왔다. `--ignore-user-config`가 이 명령에서 지원되지 않고 사용자 MCP 설정이 병합되는 차이를 확인했다. 호스트의 특정 MCP만 비활성화한 실험이며, instructionSources에 전역 AGENTS 경로도 남았다. 따라서 이 프로브의 `passed`는 프로토콜 성공만 의미하고 출시용 구성 격리나 성능 합격을 의미하지 않는다. 기존 CLI 실행 연결을 유지한다.

근거: `artifacts/codex-stream-probe.json`, `codex-stream-config-rejected.json`, `codex-stream-probe-retry.log`, `scripts/probe-codex-stream.mjs`; [공식 App Server 문서](https://learn.chatgpt.com/docs/app-server).
