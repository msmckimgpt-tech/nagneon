# 사용자 지정 모델과 역할별 라우팅

## 검토 결론

구현 가능하다. 현재 Studio는 관객 메시지·기억·활동 변경을 한 응답으로 받아 공통 검증을 거쳐 적용한다. 이를 관객별 별도 호출로 쪼개면 중복 상태 반영과 목격 범위 문제가 생기므로, 이번 구현은 **요청 단위로 제공처를 선택**한다. 단일 제공처도 같은 Studio·기록·음성 인식 경로를 그대로 사용한다.

`Studio 요청 → 작업 분류 → 사용자 경로 → 제공처 어댑터 → 기존 응답 검증·반영`

모델 추천 목록을 라우팅의 허용 목록으로 사용하지 않는다. 역할별 설정에서 Codex와 API 모델 ID, 설치된 Ollama 모델명을 직접 지정한다. 모델 접근 권한과 성능은 제공처·계정·기기별로 확인해야 한다.

## 사용

방송 설정의 계정 연결에서 **역할별 모델 라우팅**을 연다.

1. 기존 연결을 기본으로 유지하거나 연결을 추가한다. Codex는 기존 공식 CLI 구독 로그인을 사용한다. Ollama는 이 PC의 loopback 서버를 사용한다.
2. API는 HTTPS 또는 `http://127.0.0.1` 주소와 모델 ID를 지정한다. Responses 또는 Chat Completions 형식, 실제 모델의 화면 입력/웹 검색 지원 여부를 선택한다. Chat Completions에는 웹 검색 도구를 제공하지 않는다. JSON Schema 응답 지원이 필요하다.
3. 기본 경로와 일반 대화·화면·요청받은 훈수·방송 외 활동/후일담 경로를 지정한다. 지정하지 않은 역할은 기본 경로를 따른다.
4. 필요할 때만 대체 연결을 순서대로 지정한다. 선택한 API에는 같은 입력이 전송되고 별도 요금이 생길 수 있다. 대체 연결 없는 것이 기본이다.
5. 경로 저장 후 연결별 API 키를 입력하고 응답 확인을 실행한다. 키는 메모리에만 있고 앱 종료 시 삭제된다. API 연결을 삭제하거나 주소를 바꾸면 기존 키는 재사용하지 않는다. 단일 API 설정의 키도 새 연결에 자동 복사하지 않는다.

기존 `AI 제공처·관객 모델 선택`을 적용하면 단일 모델 사용으로 돌아간다. 대화·관객·기억 데이터는 복사하거나 나누지 않는다. 저장은 방송·요청·계정 연결이 없는 대기 상태에서만 가능하다. 연결별 응답 확인은 합성 인사 한 번이며 실제 모델 사용량을 소모한다.

## 분류와 실패 처리

- 방송 외 활동 → 명시적 훈수 요청 → 화면 포함 → 일반 대화 순서다. 현재 프레임뿐 아니라 마이크 발언 당시의 첨부 화면도 화면 입력으로 분류한다. 사용자 문장/모델 출력의 지시로 경로를 바꾸지 않는다.
- 화면·검색 지원 조건은 역할과 별도로 검사한다. 입력을 조용히 삭제하거나 검색 기능을 끄지 않는다. 조건이 맞지 않으면 지정된 대체 경로만 고려한다.
- 경로당 기본 1개 + 대체 최대 2개. 재귀 라우팅·중복 연결·존재하지 않는 연결은 저장할 수 없다. 시도별 1~60초, 전체 최대 90초이며 기존 Studio 취소/만료 검사가 우선한다.
- 연결 불가, 지원 기능 부족, 모델 불가, 네트워크·시간 초과에만 대체한다. 취소, 인증 오류, 사용량 제한, 잘못된 출력은 중단한다. 성공 응답 뒤 추가 호출하지 않는다. 시간 초과 전에 서버가 작업을 처리했을 수 있으므로 대체 호출은 비용 없는 재시도가 아니다.
- 앞 시도의 종료/정리를 기다린 뒤 다음 호출을 한다. 실제 추가 추론 시도는 세션 호출 수에 포함한다. 연결 시험은 기존 시험 집계 방식을 유지한다. 실패한 제공처가 보고하지 않은 토큰은 추정해서 누적하지 않는다.

## 저장·확장·복귀

- `provider-choice.json`에서 기존 단일 선택 형식 또는 `kind: routing, version: 1`을 저장한다. 기존 사용자는 자동 전환되지 않는다. 성공한 검증/저장 후 메모리 상태를 교체하고 실패하면 이전 설정을 유지한다.
- `shared/provider-routes.json`: 사용자 역할 이름.
- `server/provider-routing.js`: 설정 스키마, 역할/기능 판정, 순차 대체 정책.
- `server/configured-api-provider.js`: Responses/Chat Completions 호환 어댑터. 다른 엔드포인트의 API 키·환경 변수를 상속하지 않고 리다이렉트도 따르지 않는다.
- `server/provider-choice.js`: 기존 제공처와 라우터의 공통 진입점, 메모리 키 수명.
- 새 독자 프로토콜은 스키마·팩토리·UI 편집 필드를 추가하고 `check/status/react` 계약과 기존 Observation 검증을 따른다. Gemini/Anthropic의 독자 API나 임의 HTTP API까지 자동 호환된다는 뜻은 아니다.
- 이번 구현은 짧은 worker 전용 입력으로 프롬프트를 재설계하지 않는다. 경량 모델의 전체 입력 처리/응답 품질 문제를 라우팅 지원과 구분한다.
- 구버전 앱으로 돌아가기 전에 단일 제공처 설정을 적용한다. 새 routing 형식은 이전 배포본이 읽지 못할 수 있다. 백업 복원은 `provider-choice.json`만 대상으로 하며 사용자 대화 저장소를 초기화하지 않는다.
