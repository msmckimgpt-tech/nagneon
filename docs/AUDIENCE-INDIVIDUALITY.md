작업 기준 main은 `d3a23fce0249275df7d9b1c374618d91eeeb5491`이다. 개발은 `G:/dev/ai/00_game_backseat-worktrees/audience-individuality`, 브랜치는 `codex/audience-individuality`에서 수행한다. 판매 준비 목표 중 관객 개성·자연스러운 대화 항목을 개선한다. 기존 연속 장면 구현의 재보고만으로는 새 진전이 아니므로 실제 생성 결과의 결함을 다음 작업으로 선택했다.

## 발견한 문제

앞선 클립 유입 검증의 실제 Astra 관객 세 명은 소금책갈피·차곡차곡·문구산책이었다. 문구·책갈피·수첩, 취향 존중, 조용히 듣다 짧게 질문한다는 구성이 겹쳤다. 기존 지시에는 다양하게 만들라는 문장이 있었지만, 생성 요청의 `settings.personas=[]` 외에 기존 인물 분포를 참고할 정보가 없었다.

원본은 `G:/dev/ai/00_game_backseat-worktrees/clip-arrival-context/artifacts/clip-arrival-astra-fMxdTB/birth-calls.json`이다. 실제 사용자 프로필이 아닌 이전 시험의 합성 관객 생성 결과이며, 이번 검증에서 자체 증거 폴더로 복사하고 해시를 기록한다. 이 세 명이 한국 시청자 집단을 대표하거나 모든 생성이 획일적이라는 의미는 아니다.

## 구현과 경계

- 도착이 승인되고 포인트 보관이 완료된 시점에만 관심 분야·대화 방식·선호의 갈등·이름 방향·사회성·게임 숙련도를 조합한다. 기다리는 인물 목록이나 미래 관객은 만들거나 저장하지 않는다. 완성된 이름·성격·가치는 기존과 같이 한 번의 실제 모델 생성으로 구성한다.
- 기존 일반 관객의 성격·가치 설명에 대한 제한된 키워드 일치로 겹치는 방향에 낮은 확률을 준다. 같은 취향의 사람도 여전히 올 수 있다. 공개 발언량·웃음·호응을 균등 배분하는 규칙은 아니다. 실제 인구 통계나 특정 커뮤니티 이용자의 심리 모델로 주장하지 않는다.
- 12개 관심 분야, 6개 대화 방향, 6개 선호 갈등은 넓은 창작 방향이다. 구체적인 취미·기울어지는 선택·예외 조건은 모델이 정한다. 개인의 취미를 모든 발언에 붙이거나 같은 유행어를 반복하는 성격으로 만들지 않도록 지시한다. 향후 유입 경로와 실제 대화에서 나타나는 성향 변화는 기존 동작을 유지한다.
- 추천 탐색·클립·공략 등 유입 동기는 기존 경로가 정한다. 사회성과 숙련도는 경로별 완만한 확률 차이를 가지며, 숙련도 수치가 특정 게임의 사실이나 시청 경험을 부여하지 않는다. 모델·추론 수준·호출 한도·계정 연결은 그대로다.
- 원래 인물의 설명·ID·메모·기억·별명 이력·클립 내용은 창작 방향에 복사하지 않는다. 중복을 피하기 위한 현재 공개 닉네임만 별도로 전달한다. 이 목록으로 다른 관객의 성격이나 친분을 아는 것으로 취급하지 않는다.
- 생성용 상세 지시는 생성 호출에만 추가한다. 일반 방송과 개인 면담에는 전달하지 않는다. 방향 자체는 저장하지 않고, 실제로 구성된 인물만 기존 world 트랜잭션으로 확정한다. 기존 관객을 다시 쓰거나 성격을 해금하지 않는다. 재시도·실패 환불·강제 종료 복구는 기존 원자적 유입 흐름을 따른다.

## 검증

`test/audience-individuality.test.js`는 집중된 기존 취향의 반복 확률 감소, 공유 취향 허용, 경로별 경향, 원본 개인 정보 배제, 저장 후 동일 상태에서의 재현, 실제 입장·재시작·숨은 성향·실패 환불·중복 호출 방지를 검사한다. 유입·클립 기억 회귀를 포함한 초기 집중 검사 35개가 통과했다. 최초 필수 전체 검사 449개와 TypeScript/Vite 빌드도 통과했으며, 이후 발견한 이름 중복 보완 뒤 최종 검사를 별도로 수행한다.

`scripts/verify-audience-individuality.mjs`는 다음을 실제 `gpt-6-astra` / `low`로 실행한다.

1. 같은 Just Chatting 클립 소개를 계기로 관객 6명을 순차 생성한다.
2. 디스크 재시작 후 동일한 취향 질문을 각자에게 묻고, 제품의 채팅 큐를 실제 pump로 전달한다.
3. 앞선 시험의 관객 세 명에게도 같은 질문을 묻는다. 과거 생성 모델의 완전한 A/B 재실험이 아니라 보존된 기존 인물과 새 인물의 작은 비교다.
4. 일반 그룹 대화에서 의견을 묻고, 공략이 필요하면 요청하겠다는 말과 집중하겠다는 말에 반응하는지 본다.

각 호출의 전체 입력·응답·수치·시간·소스 해시를 독립 파일로 저장한다. 기계 판정만으로 자연스러움을 합격 처리하지 않으며 문장·후원·클립 선택과 대화 연결을 직접 읽는다. 사용자 장치·앱·방송 데이터에 접근하지 않는다.

초기 실행 `artifacts/individuality-astra-VWt8U1`의 18회 호출에서는 여섯 취향이 나뉘었으나 '모루'가 두 번 생성되어 숫자 접미사로 구분됐다. 기계 판정은 이를 놓쳤다. 현재 닉네임 목록을 생성에 추가하고 원시 이름과 저장 이름이 일치하는지도 최종 시험에서 확인한다. 시험의 채팅 큐 전달 후 시계가 실제 시각으로 되돌아가 다음 질문에서 일부 직전 대화가 아직 미래로 보일 수 있는 문제도 발견했다. 최종 시험은 단조롭게 증가하는 합성 시계를 사용한다. 초기 호출에 로드된 원본은 `artifacts/source-first/`에 보존했고 이 실행을 최종 코드의 대화 연속성 증거로 사용하지 않는다.

두 번째 실행 `artifacts/individuality-astra-FQHxfj`도 18회 호출과 기계 판정이 통과했지만, 그룹 대화의 입력을 읽자 일반 관객 없이 매니저만 있었다. 첫 입장을 보장하려고 둔 시험 난수 0이 10초마다 진행되는 실제 자리 비움 분기까지 발생시켰다. 개인 질문에서는 호명으로 다시 활성화되어 이 문제가 가려졌다. 이는 제품이 침묵 요청을 잘 따랐다는 증거가 아니다. 이후 시험은 입장 직후 난수 .5로 바꾸고 요청 전 목격자 수와 실제 모델 입력의 일반 관객 존재를 검증한다. 제품 소스가 같은 것이 확인된 이 실행의 관객 생성 6회만 재사용하고, 개별·그룹 대화 12회는 다시 실행한다. 재사용 원본·그 당시 검증기 해시와 이번 검증기 해시는 별도로 보존한다.

## 남은 범위

키워드 분산은 의미 중복을 완전히 찾는 모델이 아니며, 새 어휘·복합 관심사·넓은 분류를 놓칠 수 있다. 이름의 숫자 접미사는 마지막 충돌 처리로 남아 있다. 실제 생성 과정 전체에서 충돌이 불가능하다고 보장하지 않는다. 여섯 명과 몇 차례 합성 잡담만으로 장기 말투 구별·관계 발전·반복 플레이 몰입을 입증하지 않는다. 실제 게임·음성·긴 방송과 편향 평가, 향후 실사용 피드백은 별도로 필요하다.

이번 취향 질문의 답변에는 여전히 비슷한 길이와 '저는 … 할래요' 형태가 자주 나타났다. 취향과 선택의 다양화가 어투의 모든 획일성을 해결했다는 뜻은 아니다. 일상적인 화면·소리·관객 간 대화에서 말의 길이·리듬·농담이 어떻게 달라지는지 후속 검증 대상으로 남긴다.

Computer Use 중단 지침을 유지한다. 네이티브 앱이나 사용자 실행본을 재시작하지 않았으며 패키지 교체·Steam 게시·푸시는 하지 않는다. 소스 통합과 배포·판매 완료는 구분한다.
