# 선택형 판단 서비스 기반

`server/decision/index.js`는 생성 모델과 분리된 판단 보조 모듈이다. 현재 앱의 Studio, 제공처 라우팅, 설정 UI에는 연결되어 있지 않다. 실제 JEV SDK, API 호출, 키 저장이나 새로운 의존성도 없다. 이 모듈을 추가해도 설치된 앱의 판단 품질이나 기능은 달라지지 않는다.

기본 모드 `off`는 요청 ID, 어댑터 호출, 진단 이벤트를 생성하지 않는다. `shadow`는 관찰 결과만, `assist`는 제안만 반환하며 두 결과 모두 `apply: false`다. 생성된 값은 신뢰하지 않는 입력이며 소비자가 도메인 스키마와 최신 상태를 검증해야 한다. 권한, 목격 범위, 기억 정정·삭제, 포인트, 저장과 최종 수용은 기존 controller의 책임이다.

`JevAdapter({ judge })`의 주입 함수는 `{ task, input, signal }`을 받고 정의된 `value`를 포함한 객체를 반환한다. 이는 제품 내부 경계이며 실제 공급자 API 규격을 뜻하지 않는다. 공급자 연결 전에 해당 SDK의 취소·종료 보장을 검증해야 한다.

서비스는 기본 1초 제한 시간과 2개 동시 요청 한도를 사용한다. timeout과 공급자 오류는 기존 경로로 복귀할 수 있는 `abstain`을 반환하고, 호출자 취소와 서비스 종료는 호출자에게 rejection으로 전달한다. timeout 후에도 끝나지 않은 어댑터 작업은 동시 요청 수에 계속 포함되며 늦은 결과는 수용하지 않는다. 자동 큐나 재시도는 없다.

`close()`는 신규 작업을 거절하고 진행 중인 어댑터에 취소를 전달한 뒤 실제 정리가 끝날 때까지 기다린다. JavaScript Promise의 외부 작업을 강제로 종료할 수는 없으므로 취소에 응답하지 않는 어댑터가 있으면 drain도 끝나지 않는다. 이러한 어댑터는 앱 종료 경로에 연결해서는 안 된다. timeout으로 호출자를 복귀시키는 것과 외부 작업의 종료는 별개다.

진단에는 task, mode, 요청 ID, 숫자 revision, 경과 시간, 결과 종류와 제한된 오류 코드만 담는다. 입력·결과 본문, scope token과 공급자 오류 메시지는 전달하지 않는다. 결과 메타데이터는 요청의 식별자·모드·scope·revision을 덮어쓸 수 없다.

검증은 `node --test test/decision-service.test.js`와 `npm run check`로 수행한다. 테스트는 합성 어댑터를 사용하며 실제 JEV의 한국어 품질, 지연, 비용이나 데이터 처리 조건을 검증하지 않는다. 실제 연결에는 최소 입력 투영, 최신성 확인, 보호 기억 보존, 명시적 전송·비용 안내와 공급자 검증이 필요하다.
