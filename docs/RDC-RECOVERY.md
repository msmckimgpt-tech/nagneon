# RDC 장치 연결 복구

현재 사용자에게 설치된 RDC 에이전트만 점검하고 필요하면 시작한다. 인증 저장소를
복사하지 않으며 방화벽, 접근 허용 경로, 자동 시작 설정을 변경하지 않는다.

## 실행

저장소에서 `python scripts/web-development/install.py`를 실행하면 복구 스크립트도
현재 사용자의 전역 bin에 설치된다. 스크립트 실행이 허용된 PowerShell에서 실행한다. 현재 머신은 PowerShell 7의
RemoteSigned 정책으로 검증하며, Windows PowerShell 5.1은 기본 Restricted이므로
사용하지 않는다. 복구 스크립트는 실행 정책을 변경하거나 우회하지 않는다.

```powershell
& "$HOME\.local\share\ai-web-development\bin\repair-rdc.ps1" -ProjectPath 'G:\dev\ai\00_game_backseat'
```

다른 머신에서는 실제 프로젝트 경로로 바꾼다. `-Root`로 설치 위치를 명시할 수 있다.
기본 동작은 실행 중인 에이전트를 유지한다. 멈춘 연결을 재시작해야 하며 해당
에이전트가 사용 중이지 않음을 확인한 경우에만 `-RestartOwned`를 추가한다.
재시작은 연결된 작업을 끊을 수 있다.

PID, 시작 시각, 실행 파일, RDC 명령 경로가 기록과 일치할 때만 해당 프로세스를
다룬다. PID 재사용, 불명확한 소유권, 별도로 실행된 RDC가 있으면 중단한다.
재인증 중 다시 실행해도 에이전트나 인증 요청을 중복 생성하지 않는다.

## 결과와 다음 행동

| state / 종료 코드 | 의미와 조치 |
|---|---|
| LOCAL_READY_REMOTE_UNVERIFIED / 0 | 프로세스와 시작 로그 확인. 실제 원격 접근은 아래 절차로 확인 |
| AUTH_REQUIRED / 2 | 기존 계정으로 공식 인증 필요. logPath에서 일회용 코드를 확인하고 verificationUrl에서 인증 후 재실행 |
| STARTING_OR_RECONNECTING 또는 EXITED / 3 | 기동 중이거나 종료됨. 지정 로그를 로컬에서 확인; 자동 무한 재시도하지 않음 |
| 오류 / 1 | 설치 또는 프로세스 소유권 등의 문제. 오류 해결 후 재실행 |

기본 대기는 15초이며 `-WaitSeconds`는 0~60초다. 로그에는 일회용 인증 코드가
있을 수 있으므로 원문을 저장소나 외부 보고서에 포함하지 않는다. JSON에는
인증 코드·토큰을 출력하지 않는다. 비밀번호·MFA 등은 공식 인증 화면에서 수행하며
스크립트가 대신 처리하거나 자격 증명을 읽지 않는다.

최종 확인은 공식 RDC `list_devices`를 조회하고 현재 머신의 deviceId를 명시하여
프로젝트의 비밀 없는 파일을 읽는 것이다. 첫 온라인 장치를 자동 선택하지 않는다.
로컬 로그의 과거 ready 메시지나 종료 코드 0만으로 현재 원격 연결을 보증하지
않는다. 읽기 성공은 저장소 쓰기·셸 실행 권한까지 부여하지 않는다.

## 2026-09-22 복구 기록

로컬 에이전트가 종료됐고 재시작 시 `Invalid Refresh Token: Already Used`로
저장된 세션이 거절됐다. 공식 인증 후 기존 mckim 장치가 online으로 복구됐고
RDC get_file_info로 현재 프로젝트 package.json 접근을 확인했다. 다른 온라인
장치의 동일 경로에는 파일이 없었으므로 대상 장치 지정이 필수였다.
검증은 임시 경로의 PID 재사용 거절·설치 누락 무변경 및 실제 실행 중 에이전트의
반복 호출 시 PID 보존을 확인한다. 제품 앱의 계정 구현은 변경하지 않는다.
