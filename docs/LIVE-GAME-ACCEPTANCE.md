## 관객과 실제 대화

관객 이름은 `뭉칫`. 아래는 키보드로 전송한 발언과 실제 모델 응답이다.

1. “뭉칫 어서 와요 ㅋㅋ 오늘은 처음부터 천천히 해볼게. 일단 훈수 없이 같이 봐줘.” → “좋아요, 저도 같이 알아가는 쪽으로 볼게요!”
2. “아 두 대미지는 맞네 ㅋㅋ 뭉칫, 이번 턴은 어떻게 할까? 지금 손패 보고 힌트 딱 하나만 부탁해.” → “안 맞고 넘기려면 수비 두 장이요! 아까처럼 방어도 10이면 이번 공격 6은 다 막겠어요.”
3. 그 뒤 추가 발언 없이 “수비 한 장이면 이번 공격 6 중에 5는 막겠어요!”가 올라왔다.

저장된 발언→첫 답변 시각 차이는 각각 14,252ms, 18,454ms였다. 전송/생성/큐 표시를 합친 두 관측값이며 모델 자체 지연이나 음성 인식 지연으로 일반화하지 않는다. 첫 입장 인사는 모델 응답으로 계산하지 않는다.

남아 있는 품질 문제:

- “힌트 하나만” 이후 같은 관객의 추가 훈수. 요청 응답이 끝난 뒤 반복 호출에서 대화를 이어가는 기준을 점검해야 한다.
- 정적인 선택 화면에서도 시각 분석 호출은 계속됐고, 입장 인사 외 잡담은 거의 없었다. 게임 애니메이션, 관객 한 명, 유입 직후의 조건을 분리해 검사해야 한다. 호출 횟수와 방송 분위기를 같은 지표로 취급하지 않는다.
- 타격과 다음 턴 직후 일부 관찰은 적 체력 44/44를 유지하다 이후 38/44로 교정됐다. 높은 전체 확신 표시와 개별 수치의 정확도를 구분할 필요가 있다.
- 오버레이 창 생성과 동일 채팅의 접근성 트리는 확인했다. 현재 오버레이는 `setContentProtection(true)`여서 캡처 이미지에 표시되지 않는다. 이번 캡처만으로 실제 게임 위 가독성·투명도 성공을 주장하지 않는다.
- 억양·실제 음성 인식, 긴 플레이, 핫클립 발생, 다수 관객의 자발적 대화, 전체 게임 호환성은 이번 검증에 포함하지 않았다.

## 게임 기록과 종료

- Slay the Spire 2 실행 전 AppData 전체를 `artifacts/spire-save-before`에 보존했다. 검증 후 세이브 3에서 저장 후 종료하고 기본 선택을 기존 세이브 1로 복원했다. 기존 진행 중 탐험은 실행/포기하지 않았다.
- 세이브 1의 29개 기존 파일 중 28개가 사전 사본과 해시가 같았다. 달라진 한 파일은 게임이 갱신한 `prefs.save.backup`이다. 실제 `prefs.save`, 진행 저장·기록은 동일했다. 백업을 임의로 원복하거나 새 세이브를 삭제하지 않았다.
- Baba Is You도 사전 백업 후 시도했다. 첫 직접 실행은 셰이더 오류로 정확히 소유한 실패 프로세스만 종료했고 Steam을 통한 재실행은 성공했다. 지도 진입 이후 입력 검증이 진전되지 않아 정상 종료하고 Slay the Spire 2로 전환했다. Baba 퍼즐 플레이 성공은 주장하지 않는다.
- BACKSEAT 방송 종료 버튼으로 화면·소리를 해제했고 두 앱 모두 정상 종료했다. 해당 실행 PID의 소멸을 확인했다.

## 이번 수정

기본 1440×980 창에서 안내를 접어도 긴 상단 통계와 고정 채팅 높이 때문에 입력창이 화면 아래로 밀렸다. 창의 남은 높이를 방송 화면과 채팅이 나눠 쓰도록 변경했다.

- 데스크톱 방송실의 상단 제목과 통계를 줄이고 미리보기·방송 조작·채팅 입력창을 같은 화면에 배치한다.
- 관찰 기록, 첫 방송 안내와 관객 목록은 왼쪽 영역에서 따로 스크롤한다. 안내를 삭제하지 않았으며 미리보기 아래에서 계속 확인할 수 있다.
- 짧은 창에서는 매니저 공지 여백을 줄이고 작은 폭에서는 마이크·소리 버튼을 아이콘으로 표시한다. 버튼 제목은 유지한다.
- 폭 950px 이하와 다른 탭은 기존 문서 스크롤을 유지한다. 오류/저장 경고로 공간이 부족하면 메인 영역이 스크롤되어 내용을 숨기지 않는다.
