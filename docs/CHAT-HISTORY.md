# 현재 방송의 이전 채팅

방송실의 관객 채팅은 처음에 최근 100개를 표시한다. 위쪽의 **이전 채팅 더보기**를 누르면 현재 방송에서 보관 중인 대화를 100개씩 추가로 불러온다. 이전 방송의 대화는 섞지 않는다. 방송을 중지한 뒤에도 같은 방송의 기록을 볼 수 있으며, 새 방송을 시작하면 목록을 초기화한다.

이전 채팅을 불러오거나 읽는 동안 새 채팅이 도착해도 읽던 줄의 위치를 유지한다. **새 채팅 보기 ↓**를 누르면 최신 위치로 이동하고 새 메시지를 따라간다. 요청 중에는 더보기 버튼이 비활성화되며 실패하면 이유를 표시하고 같은 버튼으로 재시도한다. 내 발언 표시 설정은 추가로 불러온 기록에도 적용된다.

삭제한 채팅은 다시 불러오지 않는다. 채팅 비우기 이후에는 기존 실시간 목록 밖에 남아 있는 대화도 채팅창으로 되살리지 않는다. 비우기의 기존 기억 삭제 범위는 확대하지 않는다. 속마음 보기는 기존과 같이 실시간 문맥이 남은 채팅에만 제공한다.

## 저장 및 조회 범위

- 기존 대화 기억의 보관 범위(전체 최대 4,000개, 고정 최대 100개)와 현재 실시간 목록(최대 500개)을 재사용한다. 대화 원문 저장소를 추가하거나 보관 기간을 늘리지 않는다. 이미 보관 범위를 벗어난 기록을 복구하는 기능은 아니다.
- 리허설은 대화 기억에 저장하지 않으므로 실시간 목록에 남은 현재 리허설 기록만 조회한다.
- 방송실 화면에 보관하는 메시지는 최대 4,500개다. 읽는 범위가 가득 차면 그 위치를 유지하고 새 채팅 보기로 최신 목록에 돌아갈 수 있다.
- 현재 방송 ID, 삭제·비우기 변경 번호, 발행 순번을 사용한다. 동시에 도착한 메시지나 시스템 시계 변경으로 페이지 순서가 바뀌지 않는다. 새 메시지 때문에 이동하는 offset은 사용하지 않는다.
- `GET /api/chat/history`는 기존 로컬 인증을 요구하며 페이지 크기를 100개로 제한한다. 다른 방송·오래된 변경 번호는 거절한다. `Cache-Control: no-store`를 사용하며 목격자·개인 기억·모델 내부 문맥은 반환하지 않는다. 조회는 모델이나 장치를 실행하지 않는다.
- 오래된 요청은 방송 변경 시 취소하고, 응답의 방송 ID와 변경 번호도 확인한다. 연결이 오래 끊겨 실시간 목록 사이에 간격이 생기면 최근 목록을 표시하고 더보기로 다시 조회하도록 안내한다.

## 회귀 검증

`node --test test/chat-history.test.js test/studio.test.js test/state-stream.test.js`는 500개를 넘은 조회, 수신 중 페이지 이동, 같은 시각 및 시계 역행, 현재 방송 격리, 삭제·비우기, 후원·음성 교정 표시, 인증과 페이지 제한을 확인한다.

빌드 후 Electron으로 `scripts/verify-chat-history-ui.cjs`를 실행하면 격리 서버와 실제 렌더러에서 더보기, 읽던 줄 위치, 새 채팅 따라가기, 실패 후 재시도, 500개 이전 기록, 삭제·비우기 및 방송 전환 중 늦은 응답을 확인한다. 합성 대화만 사용하며 실제 장치·모델·사용자 프로필을 이용하지 않는다. 실행 로그와 화면은 작업 공간의 `artifacts/chat-history-ui-*`에 저장한다.
