## 실제 Steam 방송에서 확인한 범위

이전 Windows 패키지를 작업 폴더에 복사하고 2,452개 파일의 해시 일치를 확인했다. `app.asar` SHA-256은 `480fc45e9f456070731004e161bbde1d33cdd697f2d7e2e99d4004a6c3ad4064`다. 아래 실게임 결과는 위 기준 커밋의 패키지이며, 이후의 눈팅 반응 수정본을 실게임에서 검증한 결과로 혼동하지 않는다.

Steam 라이브러리에서 Slay the Spire 2를 실행해 기존 QA 프로필 3의 보상 선택과 다음 전투를 약 14분간 진행했다. BACKSEAT에는 실제 게임 창과 Windows 출력 소리를 연결했다. 스트리머 발언 세 건은 키보드로 입력했으며 마이크는 꺼 두었다. AI 검증용 방송 프로필만 복사했고 관객을 추가하거나 실제 테스트 중 출석을 강제로 바꾸지 않았다.

일반 관객 한 명과 시스템 매니저가 있는 방송에서 실제 채팅 다섯 건이 표시됐다. 처음 인사할 때 일반 관객은 퇴장 중이라 답하지 않았고 이후 자율적으로 돌아왔다. 카드 세 장 중 함께 골라 달라는 요청에는 왼쪽 카드의 이번 턴 힘 3 효과를 근거로 답했다. 선택 후 첫 사용 때는 “같이 고른 카드 첫 출근”이라는 반응을 보였고, 승리 후 감상을 묻자 카드의 힘 효과와 후속 타격을 연결했다. 이 소규모 기록에 같은 채팅의 연속 중복은 없었다. 모든 장면의 자연스러움이나 장기 중복 문제 해결을 뜻하지 않는다.

## 발견한 반응 누락과 수정

호출 50–56에서 관객은 실제로 시청 중이었지만 `eligibleViewers=0`이었다. 기존 `Audience.context`와 모델 지침은 눈팅 관객을 75–135초 간격의 잡담 기회 또는 호명 때만 발언 후보로 허용했다. 그 결과 전투·승리 화면을 보는 눈팅 관객에게 새 사건을 판단하고 반응할 기회 자체가 없었다. 이후 잡담 호출 58에서는 승리 대신 카드 설명용 허수아비라는 일반 취향을 이야기했다. 모든 침묵이 이 원인이라는 뜻은 아니며, 호출 3–23은 일반 관객이 실제로 없었던 별도 구간이다.

- 새 화면·시간 흐름 속 움직임·소리·목격한 관객 간 대화 또는 새 스트리머 발언이 들어오면, 현 방문에서 함께 보는 눈팅 관객 최대 한 명을 기존 발언 후보에 포함한다. 이전 장면의 excitement 상승이나 잡담 타이머를 기다리지 않는다.
- 모델에도 해당 관객이 새 사건이나 질문에 관심이 생기면 짧게 반응할 수 있다고 전달한다. 후보 제공은 채팅 의무가 아니며 관심 없는 장면에는 계속 침묵할 수 있다.
- 접속 상태, 친밀도, 방문 횟수, 호명 횟수는 후보 선정 때문에 바뀌지 않는다. 일반 관객으로 시스템 매니저를 대체하지 않는다.
- 같은 입력의 재호출 제한, 침묵 요청, 발언을 듣지 못한 늦은 입장자 제외, 퇴장·방문 변경·만료 검사, 기존 채팅 속도와 훈수 제한을 유지한다. 별도 사용자 조작이나 관객 참여 버튼을 추가하지 않았다.

## 수정본 검증

`npm run check`: 테스트 602개, 실패·취소·건너뜀 0, TypeScript/Vite 빌드 통과. 추가 회귀는 낮은 excitement 상태의 새 승리 화면, 호명 없는 Just Chatting 질문, 화면 없는 소리, 관객 간 질문, 모델 응답 중 퇴장을 다룬다. 기존 회귀에서도 한 명 제한·비활성/이전 방문/시스템 제외, 침묵 요청·호명 우선, 최신 영상 전달을 확인한다.

실제 `gpt-6-astra` low와 Studio를 이용한 합성 키보드 대화 세 건도 검사했다. QA 난수와 잠수 비율 0.9로 눈팅을 유지하고 대기열 시계만 압축한 실험이다.

1. 닉네임을 부르지 않은 퍼즐/탐험 질문에 퍼즐 취향과 시간제한 선호를 답했다. 모델 20,204ms.
2. 이어서 음악을 켜는지 묻자 가사 없는 음악을 작게 틀되 막히면 끈다는 별도 취향을 답했다. 모델 11,902ms.
3. 조용히 봐 달라는 요청에는 일반 관객을 후보에서 제외했고 채팅이 없었다. 모델 9,080ms.

관객은 세 호출 내내 lurking을 유지했다. 이 검사는 후보 누락 개선과 실제 모델 응답의 연결을 확인하며, 물리 마이크·실게임 영상·장시간 발언 빈도를 검증하지 않는다. 첫 검사 준비에서 잠수 비율 1을 넣어 설정 스키마가 실행을 거부했다. 모델 호출 전에 발생한 시험 설정 오류이며, 유효한 0.9로 고쳐 실행했다. 최초 실패 기록도 보존한다.
