# 핫클립 · 댓글 검증 기록

후속 영상 버퍼·재시도·실제 파일 전송 검증은 [핫클립 영상 복구](CLIP-BUFFER-RECOVERY.md)를 참고하세요. 아래 수치는 당시 댓글/서버 검증 범위입니다.

검증일: 2026-09-13. 대상은 `server/clips.js`의 `Clips`/`ClipFeatures`. 정적 단위 테스트만 수행했으며 실제 모델 호출, 게임 실행, `data/` 변경은 하지 않았다. 이 문서는 방송 전체 경험이나 모든 게임의 정확도를 검증했다는 뜻이 아니다.

## 실행 방법과 결과

```
node --test test/clips.test.js
# tests 31 · pass 31 · fail 0
```

전체 서버 테스트(clips, studio, training, economy, discovery, codex)를 함께 실행해 회귀가 없음을 확인했다: `tests 62 · pass 62 · fail 0`. Windows 로컬 Node v22.19.0. 원본 출력은 `/tmp/clips-test-run.log`, `/tmp/all-test-run.log`에 보존했다(임시 경로이므로 재실행 시 위 명령으로 재생성한다).

테스트는 실제 provider를 부르지 않는다. `ClipFeatures` 테스트는 모델 응답·epoch·관객 상태·연습(training) 여부를 제어하는 최소 studio 대역을 쓰고, 한 개의 통합 테스트만 실제 `Studio`를 가짜 provider와 함께 구동한다. 미디어 파일 테스트는 OS 임시 폴더(`os.tmpdir()`)에서만 쓰고 정리한다.

## 좁게 수정한 결함

- **방송 날짜가 저장 시각을 따르던 문제** — `Clips.create`가 `day`를 `now()`로 계산해, 자정을 넘겨 저장하거나 방송 종료 후 저장하면 잘못된 날짜가 찍혔다. 이제 세션 `startedAt`(caller가 제공)을 기준으로 하고, 없으면 생성 시각으로 폴백한다. `ClipFeatures.save`가 `s.startedAt`을 넘긴다. 자동 생성 경로(`studio.js`, 이 작업 범위 밖)는 `startedAt`을 넘기면 그대로 반영되고 아니면 폴백한다.
- **부분적으로 남는 모델 댓글 묶음** — 기존 `comments()`는 댓글을 하나씩 `comment()`(개별 save)로 저장해, 중간 실패 시 일부만 남았다. 원자적 트랜잭션 헬퍼 `Clips.commentBatch(id, items)`를 추가했다. 단일 `change()`/save로 커밋하며, 커밋 시점에 클립 부재·부모 삭제·깊이(4단계)·상한(150개)을 다시 검증한다. 하나라도 거부되거나 저장이 실패하면 전부 롤백된다. `comment()`도 이 헬퍼를 거친다.
- **댓글 관객 메타데이터가 참여를 가장하던 문제** — 요청에 `offStream:true`와 관객별 `attended` 플래그(해당 클립 참여자 여부)를 실어, 라이브에 없던 관객도 기록을 감상·댓글할 수 있으나 그 자리에 있었던 것처럼 말하지 않도록 한다. 지시문은 기록이 캡션·채팅 기반이며 영상 자체를 재생·분석하지 않음을 명시한다.
- **대상 검증** — 댓글 대상은 중복 없이, 알려진 활성 관객 1~4명이어야 한다. 비활성·미등록 대상을 조용히 버리지 않고 거부한다.
- **연습 중 모델 호출 차단** — `studio.training?.active`이면 `comments()`가 모델을 부르기 전에 거부한다. `training`이 아직 studio에 연동되지 않은 현재도 optional chaining으로 안전하며, 연동 후 자동으로 활성화된다.
- **취소·동시 삭제 정리** — 모델 대기 중 세션이 바뀌면(epoch 변경) 커밋 없이 취소하고 토큰을 집계하지 않는다. 대기 중 클립이 삭제되거나 부모 댓글이 삭제되면 묶음 전체가 깔끔히 거부된다. 관객 기억·관계·저장은 댓글 커밋이 성공한 뒤에만 갱신한다.

## 테스트가 다루는 범위

날짜(`startedAt` 기반, 폴백, 비정상 값 무시), 원자적 커밋과 저장 실패 롤백, 상한/깊이/삭제된 부모 거부, 빈·과길이 텍스트 거부, 미디어 경로 검증(잘못된 id·확장자·경로 이탈·디렉터리 없음), 썸네일·영상 파일 롤백, 영상 중복 연결·버퍼 검증, 서명 중복 병합과 100개 상한, `list()` 투영, 저장 참여자 필터, 대상 검증, 오프스트림/attended 메타데이터와 영상 분석 미주장, 연습 중 차단, 거부 댓글 필터링, 표시 불가 시 관객 미저장, 지속화 실패 시 무변경, 취소, 클립·부모 동시 삭제, 대댓글 친밀도 갱신(스트리머 제외), 모드/바쁨 거부, 실제 studio 통합.

## 알려진 한계 · 미검증

- 실제 모델 응답 품질(댓글의 자연스러움·기록 준수·비참여 관객의 잘못된 회상 빈도)은 검증하지 않았다. 가짜 provider로 흐름·거부·지속화만 검증한다.
- 미디어 500MB 상한(`MAX_STORAGE`)은 상수라 초과 경로를 실사용 규모로 재현하지 않았다. 대신 저장 실패 롤백 경로를 검증했다.
- 날짜 검증은 로컬 캘린더 날짜 규약을 그대로 오라클로 사용한다. 표준시간대별 자정 경계의 실기기 동작은 별도 확인이 필요하다.
- 자동 하이라이트 생성 경로(`server/studio.js`) 자체는 이 작업 범위 밖이라 통합 테스트에서 직접 구동하지 않았다.
- API 호환을 유지했다(`create`에 선택적 `startedAt` 추가, `commentBatch` 신규, 기존 메서드 시그니처 보존). HTTP 계층(`server/index.js`)은 수정하지 않았다.
